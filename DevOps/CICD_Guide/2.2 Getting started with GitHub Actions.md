## Setting up lint, test and build steps
Sau khi hoàn thành các bài tập đầu tiên, bạn hẳn đã thiết lập được một quy trình làm việc (workflow) đơn giản nhưng chưa thực sự hữu ích. Hãy cùng biến quy trình này thành một công cụ có ích.

Chúng ta sẽ triển khai một GitHub Action để thực hiện kiểm tra cú pháp và định dạng mã nguồn (linting). Nếu các bước kiểm tra không đạt yêu cầu, GitHub Actions sẽ hiển thị trạng thái màu đỏ.

Ban đầu, quy trình làm việc mà chúng ta sẽ lưu vào tệp `pipeline.yml` sẽ có dạng như sau:

```yml
name: Deployment pipeline

on:
  push:
    branches:
      - main

jobs:
```

Trước khi có thể chạy lệnh để kiểm tra lỗi cú pháp (lint) cho mã nguồn, chúng ta cần thực hiện một số thao tác để thiết lập môi trường cho tác vụ (job) này.

**Thiết lập môi trường**
Việc thiết lập môi trường là một bước quan trọng khi cấu hình pipeline. Chúng ta sẽ sử dụng môi trường ảo `ubuntu-latest` vì nó tương đồng với phiên bản Ubuntu (cụ thể là 24.04) mà chúng ta sẽ sử dụng trong môi trường thực tế (production).

Việc tái tạo môi trường CI sao cho giống với môi trường production nhất có thể là điều rất quan trọng. Điều này giúp tránh tình trạng cùng một đoạn mã lại hoạt động khác nhau giữa CI và production – một vấn đề sẽ làm mất đi ý nghĩa của việc sử dụng CI.

Tiếp theo, chúng ta liệt kê các bước mà CI cần thực hiện trong tác vụ "build". Như đã thấy ở bài tập trước, theo mặc định thì môi trường ảo không chứa sẵn mã nguồn, vì vậy chúng ta cần thực hiện thao tác checkout mã nguồn từ kho lưu trữ (repository).

Đây là một bước đơn giản:

```yml
name: Deployment pipeline

on: 
  push:
    branches:
      - main

jobs:
  simple_deployment_pipeline:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
```

Từ khóa [`uses`](https://docs.github.com/en/free-pro-team@latest/actions/reference/workflow-syntax-for-github-actions#jobsjob_idstepsuses) chỉ định cho quy trình làm việc (workflow) thực thi một hành động (action) cụ thể. Một hành động là đoạn mã có thể tái sử dụng, tương tự như một hàm (function). Các hành động có thể được định nghĩa trong một tệp riêng biệt ngay tại kho lưu trữ (repository) của bạn, hoặc bạn có thể sử dụng các hành động có sẵn trong các kho lưu trữ công khai.

Ở đây, chúng ta sử dụng hành động công khai [`actions/checkout`](https://github.com/actions/checkout) và chỉ định một phiên bản cụ thể (`@v6`) để tránh các lỗi phát sinh (breaking changes) nếu hành động này được cập nhật. Hành động `checkout` thực hiện đúng như tên gọi của nó: lấy mã nguồn dự án từ Git về.

Thứ hai, do ứng dụng được viết bằng JavaScript, cần thiết lập Node.js để có thể sử dụng các lệnh được định nghĩa trong tệp `package.json`. Để thiết lập Node.js, ta có thể sử dụng hành động [`actions/setup-node`](https://github.com/actions/setup-node). Phiên bản Node 24 được lựa chọn vì đây là phiên bản mà ứng dụng đang sử dụng trong môi trường thực tế (production).

```yml
name: Deployment pipeline

on: 
  push:
    branches:
      - main

jobs:
  simple_deployment_pipeline:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6     # Checkout the repository
      - uses: actions/setup-node@v6   # thực hiện thiết lập môi trường Node.js
        with:
          node-version: '24'            # Thiết lập phiên bản Node.js
```

Như chúng ta có thể thấy, từ khóa [`with`](https://docs.github.com/en/free-pro-team@latest/actions/reference/workflow-syntax-for-github-actions#jobsjob_idstepswith) được sử dụng để cung cấp "tham số" cho hành động (action). Trong trường hợp này, tham số xác định phiên bản Node.js mà chúng ta muốn sử dụng.

Cuối cùng, các phần phụ thuộc (dependencies) của ứng dụng cần được cài đặt. Tương tự như khi thực hiện trên máy tính cá nhân, chúng ta chạy lệnh `npm install`. Các bước trong job lúc này sẽ trông như sau:

```yml
name: Deployment pipeline

on: 
  push:
    branches:
      - main

jobs:
  simple_deployment_pipeline:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6     # Checkout the repository
      - uses: actions/setup-node@v6   # thực hiện thiết lập môi trường Node.js
        with:
          node-version: '24'            # Thiết lập phiên bản Node.js
      - name: Install dependencies      # Cài đặt các dependencies
        run: npm install                # Cài đặt các dependencies từ package.json
```

Giờ đây, môi trường đã hoàn toàn sẵn sàng để thực hiện các tác vụ quan trọng.

**Lint**

Sau khi đã thiết lập xong môi trường, chúng ta có thể chạy tất cả các script từ file `package.json` giống như khi thực hiện trên máy cá nhân. Để kiểm tra lỗi cú pháp (lint) cho mã nguồn, bạn chỉ cần thêm một bước để chạy lệnh `npm run eslint`.

```yml
name: Deployment pipeline

on: 
  push:
    branches:
      - main

jobs:
  simple_deployment_pipeline:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6     # Checkout the repository
      - uses: actions/setup-node@v6   # thực hiện thiết lập môi trường Node.js
        with:
          node-version: '24'            # Thiết lập phiên bản Node.js
      - name: Install dependencies      
        run: npm install                # Cài đặt các dependencies từ package.json
      - name: Check style
        run: npm run lint                # Kiểm tra style code bằng lệnh lint
```

Lưu ý rằng tên của một bước là tùy chọn nếu bạn định nghĩa bước đó như sau:

```yml
run: npm run lint 
```

Lệnh được thực thi sẽ được sử dụng làm tên mặc định.
