**Go** là một ngôn ngữ tổng quát được thiết với mục đích lập trình hệ thống. Ban đầu nó được phát triển tại Google vào năm 2007 bởi Robert Griesemer, Rob Pike và Ken Thompson.
Ngôn ngữ này được định hình mạnh và tĩnh, cung cấp hỗ trợ sẵn để thu gom dữ liệu ra và hỗ trợ lập trình đồng thời. Các chương trình được xây ==dựng bằng các sử dụng các packages==, để quản lý hiệu quả các **dependencies**. Triển khai lập trình **Go** ==sử dụng biên dịch và liên kết mô hình để tạo thực thi các tệp nhị phân==.

### **Tại sao dùng golang?**

Do Golang có hiệu suất cao tương đương với C/C++, cú pháp đơn giản dễ học, và khả năng xử lý lượng đồng thời cao (concurrency) vượt trội với Goroutines. Nó lý tưởng cho backend, microservice và hệ thống đám mây, giúp tối ưu tài nguyên phần cứng, biên dịch nhanh và dễ dàng bảo trì

Dưới đây là các lý do chi tiết tại sao nên dùng Golang:

- **Hiệu suất vượt trội (Performance):** Go là ngôn ngữ biên dịch (compiled) sang mã máy, giúp tốc độ xử lý nhanh chóng, gần tương đương với C/C++.
- **Xử lý đồng thời (Concurrency) dễ dàng:** Goroutines và Channels tích hợp giúp Go quản lý hàng triệu tiến trình nhẹ nhàng, tối ưu cho các hệ thống phân tán và dịch vụ mạng.
- **Quản lý bộ nhớ hiệu quả:** Go tích hợp cơ chế thu gom rác (garbage collection) tự động, giúp quản lý bộ nhớ tốt mà không đòi hỏi nhiều sự can thiệp.
- **Triển khai (Deployment) dễ dàng:** Go biên dịch ra một file nhị phân duy nhất (single binary), không phụ thuộc vào các thư viện bên ngoài, giúp việc triển khai lên server cực kỳ gọn nhẹ.
- **Được hỗ trợ bởi Google:** Đảm bảo độ tin cậy, sự phát triển lâu dài và phù hợp cho các cơ sở hạ tầng quy mô lớn

#### **2. Go là một language, framework hay library mới?**

**Go** không phải là một library và không phải là một framework, đó là một ngôn ngữ mới. ==Go hầu hết thuộc họ C (cú pháp cơ bản)==, với đầu vào đáng kể họ Pascal/ Modula / Oberon (khai báo ,gói).

**Go** có một thư viện rộng lớn, được gọi là **runtime**, là một phần của mọi chương trình **Go**. Mặc dù đó là ngôn ngữ trung tâm, **runtime** của Go tương tự như libc, thư viện C. Tuy nhiên, điều quan trọng cần hiểu là **runtime** của Go không bao gồm máy ảo, chẳng hạng như không bao gồm Java runtime.

Các chương trình Go được biên dịch trước sang mã máy gốc.

### **3. Ưu/ nhược điểm của Golang là gì?**

Go lang được đánh giá cao nhờ hiệu suất mạnh mẽ, cú pháp đone giản và khả năng xử lý đồng thời vượt trội. Tuy nhiên, ngôn ngữ này vẫn tồn tại một số điểm hạn chế so với các ngôn ngữ lập trình khác

#### **Ưu điểm**

Nhờ hiệu suất xử lý cao, gần tương đương với các ngôn ngữ biên dịch như C/C++. Khả năng hỗ trợ lập trình (Concurrency) với Goroutines giúp Golang xử lý hàng triệu tiến trình một cách nhanh chóng và nhẹ nhàng, rất phù hợp cho hệ thống phân tán microservices và dịch vụ web hiệu suất cao.
Bên cạnh đó thì cú pháp của Golang được thiết kế đơn giản, dễ đọc, dễ học và thân thiện với người mới

#### **Nhược điểm**

Golang không hỗ trợ kế thừa trong lập trình hướng đối tượng, khiến việc thiết kế hệ thống theo OOP có phân hạn chế. Mặc dù Go có hỗ trợ Interface nhưng vẫn thiếu đi những tính năng nâng cao như abstract class hay methob overloading.

Go chưa thật sự mạnh trong các lĩnh vực như trí tuệ nhân tạo (AI), học máy (machine learning), và xử lý dữ liệu lớn (big data), nơi mà Python đang chiếm ưu thế tuyệt đối. Ngoài ra, việc phát triển ứng dụng frontend, game hoặc phần mềm giao diện người dùng bằng Golang là không phù hợp do thiếu thư viện và công cụ hỗ trợ.

Cuối cùng, hệ thống quản lý thư viện bên ngoài (module) của Go vẫn còn đơn giản so với các hệ sinh thái lớn như Node.js (npm) hay Python (pip).

### 7.  **Giải thích method & interface**

#### 7.1. Method (Phương thức)

Trong Go, **Method** thực chất là một hàm (function), nhưng có thêm một tham số đặc biệt gọi là **receiver** (bộ nhận). Receiver này nằm giữa từ khóa `func` và tên hàm.

Thay vì gói mọi thứ vào một class, Go cho phép bạn "gắn" hàm vào một kiểu dữ liệu bất kỳ (thường là `struct`).

```go
type Rectangle struct {
    width, height float64
}

// Đây là một Method. (r Rectangle) là receiver.
func (r Rectangle) Area() float64 {
    return r.width * r.height
}
```

### Pointer vs. Value Receiver:

Đây là điểm quan trọng  cần nhớ:
- **Value Receiver (`r Rectangle`):** Go sẽ tạo một bản sao của đối tượng. Mọi thay đổi bên trong method sẽ không ảnh hưởng đến đối tượng gốc.
- **Pointer Receiver (`r *Rectangle`):** Go dùng địa chỉ ô nhớ. Method có thể thay đổi dữ liệu của đối tượng gốc và hiệu năng tốt hơn vì không phải copy dữ liệu.

#### 7.2. Interface (Giao diện)

Nếu Method là **hành động**, thì Interface là **bản hợp đồng**. Nó định nghĩa một tập hợp các chữ ký hàm (method signatures). Một kiểu dữ liệu được coi là "thực thi" (implement) interface đó nếu nó sở hữu tất cả các method mà interface yêu cầu.

**Điểm đặc biệt nhất của Go:** Bạn không cần từ khóa `implements`. Chỉ cần bạn có đủ method, Go sẽ tự hiểu bạn đã "ký hợp đồng". Đây gọi là **Implicit Implementation** (thực thi ngầm định).

```go
// Định nghĩa "hợp đồng" Shape
type Shape interface {
    Area() float64
}

// Đối tượng Square
type Square struct {
    side float64
}

// Square thực thi Area() -> Tự động thỏa mãn interface Shape
func (s Square) Area() float64 {
    return s.side * s.side
}

func PrintArea(sh Shape) {
    fmt.Println("Diện tích là:", sh.Area())
}
```

##### 7.3. Sự khác biệt chính

| **Đặc điểm** | **Method**                                   | **Interface**                                          |
| ------------ | -------------------------------------------- | ------------------------------------------------------ |
| **Bản chất** | Là hàm gắn liền với một kiểu dữ liệu cụ thể. | Là một kiểu dữ liệu trừu tượng định nghĩa các hành vi. |
| **Mục đích** | Thực thi logic xử lý cho đối tượng.          | Tạo ra sự đa hình (polymorphism), giúp code linh hoạt. |
| **Khai báo** | Phải có receiver.                            | Chỉ chứa tên hàm, tham số và kiểu trả về.              |
#### Tại sao Go lại làm như vậy?

Cách thiết kế này giúp Go đạt được sự linh hoạt tuyệt vời:
1. **Tính đóng gói (Encapsulation):** Bạn có thể thêm method cho bất kỳ type nào trong package của mình (không chỉ struct).
2. **Tính đa hình (Polymorphism):** Bạn có thể viết một hàm nhận vào một `Interface`, và hàm đó sẽ hoạt động với bất kỳ object nào thỏa mãn interface đó, giúp code cực kỳ dễ mở rộng.
3. **Hạn chế phụ thuộc:** Bạn có thể định nghĩa interface ở nơi sử dụng, thay vì nơi tạo ra đối tượng.

#### 12. **Giải thích sự khác nhau giữa map và struct**

**Map** và **struct** đều dùng để tổ chức dữ liệu, nhưng mục đích khác nhau.
### Map
Map là cấu trúc dữ liệu dạng key-value:

```go
m := map[string]int{
    "apple": 10,
    "banana": 20,
}
```

Đặc điểm:
- Key phải là kiểu comparable.
- Giá trị có thể thêm/xóa động.
- Thứ tự các phần tử không đảm bảo.
- Phù hợp cho lookup theo key.
- Không an toàn khi nhiều goroutine đọc/ghi đồng thời.

### Struct

Struct là kiểu dữ liệu có các trường cố định:

```go
type User struct {
    ID    int
    Name  string
    Email string
}
```
  
Đặc điểm:
- Số lượng và tên trường cố định.
- Mỗi trường có kiểu rõ ràng.
- Có thể gắn method.
- Có thể implement interface.
- Phù hợp để mô hình hóa domain entity.
### So sánh nhanh

| Tiêu chí | Map | Struct |
|---|---|---|
| Cấu trúc | Động | Cố định |
| Key | Chạy runtime | Trường cố định lúc compile-time |
| Kiểu dữ liệu | Key/value có thể linh hoạt | Mỗi trường có kiểu riêng |
| Method | Không gắn method trực tiếp | Có thể gắn method |
| Hiệu năng lookup | Tốt cho key động | Truy cập trường nhanh |
| Thread-safe | Không an toàn mặc định | Phụ thuộc cách dùng |
| Dùng khi nào | Lookup động, grouping, caching | Domain object, dữ liệu có schema rõ |

### Ví dụ minh họa

Map:
```go
scores := map[string]int{
    "Alice": 9,
    "Bob":   8,
}
scores["Carol"] = 7
```

Struct:
```go
type Student struct {
    Name  string
    Score int
}

s := Student{Name: "Alice", Score: 9}
```

### Mở rộng

- Nếu dùng map trong môi trường concurrency, cần dùng `sync.Mutex`, `sync.RWMutex`, hoặc thiết kế tránh chia sẻ map giữa các goroutine.
- `sync.Map` chỉ phù hợp cho một số trường hợp đặc biệt, không phải lúc nào cũng nhanh hơn map thường.
- Struct thường được ưu tiên khi dữ liệu có cấu trúc rõ ràng, cần validation, method hoặc JSON schema ổn định.

#### 13. **Race condition là gì?**

**Race condition** là lỗi xảy ra khi nhiều goroutine/thread/process truy cập cùng một tài nguyên dùng chung và kết quả cuối cùng phụ thuộc vào thứ tự thực thi. Nếu các goroutine không được đồng bộ hóa đúng cách, dữ liệu hoặc trạng thái hệ thống có thể bị sai.

Trong Go, race condition thường xuất hiện khi:
- Nhiều goroutine cùng đọc/ghi một biến.
- Có ít nhất một goroutine ghi.
- Không có cơ chế đồng bộ như mutex, channel, atomic.

### Ví dụ minh họa

```go
package main

import (
    "fmt"
    "sync"
)

func main() {

    counter := 0
    var wg sync.WaitGroup

    for i := 0; i < 1000; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            counter++
        }()
    }

    wg.Wait()
    fmt.Println(counter) // có thể không phải 1000
}
```

Nhiều goroutine cùng tăng `counter`, nhưng `counter++` không phải thao tác atomic. Kết quả có thể nhỏ hơn 1000.

### Cách khắc phục

1. Dùng mutex:
```go
var mu sync.Mutex

mu.Lock()
counter++
mu.Unlock()
```

2. Dùng atomic cho biến đơn giản:
```go
import "sync/atomic"

var counter int64
atomic.AddInt64(&counter, 1)
```

3. Dùng channel để gom quyền xử lý về một goroutine sở hữu dữ liệu.
4. Tránh chia sẻ trạng thái nếu không cần thiết.
### Mở rộng

- Race condition là khái niệm rộng về logic concurrency.
- **Data race** là một dạng race condition ở mức truy cập bộ nhớ, có thể được Go race detector phát hiện.
- Không phải race condition nào cũng là data race. Ví dụ: thứ tự gọi API phụ thuộc vào timing có thể gây lỗi logic, nhưng race detector không chắc phát hiện.
- Với business logic tài chính, cần kết hợp lock, transaction, idempotency và thiết kế domain phù hợp.

### Nguồn trích dẫn

- Go Blog: Introducing the Go Race Detector.
- Go Memory Model.
- Go Specification: sync package.

## Câu 14: Làm thế nào phát hiện Data Race trong Go? Cách giải quyết như thế nào?

**Data race** xảy ra khi hai hoặc nhiều goroutine truy cập cùng một vùng nhớ đồng thời, trong đó có ít nhất một thao tác ghi, và không có cơ chế đồng bộ phù hợp.

### Cách phát hiện

Go có công cụ **race detector**.
Chạy chương trình:

```bash
go run -race main.go
```

Chạy test:

```bash
go test -race ./...
```

Build với race detector:
```bash
go build -race
```
Race detector sẽ cảnh báo khi phát hiện truy cập dữ liệu không đồng bộ.
### Ví dụ data race

```go
package main

import "fmt"

func main() {
    x := 0
    go func() {
        x = 1
    }()
    fmt.Println(x)
}
```
Goroutine ghi `x`, main goroutine đọc `x`, không có đồng bộ hóa. Đây là data race.
### Cách khắc phục

1. **Mutex**

```go
var mu sync.Mutex
var x int

mu.Lock()
x = 1
mu.Unlock()
```

  

2. **RWMutex** nếu có nhiều đọc, ít ghi:
```go
var mu sync.RWMutex

mu.RLock()
v := x
mu.RUnlock()
```

3. **Atomic** cho biến đơn giản:
```go
var counter int64
atomic.AddInt64(&counter, 1)
```

4. **Channel** để chuyển quyền sở hữu dữ liệu:
```go
ch := make(chan int)
go func() {
    ch <- 1
}()

x := <-ch
```

5. **Không chia sẻ dữ liệu** nếu có thể thiết kế mỗi goroutine sở hữu dữ liệu riêng.

### Lưu ý quan trọng

- Race detector có overhead, thường không bật trong production.
- Race detector chỉ phát hiện khi đường dẫn code có data race thực sự được chạy trong lúc test/runtime.
- Nên chạy `go test -race` trong CI để phát hiện sớm.
### Mở rộng

- Data race là lỗi ở mức memory access.
- Race condition là lỗi logic rộng hơn.
- Code không có data race vẫn có thể có race condition về thứ tự nghiệp vụ.
- Trong hệ thống phân tán, cần thêm transaction, distributed lock, idempotency, event-driven design tùy bài toán.
### Nguồn trích dẫn

- Go Blog: Introducing the Go Race Detector.
- Go Race Detector Documentation.
- Go Memory Model.

#### 15. **Deadlock là gì?**

**Deadlock** là trạng thái trong đó hai hoặc nhiều goroutine bị chặn vĩnh viễn vì chờ lẫn nhau hoặc chờ tài nguyên không bao giờ được giải phóng. Trong Go, deadlock thường gặp khi dùng channel hoặc mutex.

Nếu toàn bộ goroutine đều bị block, Go runtime có thể phát hiện và panic:

```text
fatal error: all goroutines are asleep - deadlock!
```

### Ví dụ deadlock với unbuffered channel

```go
package main

func main() {
    ch := make(chan int)
    ch <- 1 // block vì không có receiver
}
```

Goroutine chính gửi vào channel nhưng không có goroutine nào nhận, dẫn đến deadlock.

### Cách sửa

Tạo goroutine nhận:

```go
package main

import "fmt"

func main() {
    ch := make(chan int)

    go func() {
        ch <- 1
    }()

    fmt.Println(<-ch)
}
```

Hoặc dùng buffered channel nếu phù hợp:

```go
ch := make(chan int, 1)
ch <- 1
fmt.Println(<-ch)
```

### Deadlock với mutex

```go
var mu sync.Mutex

mu.Lock()
mu.Lock() // deadlock, cố lock lần hai trên cùng goroutine
```

Mutex trong Go không reentrant, không thể lock hai lần liên tiếp trong cùng goroutine mà không unlock.

### Deadlock với WaitGroup

```go
var wg sync.WaitGroup

wg.Add(1)
// quên gọi wg.Done()
wg.Wait() // deadlock
```

### Cách phòng tránh

1. Luôn đảm bảo có sender và receiver phù hợp cho channel.
2. Cẩn thận khi đóng channel; chỉ đóng từ phía sender khi không còn gửi thêm.
3. Dùng `select` với timeout hoặc context.

```go
select {
case v := <-ch:
    fmt.Println(v)
case <-time.After(time.Second):
    fmt.Println("timeout")
}
```

4. Dùng `context.Context` để cancel goroutine.

```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()

select {
case <-ctx.Done():
    fmt.Println("cancelled")
case v := <-ch:
    fmt.Println(v)
}
```

5. Kiểm tra logic `wg.Add`, `wg.Done`, `defer wg.Done()`.
6. Tránh giữ mutex quá lâu hoặc gọi hàm khác trong khi đang giữ lock nếu có nguy cơ lock vòng.

### Mở rộng

- Deadlock khác race condition:
  - Race condition: kết quả sai do thứ tự thực thi.
  - Deadlock: goroutine bị kẹt, không thể tiếp tục.
- Ngoài deadlock còn có:
  - Goroutine leak: goroutine bị block mãi nhưng chương trình không panic.
  - Livelock: goroutine vẫn chạy nhưng không tiến triển.
- Trong production, nên dùng timeout, context, graceful shutdown và monitoring để phát hiện goroutine bị treo.
