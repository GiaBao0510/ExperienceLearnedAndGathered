## RPC là gì?

**RPC (Remote Procedure Call)** là một giao thức giao tiếp mạng cho phép một chương trình gọi và thực thi một hàm (thủ tục) nằm trên một máy tính khác, giống như đang gọi hàm nội bộ trong cùng một chương trình. Nói đơn giản hơn: thay vì tự xử lý, chương trình của bạn "nhờ" một máy tính từ xa thực hiện một tác vụ và trả về kết quả.

RPC sử dụng mô hình [client-server](https://en.wikipedia.org/wiki/Client%E2%80%93server_model):

- **Client**: chương trình gửi yêu cầu
- **Server**: chương trình tiếp nhận và xử lý yêu cầu, rồi gửi lại kết quả

## Ví dụ cơ bản về RPC trong Go

Phần này minh họa cách triển khai một RPC service đơn giản bằng ngôn ngữ [Go](https://go.dev/), gồm một server cung cấp hàm `Hello` và một client gọi hàm đó từ xa.

### Server

Tạo file `server/main.go`:

```go
package main

import (
	"log"
	"net"
	"net/rpc"
)

// HelloService là struct đại diện cho RPC service
type HelloService struct{}

// Hello là hàm service được công khai ra ngoài.
// Quy tắc bắt buộc khi định nghĩa hàm RPC service trong Go:
//   1. Tên hàm phải bắt đầu bằng chữ hoa (public)
//   2. Có đúng 2 tham số: tham số thứ nhất là request (giá trị đầu vào),
//      tham số thứ hai là response (con trỏ để ghi kết quả trả về)
//   3. Hàm phải trả về kiểu error
func (p *HelloService) Hello(req string, res *string) error {
	*res = "Hello " + req
	return nil
}

func main() {
	// Đăng ký service với tên "HelloService"
	rpc.RegisterName("HelloService", new(HelloService))

	// Tạo server lắng nghe kết nối TCP trên cổng 1234
	listener, err := net.Listen("tcp", ":1234")
	if err != nil {
		panic(err)
	}

	log.Print("server is listening on port 1234")

	for {
		// Chấp nhận kết nối từ client
		conn, err := listener.Accept()
		if err != nil {
			log.Fatal("Accept error: ", err)
		}

		// Phục vụ client trên một Goroutine riêng biệt
		// để vòng lặp chính tiếp tục chấp nhận kết nối mới.
		// (Goroutine là luồng nhẹ trong Go, cho phép xử lý đồng thời)
		go rpc.ServeConn(conn)
	}
}
```

### Client

Tạo file `client/main.go`:

```go
package main

import (
	"fmt"
	"log"
	"net/rpc"
)

func main() {
	// Kết nối đến server tại địa chỉ localhost:1234
	client, err := rpc.Dial("tcp", "localhost:1234")
	if err != nil {
		log.Fatal("Lỗi khi kết nối đến server: ", err)
	}

	// Biến để nhận kết quả trả về từ server
	var reply string

	// Thực hiện lời gọi RPC đến service "HelloService", phương thức "Hello",
	// với tham số đầu vào là chuỗi "Gia Bao"
	err = client.Call("HelloService.Hello", "Gia Bao", &reply)
	if err != nil {
		log.Fatal(err)
	}

	fmt.Println(reply)
}
```

> **Lưu y:** Tên service truyền vào `client.Call` phải khớp chính xác với tên đã đăng ký trên server bằng `rpc.RegisterName`. Ở đây cả hai đều dùng `"HelloService"`.

### Kết quả chạy

Chạy server:

```bash
GO_web\RPC_gRPC\practice> go run server/main.go
2026/03/23 21:50:33 server is listening on port 1234
```

Chạy client (trong một terminal khác):

```bash
GO_web\RPC_gRPC\practice> go run client/main.go
Hello Gia Bao
```

Qua ví dụ trên, có thể thấy việc sử dụng RPC trong Go khá trực quan: server đăng ký hàm cần cung cấp, client kết nối và gọi hàm đó như gọi hàm bình thường.

## Hàm giám sát bằng RPC (Watch)

Trong thực tế, có những tình huống mà client cần được thông báo ngay khi có thay đổi xảy ra trên server — thay vì liên tục hỏi lại server (polling). Phần này trình bày cách xây dựng phương thức `Watch` để đáp ứng nhu cầu đó.

**Ý tưởng:** Xây dựng một kho lưu trữ dữ liệu dạng key-value đơn giản. Mỗi khi giá trị (value) của một khóa (key) bị thay đổi, server sẽ chủ động thông báo cho client biết khóa nào vừa thay đổi.

![Mô hình sử dụng hàm Watch](https://zalopay-oss.github.io/go-advanced/images/watch.png)

### Định nghĩa KVStoreService

```go
type KVStoreService struct {
	// m lưu trữ các cặp key-value
	m map[string]string

	// filter chứa các hàm callback, mỗi hàm sẽ được gọi
	// khi có key bị thay đổi giá trị
	filter map[string]func(key string)

	// mu là Mutex, dùng để tránh xung đột khi nhiều Goroutine
	// cùng đọc hoặc ghi vào m và filter đồng thời
	mu sync.Mutex
}

func NewKVStoreService() *KVStoreService {
	return &KVStoreService{
		m:      make(map[string]string),
		filter: make(map[string]func(key string)),
	}
}
```

### Phương thức Get và Set

```go
func (p *KVStoreService) Get(key string, value *string) error {
	p.mu.Lock()
	defer p.mu.Unlock()

	if v, ok := p.m[key]; ok {
		*value = v
		return nil
	}

	return fmt.Errorf("not found")
}

func (p *KVStoreService) Set(kv [2]string, reply *struct{}) error {
	p.mu.Lock()
	defer p.mu.Unlock()

	key, value := kv[0], kv[1]

	// Nếu giá trị thực sự thay đổi, gọi tất cả các hàm filter
	// để thông báo cho các Watch đang chờ
	if oldValue := p.m[key]; oldValue != value {
		for _, fn := range p.filter {
			fn(key)
		}
	}

	p.m[key] = value
	return nil
}
```

### Phương thức Watch

```go
// Watch chờ cho đến khi có một key thay đổi hoặc hết thời gian chờ,
// rồi ghi tên key đó vào keyChanged và trả về.
func (p *KVStoreService) Watch(timeoutSecond int, keyChanged *string) error {
	// Tạo một ID duy nhất để phân biệt lần gọi Watch này
	id := fmt.Sprintf("watch-%s-%03d", time.Now(), rand.Int())

	// ch là buffered channel (kênh có bộ đệm) dùng để nhận key thay đổi.
	// Buffered channel giúp hàm filter không bị chặn khi ghi vào channel.
	ch := make(chan string, 10)

	// Đăng ký hàm filter: mỗi khi có key thay đổi, gửi tên key vào channel ch
	p.mu.Lock()
	p.filter[id] = func(key string) { ch <- key }
	p.mu.Unlock()

	select {
	// Trường hợp 1: hết thời gian chờ
	case <-time.After(time.Duration(timeoutSecond) * time.Second):
		return fmt.Errorf("timeout")
	// Trường hợp 2: nhận được thông báo có key thay đổi
	case key := <-ch:
		*keyChanged = key
		return nil
	}
}
```

### Sử dụng Watch từ phía client

```go
func doClientWork(client *rpc.Client) {
	// Chạy một Goroutine riêng để lắng nghe thông báo thay đổi
	// mà không chặn luồng chính
	go func() {
		var keyChanged string
		// Lời gọi Watch sẽ block cho đến khi nhận được thông báo
		// hoặc hết 30 giây
		err := client.Call("KVStoreService.Watch", 30, &keyChanged)
		if err != nil {
			log.Fatal(err)
		}
		fmt.Println("watch:", keyChanged)
	}()

	// Gán giá trị lần đầu cho key "abc"
	err := client.Call(
		"KVStoreService.Set", [2]string{"abc", "abc-value"},
		new(struct{}),
	)

	// Thay đổi giá trị của key "abc" — lúc này Watch sẽ được kích hoạt
	err = client.Call(
		"KVStoreService.Set", [2]string{"abc", "another-value"},
		new(struct{}),
	)
	if err != nil {
		log.Fatal(err)
	}

	// Chờ để đảm bảo Goroutine giám sát kịp in kết quả
	time.Sleep(time.Second * 3)
}
```

### Kết quả

```bash
watch: abc
```

Server trả về tên key vừa thay đổi (`abc`) cho client thông qua phương thức `Watch`. Cơ chế này cho phép client phản ứng ngay khi có thay đổi mà không cần liên tục hỏi lại server.

## Reverse RPC

### Vấn đề đặt ra

Trong mô hình RPC thông thường, client luôn là người khởi tạo kết nối đến server. Tuy nhiên, có những trường hợp các service nằm trong mạng nội bộ (intranet) và không thể bị gọi trực tiếp từ bên ngoài vì lý do bảo mật.

Để giải quyết bài toán này, người ta sử dụng một **Server Proxy** đứng trung gian:

- **Server Proxy** lắng nghe kết nối từ client bên ngoài.
- Các **Server nội bộ** chủ động kết nối ngược vào Server Proxy để đăng ký phục vụ.
- Khi có yêu cầu từ client, Server Proxy chuyển tiếp đến Server nội bộ thông qua kết nối đã được thiết lập sẵn.

Mô hình này gọi là **Reverse RPC**, tương tự khái niệm reverse proxy trong web.

![Mô hình Reverse RPC](https://zalopay-oss.github.io/go-advanced/images/reverse-rpc2.png)

Trong mô hình này:

- **Server Proxy** đóng vai trò server đối với client bên ngoài.
- **Server nội bộ** đóng vai trò client khi kết nối vào Server Proxy, nhưng đồng thời lại là server RPC cung cấp dịch vụ.

### Triển khai Reverse RPC

#### server/main.go (Server nội bộ)

```go
package main

import (
	"net"
	"net/rpc"
	"time"
)

// GreetingService là RPC service cung cấp hàm Hello
type GreetingService struct{}

func (p *GreetingService) Hello(req string, res *string) error {
	*res = "Hello " + req
	return nil
}

func main() {
	// Đăng ký service
	rpc.Register(new(GreetingService))

	for {
		// Server nội bộ chủ động kết nối đến Server Proxy tại localhost:1234
		conn, _ := net.Dial("tcp", "localhost:1234")

		if conn == nil {
			// Nếu chưa kết nối được, thử lại sau 1 giây
			time.Sleep(time.Second)
			continue
		}

		// Phục vụ RPC trên kết nối này
		rpc.ServeConn(conn)
		conn.Close()
	}
}
```

Server nội bộ không lắng nghe kết nối đến; thay vào đó, nó chủ động kết nối ra ngoài và cung cấp RPC service trên kết nối đó.

#### client/main.go (Server Proxy / Client bên ngoài)

```go
package main

import (
	"fmt"
	"log"
	"net"
	"net/rpc"
)

func main() {
	// Lắng nghe trên cổng 1234, chờ Server nội bộ kết nối vào
	listener, err := net.Listen("tcp", "localhost:1234")
	if err != nil {
		log.Fatal("ListenTCP error: ", err)
	}

	clientChan := make(chan *rpc.Client)

	go func() {
		for {
			conn, err := listener.Accept()
			if err != nil {
				log.Fatal("Accept error: ", err)
			}

			// Mỗi khi Server nội bộ kết nối vào, tạo RPC Client
			// từ kết nối đó và gửi vào channel để xử lý
			clientChan <- rpc.NewClient(conn)
		}
	}()

	doClientWork(clientChan)
}

func doClientWork(clientChan <-chan *rpc.Client) {
	// Nhận RPC Client từ channel (chờ đến khi Server nội bộ kết nối)
	client := <-clientChan
	defer client.Close()

	var reply string

	// Gọi hàm Hello trên Server nội bộ thông qua kết nối Reverse RPC
	err := client.Call("GreetingService.Hello", "Gia Bao", &reply)
	if err != nil {
		log.Fatal("Call error: ", err)
	}

	fmt.Println("Response:", reply)
}
```

### Kết quả

```bash
Response: Hello Gia Bao
```

Với Reverse RPC, phía bên ngoài có thể gọi được hàm trên Server nội bộ mà không cần Server nội bộ mở cổng lắng nghe ra ngoài, giúp đảm bảo an toàn cho hệ thống mạng nội bộ.
