**Định nghĩa:** ==là loại chỉ mục sử dụng **hàm băm (hash function)** để ánh xạ dữ liệu đến các vị trí lưu trữ cụ thể==. Nó hoạt động cực nhanh với độ phức tạp thời gian là O(1) cho các thao tác tìm kiếm khớp chính xác (so sánh bằng), nhưng không hỗ trợ tìm kiếm theo khoảng (>, <, BETWEEN).

Hash index là được thiết kế cho query data một cách cực nhanh, khi điểu kiện query là `bằng` trên index column nào đó, `hash index` có thể làm việc truy vấn data rất nhanh, và đồng thời `hash index` cũng xác định trực tiếp vùng lưu trữ dữ liệu mong muốn, chỉ phù hợp cho những tình huống `query` trên so sánh bằng, như `=` or `in`.

không như những loại index khác, hash index là khi có một hoạt động thay đổi data `(inserts, updates, and deletes)` thì sẽ cần rehash lại và quá trình này là tốn kém hơn `BTree` index.

Ví dụ chưa có thiết lập hash index:
```sql
explain analyse
SELECT * FROM products WHERE sku = 'SKU-12345';
```

***OutPut:***
```
Gather  (cost=1000.00..19582.04 rows=1 width=52) (actual time=1911.358..1978.890 rows=1 loops=1)
  Workers Planned: 1
  Workers Launched: 1
  ->  Parallel Seq Scan on products  (cost=0.00..18581.94 rows=1 width=52) (actual time=964.984..1900.013 rows=0 loops=2)

```

Đã thiết lập Hash index:
```sql
Create index idx_products_sku_hash on products using hash (sku);

explain analyse
SELECT * FROM products WHERE sku = 'SKU-12345';
```

***OutPut:***
```

Planning Time: 0.428 ms
Execution Time: 0.130 ms
```

**Giới hạn quan trọng:** Hash Index **chỉ hỗ trợ `=`**, hoàn toàn **không hỗ trợ** `<`, `>`, `BETWEEN`, `ORDER BY`, hay `LIKE` — vì hash function phá vỡ thứ tự dữ liệu gốc (2 giá trị gần nhau về mặt số/chữ không đảm bảo có hash gần nhau).

> **Thực tế:** trong PostgreSQL hiện đại, B-tree đã được tối ưu tốt tới mức xử lý `=` gần bằng Hash Index, nên Hash Index **ít khi được dùng thực tế** trừ khi có lý do đặc biệt (VD: cột rất dài, chỉ cần so sánh bằng). Hầu hết trường hợp, B-tree là lựa chọn mặc định an toàn vì linh hoạt hơn nhiều.
