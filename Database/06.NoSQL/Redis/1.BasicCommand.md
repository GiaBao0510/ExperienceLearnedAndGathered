# Redis – Cấu hình & Câu lệnh cơ bản

---

## **0. Kiểm tra và cài đặt Redis trên Docker**

### Cài đặt image Redis

```bash
docker pull redis
```

Kiểm tra image đã tồn tại chưa:

```bash
docker images redis
```

Kết quả mẫu:

```
REPOSITORY   TAG       IMAGE ID       CREATED       SIZE
redis        latest    77e6be7eb290   2 weeks ago   139MB
```

### Tạo Container Redis

Câu lệnh dưới đây sẽ tạo container Redis với mật khẩu bảo vệ và cấu hình tự khởi động khi Docker được bật lên:

```bash
docker run -d --name my-redis-server -p 6379:6379 --restart unless-stopped redis redis-server --requirepass "MyRedis_12345"
```

**Giải thích các tham số:**

|Tham số|Ý nghĩa|
|---|---|
|`-d`|**Detached** – Container chạy ngầm dưới nền, không chiếm terminal|
|`--name my-redis-server`|Đặt **tên cho container**, giúp dễ quản lý (start, stop, logs, exec…)|
|`-p 6379:6379`|**Map cổng** từ máy host sang container, cho phép kết nối từ localhost, ứng dụng .NET, Redis CLI,...|
|`--restart unless-stopped`|**Tự khởi động** container khi Docker restart|
|`--requirepass "MyRedis_12345"`|Đặt **mật khẩu xác thực** cho Redis|

**Các giá trị của `--restart`:**

| Giá trị          | Ý nghĩa                                                        |
| ---------------- | -------------------------------------------------------------- |
| `no`             | Không tự khởi động (mặc định)                                  |
| `always`         | Luôn tự khởi động, kể cả khi bạn stop thủ công                 |
| `unless-stopped` | Tự khởi động khi Docker restart, **trừ khi** bạn stop thủ công |
| `on-failure`     | Chỉ tự khởi động khi container bị lỗi (exit code khác 0)       |

### Kết nối vào Redis CLI trong Container

Giả sử container đang chạy như sau:

```
CONTAINER ID   IMAGE          COMMAND                  CREATED       STATUS         PORTS                    NAMES
fc6b05b35fdb   redis:latest   "docker-entrypoint.s…"   10 days ago   Up 4 minutes   0.0.0.0:6379->6379/tcp   my-redis-server
```

Dùng lệnh sau để kết nối vào Redis CLI:

```bash
docker exec -it my-redis-server redis-cli -a "MyRedis_12345"
```

> **Lưu ý:** Tham số `-a` dùng để truyền mật khẩu xác thực trực tiếp. Ngoài ra, bạn cũng có thể xác thực sau khi vào CLI bằng lệnh `AUTH MyRedis_12345`.

## **1. Redis Key**

Các lệnh dùng để **thao tác và quản lý key** trong Redis:

|Command|Ý nghĩa|
|---|---|
|`EXISTS key`|Kiểm tra xem key có tồn tại không (trả về 1 nếu có, 0 nếu không)|
|`DEL key`|Xóa key nếu tồn tại|
|`EXPIRE key seconds`|Đặt thời gian hết hạn cho key sau `seconds` giây|
|`KEYS pattern`|Tìm các key theo pattern (ví dụ: `KEYS user:*`)|
|`TTL key`|Lấy thời gian sống còn lại của key (giây). Trả về `-1` nếu không có TTL, `-2` nếu key không tồn tại|
|`PERSIST key`|Xóa thời gian hết hạn, biến key thành tồn tại vĩnh viễn|
|`RENAME key newkey`|Đổi tên key|
|`RENAMENX key newkey`|Đổi tên key sang `newkey`, chỉ khi `newkey` **chưa tồn tại**|
|`TYPE key`|Lấy kiểu dữ liệu đang lưu trữ tại key (string, list, hash, set, zset)|

> **Lưu ý:** Tránh dùng `KEYS *` trên môi trường production vì có thể gây chậm hệ thống khi có nhiều key. Thay vào đó hãy dùng `SCAN`.

## **2. Redis String**

String là kiểu dữ liệu cơ bản nhất trong Redis, dùng để lưu trữ **giá trị văn bản hoặc số**.

**Ví dụ:**

```
127.0.0.1:6379> SET myname giabao
OK
127.0.0.1:6379> GET myname
"giabao"
```

|Command|Ý nghĩa|
|---|---|
|`SET key value`|Đặt giá trị cho key|
|`GET key`|Lấy giá trị tại key|
|`GETRANGE key start end`|Lấy chuỗi con từ vị trí `start` đến `end`|
|`GETSET key value`|Lấy giá trị cũ và đặt giá trị mới (atomic)|
|`MGET key1 key2 ...`|Lấy giá trị của nhiều key cùng lúc|
|`MSET key1 val1 key2 val2 ...`|Đặt giá trị cho nhiều key cùng lúc|
|`SETEX key seconds value`|Đặt giá trị và thời gian hết hạn (giây) cho key|
|`SETNX key value`|Đặt giá trị cho key **chỉ khi key chưa tồn tại**|
|`STRLEN key`|Lấy độ dài chuỗi giá trị tại key|
|`INCR key`|Tăng giá trị số nguyên tại key lên **1**|
|`INCRBY key n`|Tăng giá trị số nguyên tại key lên **n** đơn vị|
|`INCRBYFLOAT key f`|Tăng giá trị số thực tại key lên **f**|
|`DECR key`|Giảm giá trị số nguyên tại key xuống **1**|
|`DECRBY key n`|Giảm giá trị số nguyên tại key xuống **n** đơn vị|

## **3. Redis Hash**

Hash được dùng để lưu trữ **đối tượng (object)** dưới dạng tập hợp các cặp `field – value`, tương tự như một bản ghi trong cơ sở dữ liệu.

**Ví dụ:**

```
127.0.0.1:6379> HSET user:1 name "john" age 30
(integer) 2
127.0.0.1:6379> HGET user:1 name
"john"
127.0.0.1:6379> HGETALL user:1
1) "name"
2) "john"
3) "age"
4) "30"
```

|Command|Ý nghĩa|
|---|---|
|`HSET key field value`|Đặt giá trị cho một field trong hash|
|`HGET key field`|Lấy giá trị của một field trong hash|
|`HMSET key field1 val1 field2 val2 ...`|Đặt giá trị cho nhiều field trong hash (cùng lúc)|
|`HMGET key field1 field2 ...`|Lấy giá trị của nhiều field trong hash|
|`HGETALL key`|Lấy **tất cả** các field và value trong hash|
|`HDEL key field1 field2 ...`|Xóa một hoặc nhiều field trong hash|
|`HEXISTS key field`|Kiểm tra field có tồn tại trong hash không (1/0)|
|`HLEN key`|Lấy số lượng field trong hash|
|`HKEYS key`|Lấy danh sách tất cả các field trong hash|
|`HVALS key`|Lấy danh sách tất cả các value trong hash|
|`HINCRBY key field n`|Tăng giá trị số nguyên của field lên **n** đơn vị|
|`HINCRBYFLOAT key field f`|Tăng giá trị số thực của field lên **f**|

## **4. Redis List**

List là **danh sách có thứ tự** cho phép lưu các phần tử trùng lặp. List thường được sử dụng để mô phỏng **Stack (LIFO)** hoặc **Queue (FIFO)**.

- **Stack**: dùng `LPUSH` + `LPOP`
- **Queue**: dùng `RPUSH` + `LPOP`

**Ví dụ:**

```
127.0.0.1:6379> LPUSH TaiKhoan user1
(integer) 1
127.0.0.1:6379> LPUSH TaiKhoan user2
(integer) 2
127.0.0.1:6379> LPUSH TaiKhoan user3
(integer) 3
127.0.0.1:6379> LRANGE TaiKhoan 0 -1
1) "user3"
2) "user2"
3) "user1"
```

|Command|Ý nghĩa|
|---|---|
|`LPUSH key value1 value2 ...`|Thêm các phần tử vào **đầu** danh sách|
|`RPUSH key value1 value2 ...`|Thêm các phần tử vào **cuối** danh sách|
|`LPOP key`|Lấy và xóa phần tử ở **đầu** danh sách|
|`RPOP key`|Lấy và xóa phần tử ở **cuối** danh sách|
|`LRANGE key start end`|Lấy các phần tử từ index `start` đến `end` (dùng `-1` để lấy đến cuối)|
|`LINDEX key index`|Lấy phần tử tại vị trí `index`|
|`LLEN key`|Lấy độ dài (số phần tử) của danh sách|
|`LSET key index value`|Đặt giá trị mới tại vị trí `index`|
|`LINSERT key BEFORE\|AFTER pivot value`|Chèn `value` vào trước hoặc sau phần tử `pivot`|
|`LREM key count value`|Xóa `count` phần tử có giá trị bằng `value` khỏi danh sách|

## **5. Redis Set**

Set là **tập hợp các giá trị không trùng lặp** và không có thứ tự. Thường dùng để kiểm tra thành viên, loại trừ phần tử trùng lặp, hoặc thực hiện các phép toán tập hợp.

**Ví dụ:**

```
127.0.0.1:6379> SADD server gachien
(integer) 1
127.0.0.1:6379> SADD server gvr
(integer) 1
127.0.0.1:6379> SADD server gfamily
(integer) 1
127.0.0.1:6379> SMEMBERS server
1) "gachien"
2) "gvr"
3) "gfamily"
```

|Command|Ý nghĩa|
|---|---|
|`SADD key value1 value2 ...`|Thêm các phần tử vào tập hợp|
|`SCARD key`|Lấy số lượng phần tử trong tập hợp|
|`SMEMBERS key`|Lấy tất cả phần tử trong tập hợp|
|`SISMEMBER key value`|Kiểm tra `value` có trong tập hợp không (1/0)|
|`SREM key value1 value2 ...`|Xóa một hoặc nhiều phần tử khỏi tập hợp|
|`SPOP key`|Xóa và trả về **một phần tử ngẫu nhiên** trong tập hợp|
|`SRANDMEMBER key [count]`|Lấy ngẫu nhiên một (hoặc nhiều) phần tử **mà không xóa**|
|`SUNION key1 key2 ...`|Hợp của nhiều tập hợp|
|`SINTER key1 key2 ...`|Giao của nhiều tập hợp|
|`SDIFF key1 key2 ...`|Hiệu của tập hợp (key1 trừ đi các key còn lại)|

## **6. Redis Sorted Set (ZSet)**

Sorted Set là tập hợp các **giá trị duy nhất**, mỗi giá trị gắn với một **score (điểm số)** để sắp xếp từ thấp đến cao. Thường dùng cho **bảng xếp hạng (leaderboard)**, hàng đợi ưu tiên,...

**Ví dụ:**

```
127.0.0.1:6379> ZADD todoi 1 dcod
(integer) 1
127.0.0.1:6379> ZADD todoi 2 otc
(integer) 1
127.0.0.1:6379> ZADD todoi 3 gfamily
(integer) 1
127.0.0.1:6379> ZADD todoi 4 gvr
(integer) 1
127.0.0.1:6379> ZRANGE todoi 0 -1 WITHSCORES
1) "dcod"
2) "1"
3) "otc"
4) "2"
5) "gfamily"
6) "3"
7) "gvr"
8) "4"
```

| Command                                | Ý nghĩa                                                    |
| -------------------------------------- | ---------------------------------------------------------- |
| `ZADD key score1 val1 score2 val2 ...` | Thêm các phần tử vào sorted set với score tương ứng        |
| `ZCARD key`                            | Lấy số lượng phần tử trong sorted set                      |
| `ZSCORE key member`                    | Lấy giá trị score của một member                           |
| `ZRANK key member`                     | Lấy vị trí (index) của member, sắp xếp tăng dần theo score |
| `ZREVRANK key member`                  | Lấy vị trí của member, sắp xếp giảm dần theo score         |
| `ZRANGE key start end`                 | Lấy các phần tử từ `start` đến `end` (tăng dần theo score) |
| `ZRANGE key start end WITHSCORES`      | Lấy các phần tử kèm score (tăng dần)                       |
| `ZREVRANGE key start end WITHSCORES`   | Lấy các phần tử kèm score (giảm dần)                       |
| `ZCOUNT key min max`                   | Đếm số member có score trong khoảng `[min, max]`           |
| `ZREM key member1 member2 ...`         | Xóa một hoặc nhiều member khỏi sorted set                  |
| `ZINCRBY key increment member`         | Tăng score của member lên `increment`                      |

## **7. Redis Transaction**

Redis Transaction cho phép **nhóm nhiều lệnh lại** và thực thi chúng theo thứ tự, **nguyên tử (atomic)** – tức là toàn bộ nhóm lệnh được thực hiện liên tiếp mà không bị gián đoạn bởi lệnh khác.

Luồng hoạt động:

1. `MULTI` – Bắt đầu transaction, các lệnh tiếp theo được **xếp hàng (QUEUED)**
2. `EXEC` – Thực thi toàn bộ các lệnh đã xếp hàng
3. `DISCARD` – Hủy bỏ transaction, bỏ tất cả lệnh đã xếp hàng

**Ví dụ:**

```
127.0.0.1:6379> MULTI
OK
127.0.0.1:6379(TX)> SET fullname PhamGiaBao
QUEUED
127.0.0.1:6379(TX)> GET fullname
QUEUED
127.0.0.1:6379(TX)> INCR visitors
QUEUED
127.0.0.1:6379(TX)> EXEC
1) OK
2) "PhamGiaBao"
3) (integer) 1
```

**Ví dụ hủy transaction:**

```
127.0.0.1:6379> MULTI
OK
127.0.0.1:6379(TX)> SET fullname PhamGiaBao
QUEUED
127.0.0.1:6379(TX)> DISCARD
OK
```

|Command|Ý nghĩa|
|---|---|
|`MULTI`|Đánh dấu **bắt đầu** khối lệnh transaction|
|`EXEC`|**Thực thi** toàn bộ các lệnh trong transaction|
|`DISCARD`|**Hủy bỏ** transaction, xóa toàn bộ lệnh đã xếp hàng|
|`WATCH key`|Theo dõi key; nếu key bị thay đổi trước `EXEC`, transaction sẽ bị hủy tự động|

> **Lưu ý quan trọng:** Redis Transaction **không hỗ trợ rollback** như SQL. Nếu một lệnh trong `EXEC` bị lỗi logic (ví dụ: `INCR` trên giá trị không phải số), các lệnh còn lại vẫn được thực thi bình thường.
