#### 3.1. Các hàm tổng hợp (Aggregate Functions) cơ bản

```sql
SELECT
    COUNT(*)        AS total_orders,        -- đếm số dòng
    COUNT(customer_id) AS orders_with_customer, -- đếm số dòng KHÔNG NULL ở cột này
    SUM(total)       AS total_revenue,
    AVG(total)        AS avg_order_value,
    MAX(total)        AS max_order,
    MIN(total)        AS min_order
FROM orders;
```

⚠️ **Điểm hay bị hỏi phỏng vấn:** `COUNT(*)` đếm **tất cả các dòng** (kể cả dòng có NULL ở mọi cột), còn `COUNT(column_name)` chỉ đếm các dòng mà **cột đó khác NULL**.

Với data mẫu (`orders` có 1 dòng `customer_id = NULL`):

```sql
SELECT COUNT(*) FROM orders;           -- 5
SELECT COUNT(customer_id) FROM orders; -- 4 (bỏ dòng guest_order)
```

Các hàm `SUM`, `AVG`, `MAX`, `MIN` cũng **tự động bỏ qua NULL** khi tính toán — không coi NULL là 0.

```sql
-- Nếu 1 dòng total = NULL, SUM và AVG vẫn tính đúng trên các dòng còn lại
-- Nhưng nếu TOÀN BỘ giá trị là NULL, SUM trả về NULL (không phải 0)
SELECT SUM(total) FROM orders WHERE status = 'nonexistent_status'; -- → NULL, không
```

Đây là lý do khi hiển thị ra API/report, dân backend hay wrap bằng `COALESCE`:

```sql
SELECT COALESCE(SUM(total), 0) AS total_revenue
FROM orders WHERE status = 'nonexistent_status';  -- → 0
```

**3.2. GROUP BY — nhóm dữ liệu để tính tổng hợp theo nhóm**

```sql
-- Doanh thu theo từng trạng thái đơn hàng
Select status, count(*) as order_count, sum(total) as revenue
from orders
group by status;
```

*output:*

| status      | order_count | revenue   |
| ----------- | ----------- | --------- |
| completed   | 2           | 700000.00 |
| cancelled   | 1           | 800000.00 |
| pending     | 1           | 150000.00 |
| guest_order | 1           | 99000.00  |

**Quy tắc bắt buộc:** mọi cột xuất hiện trong `SELECT` mà **không nằm trong hàm tổng hợp** thì bắt buộc phải có trong `GROUP BY`.

```sql
-- SAI: name không nằm trong GROUP BY và không phải hàm tổng hợp
Select o.customer_id, c.name, sum(total)
from orders o JOIN customers c on o.customer_id = c.id
group by o.customer_id;
```

*output:*

```shell
Failed to run sql query: ERROR:  42803: column "c.name" must appear in the GROUP BY clause or be used in an aggregate function
LINE 1: Select o.customer_id, c.name, sum(total)
                              ^
```

```sql
-- ĐÚNG
Select o.customer_id, c.name, sum(total)
from orders o JOIN customers c on o.customer_id = c.id
group by o.customer_id, c.name;
```

*output:*

| customer_id | name  | sum       |
| ----------- | ----- | --------- |
| 3           | Cuong | 800000.00 |
| 2           | Binh  | 150000.00 |
| 1           | An    | 700000.00 |

#### 3.3 Giải bài tập số 6 ở Phần 2 (tổng doanh thu theo khách hàng, kể cả khách chưa mua)

Đây là kết hợp LEFT JOIN + GROUP BY + COALESCE — pattern rất hay dùng trong thực tế:

```sql
Select o.customer_id, 
  c.name, 
  COALESCE(sum(total), 0) AS total_revenue,
  COUNT(o.id) AS order_count

from orders o JOIN customers c on o.customer_id = c.id
group by o.customer_id, c.name
order by total_revenue DESC;
```

*output:*

| customer_id | name  | total_revenue | order_count |
| ----------- | ----- | ------------- | ----------- |
| 3           | Cuong | 800000.00     | 1           |
| 1           | An    | 700000.00     | 2           |
| 2           | Binh  | 150000.00     | 1           |

#### 3.4. HAVING — lọc SAU khi đã GROUP BY

`WHERE` lọc dòng **trước khi** nhóm. `HAVING` lọc nhóm **sau khi** đã tính tổng hợp.

```sql
Select 
  c.name, 
  sum(o.total) AS revenue

from orders o JOIN customers c on o.customer_id = c.id
group by c.name
having sum(o.total) > 300000;
```

*output:*

| name  | revenue   |
| ----- | --------- |
| An    | 700000.00 |
| Cuong | 800000.00 |

⚠️ **Bẫy phỏng vấn kinh điển:** không thể viết `WHERE SUM(o.total) > 300000` — vì lúc `WHERE` chạy, hàm tổng hợp **chưa được tính**. Nhớ lại thứ tự thực thi ở Phần 1:

```
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
```

Kết hợp cả `WHERE` và `HAVING` trong 1 câu để thấy rõ vai trò khác nhau:

```sql
-- Chỉ tính đơn "completed", sau đó chỉ lấy khách có tổng > 300,000
SELECT c.name, SUM(o.total) AS revenue
FROM customers c
JOIN orders o ON c.id = o.customer_id
WHERE o.status = 'completed'      -- lọc TỪNG DÒNG trước khi nhóm
GROUP BY c.name
HAVING SUM(o.total) > 300000;     -- lọc SAU KHI đã tính tổng theo nhóm
```

*output:*

| name | revenue   |
| ---- | --------- |
| An   | 700000.00 |

#### **3.5. GROUP BY nhiều cột**

```sql
-- Doanh thu theo từng khách hàng, theo từng trạng thái
SELECT c.name, o.status, SUM(o.total) AS revenue
FROM customers c
JOIN orders o ON c.id = o.customer_id
GROUP BY c.name, o.status
ORDER BY c.name;
```

*output:*

| name  | status    | revenue   |
| ----- | --------- | --------- |
| An    | completed | 700000.00 |
| Binh  | pending   | 150000.00 |
| Cuong | cancelled | 800000.00 |

#### 3.6. DISTINCT trong hàm tổng hợp

```sql
-- Đếm số khách hàng KHÁC NHAU đã từng đặt hàng (không đếm trùng)
SELECT COUNT(DISTINCT customer_id) FROM orders;
```

Rất hữu ích khi 1 khách có nhiều đơn hàng nhưng bạn chỉ muốn đếm số khách unique.

### **Q&A**

- **`COUNT(*)` và `COUNT(column_name)` khác nhau thế nào?** Cho ví dụ dữ liệu có NULL để minh họa.

> `COUNT(*)` đếm **tất cả số dòng**, không quan tâm NULL. `COUNT(column_name)` chỉ đếm các dòng mà **cột đó khác NULL**. Ví dụ bảng `orders` có 5 dòng, 1 dòng `customer_id = NULL`: `COUNT(*) = 5` nhưng `COUNT(customer_id) = 4`.

- **Vì sao không thể viết điều kiện tổng hợp (`SUM(...) > x`) trong `WHERE`?** Phải dùng `HAVING`, giải thích theo thứ tự thực thi.

> Vì `WHERE` chạy trước `GROUP BY` trong thứ tự thực thi, lúc đó dữ liệu **chưa được nhóm và tổng hợp** nên `SUM()` chưa có giá trị để so sánh. Phải dùng `HAVING`, vì nó chạy sau khi GROUP BY đã tính xong.

- **Nếu SELECT có cột không nằm trong GROUP BY và không phải hàm tổng hợp thì sao?** Postgres và MySQL xử lý khác nhau thế nào?

> PostgreSQL sẽ báo lỗi ngay (`column must appear in GROUP BY clause or be used in an aggregate function`) vì nó tuân thủ chuẩn SQL nghiêm ngặt. MySQL (bản cũ, chế độ không strict) cho phép chạy nhưng giá trị trả về của cột đó là **không xác định** (DB tự chọn 1 dòng bất kỳ trong nhóm) — dễ gây bug âm thầm, rất nguy hiểm trong production.

- **`SUM()` trên tập rỗng/toàn NULL trả về gì?** Vì sao không phải là 0? Cách xử lý an toàn khi trả JSON cho frontend.

> Trả về `NULL`, không phải `0`. Vì về mặt logic, "tổng của không có gì" là "không xác định", không phải "bằng 0". Khi trả JSON cho frontend, nếu không xử lý sẽ hiện `null` gây lỗi hiển thị hoặc crash phép tính phía client. Cách xử lý an toàn: bọc bằng `COALESCE(SUM(total), 0)`.

- Viết query: **đếm số lượng khách hàng duy nhất đã đặt hàng trong trạng thái 'completed'.**

> ```sql
> SELECT COUNT(DISTINCT customer_id) 
> FROM orders 
> WHERE status = 'completed';
> ```

- Viết query: **tìm ra trạng thái đơn hàng (status) có giá trị trung bình (AVG) cao nhất.**

```sql
SELECT status, AVG(total) as AVG_total
FROM orders
group by status
order by AVG_total desc
limit 1;
```

- Giải thích sự khác nhau giữa `COUNT(o.id)` và `COUNT(*)` khi dùng chung với LEFT JOIN — vì sao chọn sai hàm có thể dẫn đến số liệu sai trong báo cáo thực tế.

> Với LEFT JOIN, khi bên phải không khớp, DB sinh ra dòng "đệm" với toàn bộ cột bên phải là NULL (nhưng dòng đó **vẫn tồn tại** trong result set). `COUNT(*)` đếm cả dòng đệm này → **đếm dư 1** cho mỗi khách không có đơn hàng. `COUNT(o.id)` chỉ đếm khi `o.id` khác NULL → đúng số đơn hàng thực tế (0 cho khách chưa mua). Nếu chọn nhầm `COUNT(*)` trong báo cáo "số đơn hàng theo khách", số liệu sẽ bị **thổi phồng sai lệch** — đây là lỗi rất dễ mắc và khó phát hiện nếu không test kỹ với dữ liệu có LEFT JOIN không khớp.
