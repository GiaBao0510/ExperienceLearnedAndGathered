Trong SQL, **subquery** (truy vấn con) là một câu lệnh `SELECT` được lồng bên trong một câu lệnh truy vấn khác (như `SELECT`, `FROM`, `WHERE`, `UPDATE`, hoặc `DELETE`). Subquery luôn được đặt trong cặp ngoặc đơn `()` và thường được thực thi trước để cung cấp dữ liệu cho câu lệnh chính

## **Subquery trong mệnh đề WHERE**

Thường được dùng để lọc dữ liệu dựa trên kết quả trả về của truy vấn con. Nó có thể trả về một giá trị duy nhất, một cột nhiều giá trị, hoặc nhiều cột.



```sql
-- Tìm đơn hàng có giá trị lớn > 
select o1.id, o1.customer_id, o1.total, o1.status 
from orders o1
where o1.id in (
  select o2.id
  from orders o2
  where o2.total > 500000
);
```

<u>*output:*</u>

| id  | customer_id | total     | status    |
| --- | ----------- | --------- | --------- |
| 4   | 3           | 800000.00 | cancelled |



```sql
-- Tìm khách hàng có tổng chi tiêu lớn hơn mức trung bình toàn hệ thống
SELECT c.name, SUM(o.total) AS total_spent
FROM customers c
JOIN orders o ON c.id = o.customer_id
GROUP BY c.name
HAVING SUM(o.total) > (
    SELECT AVG(total) FROM orders
);
```

<u><em>output:</em></u>

| name  | total_spent |
| ----- | ----------- |
| Binh  | 450000.00   |
| An    | 700000.00   |
| Cuong | 1250000.00  |

Subquery `(SELECT AVG(total) FROM orders)` chạy độc lập trước, trả về 1 giá trị duy nhất (scalar subquery), rồi mới so sánh.

## **Subquery trong mệnh đề FROM**

Đóng vai trò như một bảng tạm thời (derived table) để truy vấn chính lấy dữ liệu từ đó

```sql
-- Tính doanh thu theo khách, sau đó lọc top khách có doanh thu > 500k
SELECT * FROM (
    SELECT c.name, SUM(o.total) AS revenue
    FROM customers c
    JOIN orders o ON c.id = o.customer_id
    GROUP BY c.name
) AS customer_revenue
WHERE revenue > 500000;
```

<u><em>output:</em></u>

| name  | revenue    |
| ----- | ---------- |
| An    | 700000.00  |
| Cuong | 1250000.00 |

> Lưu ý: subquery trong FROM **bắt buộc phải có alias** (ở đây là `customer_revenue`), nếu không PostgreSQL sẽ báo lỗi.

## **Subquery trong mệnh đề SELECT**

Được dùng để tính toán hoặc hiển thị một giá trị cụ thể đi kèm với từng hàng dữ liệu của truy vấn chính.

```sql
-- Với mỗi khách hàng, hiện luôn số đơn hàng của họ (không cần GROUP BY)
SELECT
    c.name,
    (SELECT COUNT(*) FROM orders o WHERE o.customer_id = c.id) AS order_count
FROM customers c;
```

<u><em>output:</em></u>

| name  | order_count |
| ----- | ----------- |
| An    | 2           |
| Binh  | 2           |
| Cuong | 2           |
| Dung  | 0           |

## **Subquery với IN / EXISTS**

**Subquery với IN** trả về kết quả dựa trên việc so khớp một giá trị với một tập hợp danh sách. **Subquery với EXISTS** kiểm tra xem truy vấn con có trả về bất kỳ dòng nào hay không (đánh giá đúng/sai). Cả hai đều dùng để lọc dữ liệu từ bảng cha dựa trên dữ liệu ở bảng con

```sql
-- Khách hàng đã từng mua với đơn > 400k
SELECT * FROM customers
WHERE id IN (
    SELECT customer_id FROM orders WHERE total > 400000
);
```

<u><em>output:</em></u>

| id  | name  | email           |
| --- | ----- | --------------- |
| 1   | An    | an@gmail.com    |
| 3   | Cuong | cuong@gmail.com |



```sql
-- Dùng EXISTS (thường hiệu quả hơn IN với bảng lớn, và an toàn với NULL)
SELECT * FROM customers c
WHERE EXISTS (
    SELECT 1 FROM orders o WHERE o.customer_id = c.id AND o.total > 400000
);
```

<u><em>output:</em></u>

| id  | name  | email           |
| --- | ----- | --------------- |
| 1   | An    | an@gmail.com    |
| 3   | Cuong | cuong@gmail.com |

## **Common Table Expression (CTE) — `WITH ... AS (...)`**

**Common Table Expression (CTE)** là <mark>một tập hợp kết quả tạm thời</mark> được đặt tên, tồn tại duy nhất trong phạm vi của một câu lệnh SQL. Nó giúp bạn chia nhỏ các truy vấn phức tạp thành các khối logic dễ đọc, dễ quản lý hơn và có thể tái sử dụng nhiều lần trong truy vấn chính



**Cú pháp cơ bản**

CTE được bắt đầu bằng từ khóa `WITH`, theo sau là tên bảng tạm và câu lệnh định nghĩa nó nằm trong cặp ngoặc đơn `()`

```sql
WITH Ten_CTE AS (
    -- Câu lệnh truy vấn tạo ra tập kết quả tạm
    SELECT cot_1, cot_2 
    FROM Ten_Bang 
    WHERE dieu_kien
)
-- Truy vấn chính sử dụng lại CTE vừa tạo
SELECT * 
FROM Ten_CTE;

```



Ví dụ: CTE giống như đặt tên cho 1 subquery, giúp query dễ đọc hơn, đặc biệt khi cần dùng lại nhiều lần hoặc query nhiều bước.

```sql
WITH customer_revenue AS (
    SELECT c.id, c.name, SUM(o.total) AS revenue
    FROM customers c
    LEFT JOIN orders o ON c.id = o.customer_id
    GROUP BY c.id, c.name
)
SELECT name, revenue
FROM customer_revenue
WHERE revenue > 300000
ORDER BY revenue DESC;
```

<u><em>output:</em></u>

| name  | revenue    |
| ----- | ---------- |
| Cuong | 1250000.00 |
| An    | 700000.00  |
| Binh  | 450000.00  |



Nhiều CTE cùng lúc (chain nhiều bước xử lý):

```sql
WITH completed_orders AS (
    SELECT * FROM orders WHERE status = 'completed'
),
customer_summary AS (
    SELECT c.name, COUNT(*) AS order_count, SUM(co.total) AS revenue
    FROM customers c
    JOIN completed_orders co ON c.id = co.customer_id
    GROUP BY c.name
)
Select *
from customer_summary;
```

<u><em>output:</em></u>

| name  | order_count | revenue   |
| ----- | ----------- | --------- |
| An    | 2           | 700000.00 |
| Binh  | 1           | 300000.00 |
| Cuong | 1           | 450000.00 |



**CTE đệ quy (Recursive CTE)** — dùng cho dữ liệu phân cấp (category cha-con, tổ chức nhân sự):

```sql
-- Dùng bảng employees (manager_id) ở Phần 2
WITH RECURSIVE org_chart AS (
    -- Anchor: điểm bắt đầu (nhân viên không có quản lý = cấp cao nhất)
    SELECT id, name, manager_id, 1 AS level
    FROM employees
    WHERE manager_id IS NULL

    UNION ALL

    -- Recursive: nối tiếp xuống các cấp dưới
    SELECT e.id, e.name, e.manager_id, oc.level + 1
    FROM employees e
    JOIN org_chart oc ON e.manager_id = oc.id
)
SELECT * FROM org_chart ORDER BY level;
```

<u><em>output:</em></u>

| id  | name           | manager_id | level |
| --- | -------------- | ---------- | ----- |
| 1   | Sếp Bảo        | null       | 1     |
| 2   | An             | 1          | 2     |
| 3   | Vũ Trung Nghĩa | 1          | 2     |
| 4   | Kiệt           | 1          | 2     |
| 5   | Binh           | 1          | 2     |



#### ***Ưu điểm của CTE***

- **Tính rõ ràng:** Giống như việc đặt tên biến trong lập trình, CTE thay thế các truy vấn con (subqueries) lồng nhau rối rắm bằng các bước độc lập, rành mạch. 

- **Tái sử dụng:** Nếu bạn cần dùng cùng một tập dữ liệu nhiều lần trong một câu lệnh, bạn chỉ cần viết CTE một lần và gọi lại tên của nó ở các phần sau. 

- **Đệ quy (Recursive):** CTE có khả năng tự tham chiếu đến chính nó. Tính năng này cực kỳ mạnh mẽ khi bạn cần truy vấn dữ liệu phân cấp như cấu trúc tổ chức (nhân viên - quản lý) hoặc sơ đồ cây. 



**So sánh CTE vs Subquery thường:**

- CTE dễ đọc hơn, đặt tên rõ ràng cho từng bước.
- CTE có thể tái sử dụng nhiều lần trong cùng câu query (không phải viết lại).
- CTE hỗ trợ đệ quy, subquery thường thì không.
- Về hiệu năng: PostgreSQL bản cũ (trước 12) coi CTE là "optimization fence" (không tối ưu xuyên qua CTE), nhưng từ Postgres 12 trở đi, CTE không đệ quy sẽ được inline tự động nếu có thể — hiệu năng gần như tương đương subquery

#### Window Functions

**Window function trong SQL** là hàm thực hiện phép tính trên một tập hợp các hàng (được gọi là "window") có liên quan đến hàng hiện tại. Khác với hàm tổng hợp (Aggregate function như `SUM`, `AVG`), window function không gộp nhiều hàng thành một hàng duy nhất mà vẫn giữ nguyên số lượng hàng ban đầu, kết quả được tính riêng cho từng dòng

Điểm khác biệt cốt lõi so với `GROUP BY`: **Window Function không làm gộp dòng lại** — mỗi dòng gốc vẫn giữ nguyên, chỉ thêm 1 cột tính toán dựa trên "cửa sổ" (window) các dòng liên quan.

Cú pháp cơ bản của window function luôn đi kèm mệnh đề `OVER()`:  
`Hàm() OVER (PARTITION BY Cột_Phân_Nhóm ORDER BY Cột_Sắp_Xếp)`



**a) ROW_NUMBER(), RANK(), DENSE_RANK()**

```sql
SELECT
    c.name,
    o.total,
    ROW_NUMBER() OVER (ORDER BY o.total DESC) AS row_num,
    RANK()       OVER (ORDER BY o.total DESC) AS rank_num,
    DENSE_RANK() OVER (ORDER BY o.total DESC) AS dense_rank_num
FROM orders o
JOIN customers c ON o.customer_id = c.id;
```

<u><em>output:</em></u>

| name  | total     | row_num | rank_num | dense_rank_num |
| ----- | --------- | ------- | -------- | -------------- |
| Cuong | 800000.00 | 1       | 1        | 1              |
| An    | 500000.00 | 2       | 2        | 2              |
| Cuong | 450000.00 | 3       | 3        | 3              |
| Binh  | 300000.00 | 4       | 4        | 4              |
| An    | 200000.00 | 5       | 5        | 5              |
| Binh  | 150000.00 | 6       | 6        | 6              |

Khác nhau khi có **giá trị trùng nhau**: giả sử 2 đơn cùng `total = 500000` đứng hạng 1:

- `ROW_NUMBER()`: 1, 2, 3, 4... (luôn tăng liên tục, không quan tâm trùng)
- `RANK()`: 1, 1, 3, 4... (trùng hạng thì cùng số, nhưng **nhảy cóc** số tiếp theo)
- `DENSE_RANK()`: 1, 1, 2, 3... (trùng hạng thì cùng số, **không nhảy cóc**)



**b) PARTITION BY — chia nhỏ "cửa sổ" theo nhóm**

```sql
-- Xếp hạng đơn hàng theo giá trị, NHƯNG xếp riêng cho từng khách hàng
SELECT
    c.name,
    o.total,
    RANK() OVER (PARTITION BY c.id ORDER BY o.total DESC) AS rank_within_customer
FROM orders o
JOIN customers c ON o.customer_id = c.id
WHERE o.customer_id IS NOT NULL;
```

<u><em>output:</em></u>

| name  | total     | rank_within_customer |
| ----- | --------- | -------------------- |
| An    | 500000.00 | 1                    |
| An    | 200000.00 | 2                    |
| Binh  | 300000.00 | 1                    |
| Binh  | 150000.00 | 2                    |
| Cuong | 800000.00 | 1                    |
| Cuong | 450000.00 | 2                    |

`PARTITION BY c.id` giống như "GROUP BY tạm thời" chỉ để tính rank, nhưng **không làm gộp dòng** — vẫn giữ nguyên từng đơn hàng riêng lẻ.



**c) SUM() OVER(), AVG() OVER() — tổng/trung bình lũy kế**

```sql
-- Tổng doanh thu lũy kế (running total) theo thời gian
SELECT
    id,
    customer_id,
    total,
    SUM(total) OVER (ORDER BY id) AS running_total
FROM orders
WHERE customer_id IS NOT NULL;
```

<u><em>output:</em></u>

| id  | customer_id | total     | running_total |
| --- | ----------- | --------- | ------------- |
| 1   | 1           | 500000.00 | 500000.00     |
| 2   | 1           | 200000.00 | 700000.00     |
| 3   | 2           | 150000.00 | 850000.00     |
| 4   | 3           | 800000.00 | 1650000.00    |
| 6   | 2           | 300000.00 | 1950000.00    |
| 7   | 3           | 450000.00 | 2400000.00    |



```sql
-- So sánh mỗi đơn hàng với trung bình của khách đó (không cần JOIN lại hay subquery)
SELECT
    c.name,
    o.total,
    AVG(o.total) OVER (PARTITION BY c.id) AS customer_avg,
    o.total - AVG(o.total) OVER (PARTITION BY c.id) AS diff_from_avg
FROM orders o
JOIN customers c ON o.customer_id = c.id
WHERE o.customer_id IS NOT NULL;
```

<u><em>output:</em></u>

| name  | total     | customer_avg        | diff_from_avg        |
| ----- | --------- | ------------------- | -------------------- |
| An    | 500000.00 | 350000.000000000000 | 150000.000000000000  |
| An    | 200000.00 | 350000.000000000000 | -150000.000000000000 |
| Binh  | 150000.00 | 225000.000000000000 | -75000.000000000000  |
| Binh  | 300000.00 | 225000.000000000000 | 75000.000000000000   |
| Cuong | 800000.00 | 625000.000000000000 | 175000.000000000000  |
| Cuong | 450000.00 | 625000.000000000000 | -175000.000000000000 |



**d) LAG() / LEAD() — lấy giá trị dòng trước/sau**

```sql
-- So sánh mỗi đơn hàng với trung bình của khách đó (không cần JOIN lại hay subquery)
SELECT
    c.name,
    o.total,
    LAG(o.total) OVER(PARTITION BY c.id ORDER BY o.id) AS previous_order_total
FROM orders o
JOIN customers c ON o.customer_id = c.id
WHERE o.customer_id IS NOT NULL;
```

<u><em>output:</em></u>

| name  | total     | previous_order_total |
| ----- | --------- | -------------------- |
| An    | 500000.00 | null                 |
| An    | 200000.00 | 500000.00            |
| Binh  | 150000.00 | null                 |
| Binh  | 300000.00 | 150000.00            |
| Cuong | 800000.00 | null                 |
| Cuong | 450000.00 | 800000.00            |



**Tổng kết khác biệt cốt lõi GROUP BY vs Window Function:**

|                                   | GROUP BY                 | Window Function                            |
| --------------------------------- | ------------------------ | ------------------------------------------ |
| Số dòng kết quả                   | Gộp lại, ít hơn dòng gốc | Giữ nguyên số dòng gốc                     |
| Có thể xem chi tiết từng dòng gốc | Không                    | Có                                         |
| Cú pháp                           | `GROUP BY col`           | `... OVER (PARTITION BY col ORDER BY col)` |

#### Q&A:

**1. Khác nhau giữa Subquery trong WHERE và subquery trong FROM?**

Subquery trong `WHERE` trả về giá trị hoặc tập giá trị dùng để **so sánh/lọc** (thường dùng với `=`, `IN`, `EXISTS`). Subquery trong `FROM` (derived table) tạo ra **1 bảng tạm** để query tiếp lên trên, bắt buộc phải có alias, và có thể chứa `GROUP BY`, `JOIN` như 1 bảng thật.

**2. Correlated subquery là gì? Vì sao có thể chậm?**

Là subquery mà bên trong nó tham chiếu đến cột của bảng ngoài (VD: `WHERE o.customer_id = c.id`). Vì subquery này **phụ thuộc vào từng dòng của bảng ngoài**, DB phải chạy lại subquery **cho mỗi dòng** của bảng ngoài (giống vòng lặp lồng nhau). Với bảng có N dòng, subquery chạy N lần → chậm khi N lớn. Cách tối ưu: thay bằng `JOIN` + `GROUP BY`, hoặc `EXISTS` nếu chỉ cần kiểm tra tồn tại.

**3. CTE khác gì so với subquery thường? Khi nào nên dùng CTE?**

CTE (`WITH ... AS`) đặt tên rõ ràng cho từng bước xử lý, giúp query dài dễ đọc và maintain hơn, có thể tái sử dụng nhiều lần trong cùng query, và hỗ trợ đệ quy (`WITH RECURSIVE`) — điều mà subquery thường không làm được. Nên dùng CTE khi: query có nhiều bước logic tuần tự, cần tái sử dụng 1 tập kết quả trung gian nhiều lần, hoặc xử lý dữ liệu phân cấp (category cha-con, tổ chức).

**4. Recursive CTE hoạt động như thế nào?**

Gồm 2 phần nối bằng `UNION ALL`: phần **anchor** (điểm khởi đầu, VD nhân viên không có quản lý) chạy 1 lần đầu tiên, và phần **recursive** (tham chiếu lại chính CTE đó) chạy lặp lại, mỗi lần lấy kết quả của lần trước làm đầu vào, cho đến khi không còn dòng mới nào sinh ra thì dừng.

**5. Sự khác nhau giữa ROW_NUMBER(), RANK(), DENSE_RANK() khi có giá trị trùng nhau?**

`ROW_NUMBER()` luôn đánh số tăng dần liên tục, không quan tâm trùng giá trị. `RANK()` cho các dòng trùng giá trị cùng 1 hạng, nhưng **bỏ qua (nhảy cóc)** số hạng tiếp theo (VD: 1, 1, 3). `DENSE_RANK()` cũng cho cùng hạng khi trùng, nhưng **không nhảy cóc** (VD: 1, 1, 2).

**6. GROUP BY và Window Function khác nhau cốt lõi ở điểm nào?**

`GROUP BY` **gộp nhiều dòng thành 1 dòng** đại diện cho mỗi nhóm, làm mất chi tiết từng dòng gốc. Window Function (`... OVER (...)`) **giữ nguyên số dòng gốc**, chỉ thêm 1 cột tính toán dựa trên nhóm liên quan (partition) — cho phép vừa xem chi tiết từng dòng, vừa có số liệu tổng hợp trong cùng 1 kết quả.

**7. PARTITION BY trong Window Function dùng để làm gì?**

Chia tập dữ liệu thành các nhóm nhỏ (giống GROUP BY tạm thời) để hàm window tính toán riêng cho từng nhóm, nhưng không làm gộp dòng — mỗi dòng trong nhóm vẫn giữ nguyên và có thêm giá trị tính toán từ nhóm đó (VD: rank riêng theo từng khách hàng, trung bình riêng theo từng category).

**8. Viết query xếp hạng Top 3 đơn hàng có giá trị cao nhất của MỖI khách hàng.**

```sql
WITH ranked_orders AS (
    SELECT
        c.name,
        o.total,
        ROW_NUMBER() OVER (PARTITION BY c.id ORDER BY o.total DESC) AS rn
    FROM orders o
    JOIN customers c ON o.customer_id = c.id
)
SELECT name, total
FROM ranked_orders
WHERE rn <= 3;
```

<u><em>output:</em></u>

| name  | total     |
| ----- | --------- |
| An    | 500000.00 |
| An    | 200000.00 |
| Binh  | 300000.00 |
| Binh  | 150000.00 |
| Cuong | 800000.00 |
| Cuong | 450000.00 |
