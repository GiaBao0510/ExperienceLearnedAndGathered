# **Các loại JOIN trong SQL**

Bạn copy đoạn này chạy trên PostgreSQL (hoặc psql/pgAdmin/DBeaver) để có dữ liệu thực hành xuyên suốt phần JOIN:

```sql
-- Bảng khách hàng
CREATE TABLE customers (
    id      SERIAL PRIMARY KEY,
    name    VARCHAR(100) NOT NULL,
    email   VARCHAR(100)
);

INSERT INTO customers (name, email) VALUES
('An',    'an@gmail.com'),
('Binh',  'binh@gmail.com'),
('Cuong', 'cuong@gmail.com'),
('Dung',  'dung@gmail.com');   -- Dung chưa có đơn hàng nào

-- Bảng đơn hàng
CREATE TABLE orders (
    id          SERIAL PRIMARY KEY,
    customer_id INT REFERENCES customers(id),
    total       NUMERIC(10,2),
    status      VARCHAR(20)
);

INSERT INTO orders (customer_id, total, status) VALUES
(1, 500000,  'completed'),
(1, 200000,  'completed'),
(2, 150000,  'pending'),
(3, 800000,  'cancelled'),
(NULL, 99000, 'guest_order');  -- đơn hàng của khách vãng lai, không gắn customer nào
```

---

#### 2.1. INNER JOIN

Chỉ lấy các dòng **khớp ở cả 2 bảng**. Đây là loại JOIN phổ biến nhất.

```sql
select c.name, o.id AS order_id, o.total, o.status
from customers c 
inner join orders o on c.id = o.customer_id;
```

*output:*

| name  | order_id | total     | status    |
| ----- | -------- | --------- | --------- |
| An    | 1        | 500000.00 | completed |
| An    | 2        | 200000.00 | completed |
| Binh  | 3        | 150000.00 | pending   |
| Cuong | 4        | 800000.00 | cancelled |

**Kết quả:** An (2 dòng), Binh (1 dòng), Cuong (1 dòng). **Dung bị loại** (không có đơn hàng), **guest_order bị loại** (không có customer).

> Cơ chế: DB duyệt qua từng dòng bên trái, tìm dòng khớp bên phải theo điều kiện `ON`. Nếu không khớp → dòng đó **không xuất hiện** trong kết quả, ở cả 2 phía.

---

#### 2.2. LEFT JOIN (LEFT OUTER JOIN)

Lấy **toàn bộ bảng bên trái**, dù có khớp hay không. Nếu không khớp, các cột bên phải sẽ là `NULL`.

```sql
select c.name, o.id AS order_id, o.total, o.status
from customers c 
left join orders o on c.id = o.customer_id;
```

*Output: *

| name  | order_id | total     | status    |
| ----- | -------- | --------- | --------- |
| An    | 1        | 500000.00 | completed |
| An    | 2        | 200000.00 | completed |
| Binh  | 3        | 150000.00 | pending   |
| Cuong | 4        | 800000.00 | cancelled |
| Dung  | null     | null      | null      |

**Kết quả:** An (2 dòng), Binh (1 dòng), Cuong (1 dòng), **Dung (1 dòng với order_id/total/status đều NULL)**.

**Use case thực tế:** "Tìm khách hàng chưa từng mua hàng" — pattern rất hay dùng trong thực tế:

```sql
select c.name, o.id AS order_id, o.total, o.status
from customers c 
left join orders o on c.id = o.customer_id
where o.id is null;
```

*Output:*

| name | order_id | total | status |
| ---- | -------- | ----- | ------ |
| Dung | null     | null  | null   |

⚠️ **Bẫy hay gặp:** Nếu bạn đặt điều kiện lọc của bảng phải vào `WHERE` thay vì `ON`, LEFT JOIN sẽ **biến thành INNER JOIN** một cách vô tình:

```sql
-- SAI Ý ĐỊNH: mất hết các dòng NULL (mất luôn Dung)select c.name, o.status
from customers c 
left join orders o on c.id = o.customer_id
where o.status = 'completed';
```

<u>Output</u>

| name | status    |
| ---- | --------- |
| An   | completed |
| An   | completed |

```sql
-- ĐÚNG Ý ĐỊNH: giữ Dung, chỉ lọc điều kiện status khi có đơn hàngselect c.name, o.status
from customers c 
left join orders o ON c.id = o.customer_id AND o.status = 'completed';
```

<u>Output</u>

| name  | status    |
| ----- | --------- |
| An    | completed |
| An    | completed |
| Binh  | null      |
| Cuong | null      |
| Dung  | null      |

---

#### 2.3. RIGHT JOIN (RIGHT OUTER JOIN)

Ngược lại LEFT JOIN — lấy toàn bộ bảng bên phải.

```sql
select c.name, o.status
from customers c 
right join orders o ON c.id = o.customer_id;
```

<u>Output</u>

| name  | status      |
| ----- | ----------- |
| An    | completed   |
| An    | completed   |
| Binh  | pending     |
| Cuong | cancelled   |
| null  | guest_order |

**Kết quả:** An, Binh, Cuong (như INNER), cộng thêm **1 dòng cho guest_order với `name = NULL`** (vì đơn này không gắn customer nào).

> Thực tế trong công việc, RIGHT JOIN ít được dùng — người ta thường viết lại thành LEFT JOIN bằng cách đảo thứ tự bảng cho dễ đọc (convention team). Nhưng bạn vẫn cần hiểu và biết dùng khi đọc code người khác.

---

#### 2.4. FULL JOIN (FULL OUTER JOIN)

Lấy **tất cả** các dòng từ cả 2 bảng, khớp được thì ghép, không khớp thì để NULL ở phía thiếu.

```sql
select c.name, o.status
from customers c 
full join orders o ON c.id = o.customer_id;
```

<u>Output</u>

| name  | status      |
| ----- | ----------- |
| An    | completed   |
| An    | completed   |
| Binh  | pending     |
| Cuong | cancelled   |
| null  | guest_order |
| Dung  | null        |

**Kết quả:** đầy đủ An, Binh, Cuong + **Dung (order NULL)** + **guest_order (name NULL)**.

**Use case thực tế:** đối chiếu dữ liệu giữa 2 hệ thống (VD: đối soát thanh toán giữa hệ thống nội bộ và cổng thanh toán) — tìm ra bản ghi lệch ở cả 2 phía.

> **Lưu ý:** MySQL **không hỗ trợ FULL JOIN** trực tiếp, phải giả lập bằng `LEFT JOIN UNION RIGHT JOIN`. PostgreSQL hỗ trợ native.

---

#### 2.5. CROSS JOIN

Tích Descartes — mỗi dòng bảng A ghép với **mọi** dòng bảng B. Không có điều kiện `ON`.

```sql
select c.name, o.status
from customers c 
cross join orders o;
```

<u>Output</u>

| name  | status      |
| ----- | ----------- |
| An    | completed   |
| Binh  | completed   |
| Cuong | completed   |
| Dung  | completed   |
| An    | completed   |
| Binh  | completed   |
| Cuong | completed   |
| Dung  | completed   |
| An    | pending     |
| Binh  | pending     |
| Cuong | pending     |
| Dung  | pending     |
| An    | cancelled   |
| Binh  | cancelled   |
| Cuong | cancelled   |
| Dung  | cancelled   |
| An    | guest_order |
| Binh  | guest_order |
| Cuong | guest_order |
| Dung  | guest_order |

⚠️ Cẩn thận: nếu vô tình JOIN 2 bảng mà **quên mất điều kiện ON**, SQL sẽ tự hiểu là CROSS JOIN → dữ liệu nhân lên khủng khiếp (bug rất phổ biến của người mới, gọi là "cartesian product bug").

---

#### 2.6. Self JOIN (join bảng với chính nó)

Không phải loại JOIN riêng, mà là kỹ thuật dùng INNER/LEFT JOIN để so sánh các dòng trong cùng 1 bảng. Rất hay gặp trong phỏng vấn.

Tạo bảng employees và điền gía trị

```sql
CREATE TABLE employees (
    id        SERIAL PRIMARY KEY,
    name      VARCHAR(100),
    manager_id INT REFERENCES employees(id)
);

INSERT INTO employees (name, manager_id) VALUES
('Sếp Bảo', NULL),
('An',       1),
('Vũ Trung Nghĩa',       1),
('Kiệt',       1),
('Binh',     1);
```

Tìm tên nhân viên và tên quản lý tương ứng

```sql
select e.name as employees, m.name as Manager 
from employees e
left join employees m on e.manager_id = m.id;
```

<u>Output</u>

| employees      | manager |
| -------------- | ------- |
| Sếp Bảo        | null    |
| An             | Sếp Bảo |
| Vũ Trung Nghĩa | Sếp Bảo |
| Kiệt           | Sếp Bảo |
| Binh           | Sếp Bảo |

#### 2.7. Tổng kết trực quan

| JOIN  | Lấy gì                              |
| ----- | ----------------------------------- |
| INNER | Chỉ giao nhau (khớp cả 2 bên)       |
| LEFT  | Toàn bộ trái + phần khớp phải       |
| RIGHT | Toàn bộ phải + phần khớp trái       |
| FULL  | Hợp của cả 2 bảng                   |
| CROSS | Tích Descartes, không cần điều kiện |

----

#### Câu hỏi phỏng vấn thực tế cho phần này

 **Sự khác nhau giữa đặt điều kiện lọc ở `ON` và ở `WHERE` khi dùng LEFT JOIN?** Cho ví dụ minh họa kết quả khác nhau.

> Điều kiện ở `ON` được áp dụng **trong lúc join** — nếu không khớp, dòng bên trái vẫn giữ lại với cột phải là NULL (đúng bản chất LEFT JOIN). Điều kiện ở `WHERE` được áp dụng **sau khi** đã join xong — nếu cột bên phải là NULL mà điều kiện WHERE yêu cầu so sánh giá trị cụ thể, dòng đó sẽ bị loại → vô tình biến LEFT JOIN thành INNER JOIN.

**Làm sao viết query "tìm các khách hàng chưa từng đặt đơn hàng nào"?** (dùng LEFT JOIN + IS NULL, hoặc NOT EXISTS)

```sql
SELECT c.name
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id
WHERE o.id IS NULL;
```

Hoặc dùng `NOT EXISTS` (an toàn hơn với NULL, hiệu năng thường tốt hơn với bảng lớn):

```sql
SELECT c.name FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);
```

**MySQL không có FULL JOIN, làm sao giả lập?** (gợi ý: `LEFT JOIN ... UNION LEFT JOIN` đảo bảng)

```sql
SELECT c.name, o.id FROM customers c LEFT JOIN orders o ON c.id = o.customer_id
UNION
SELECT c.name, o.id FROM customers c RIGHT JOIN orders o ON c.id = o.customer_id;
```

`UNION` (không phải `UNION ALL`) sẽ tự loại bỏ các dòng trùng lặp xuất hiện ở cả 2 vế.

**CROSS JOIN dùng để làm gì trong thực tế?** Cho 1 ví dụ nghiệp vụ.

Sinh tổ hợp toàn bộ giữa 2 tập dữ liệu. Ví dụ: sinh biến thể sản phẩm (màu × size), sinh bảng lịch làm việc (nhân viên × ngày trong tuần) để check lịch trống, hoặc sinh dữ liệu test

**Self JOIN là gì, khi nào dùng?** Cho ví dụ ngoài employee-manager (VD: tìm cặp sản phẩm cùng category).

Là kỹ thuật JOIN một bảng với chính nó để so sánh các dòng trong cùng bảng. Ví dụ: tìm các cặp sản phẩm cùng `category_id` nhưng khác `id` để gợi ý "sản phẩm tương tự":

```sql
SELECT p1.name, p2.name
FROM products p1
JOIN products p2 ON p1.category_id = p2.category_id AND p1.id < p2.id;
```

Với bộ dữ liệu `customers`/`orders` phía trên, viết query tính **tổng doanh thu (total) theo từng khách hàng**, kể cả khách chưa có đơn hàng nào (kết quả trả về 0 hoặc NULL cho Dung).

```sql
SELECT c.name, COALESCE(SUM(o.total), 0) AS total_revenue
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id
GROUP BY c.name;
```

**Giải thích "Cartesian product bug"** — vì sao nó nguy hiểm trong production, và cách phòng tránh khi review code JOIN.

> Khi JOIN 2 bảng mà quên điều kiện `ON` (hoặc điều kiện sai làm khớp quá nhiều dòng), SQL tự hiểu là CROSS JOIN — số dòng kết quả = số dòng bảng A × số dòng bảng B. Với bảng lớn (VD 10,000 × 10,000), kết quả bùng nổ thành 100 triệu dòng, gây treo query, hết bộ nhớ, hoặc số liệu báo cáo sai gấp nhiều lần (VD: doanh thu bị nhân đôi/nhân ba do join trùng). Cách phòng tránh: luôn kiểm tra kỹ điều kiện `ON`, review kỹ khi JOIN nhiều bảng, và test với dữ liệu có bản ghi trùng khóa để phát hiện sớm.
