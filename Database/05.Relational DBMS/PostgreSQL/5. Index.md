# Index Trong PostgreSQL

Index (chỉ mục) là một cơ chế tối ưu hóa giúp tăng tốc độ truy vấn dữ liệu trong PostgreSQL, đặc biệt hiệu quả khi làm việc với bảng có hàng triệu dòng. Index hoạt động như một "mục lục" giúp cơ sở dữ liệu tìm kiếm trực tiếp đến dữ liệu cần thiết thay vì quét toàn bộ bảng (full table scan).

## **1. Index Là Gì?**

- **Mô tả**: Index là một cấu trúc dữ liệu đặc biệt được tạo trên một hoặc nhiều cột của bảng, cho phép PostgreSQL truy vấn nhanh hơn bằng cách giảm số lượng dữ liệu cần kiểm tra.

- **Cách hoạt động**:
    - Không có index: PostgreSQL quét toàn bộ bảng từ đầu đến cuối (full scan), tốn thời gian với bảng lớn.
    - Có index: PostgreSQL sử dụng cấu trúc index (như cây B-tree) để tìm kiếm trực tiếp đến các dòng phù hợp.

- **Ứng dụng**:
    - Tăng tốc các truy vấn `SELECT` với điều kiện `WHERE`, `JOIN`, hoặc `ORDER BY`.
    - Hỗ trợ tìm kiếm trên các cột thường xuyên sử dụng, như khóa chính, khóa ngoại, hoặc cột lọc.

---
## **2. Các Loại Index Trong PostgreSQL**

PostgreSQL hỗ trợ nhiều loại index, mỗi loại phù hợp với các trường hợp sử dụng khác nhau:

|**Loại Index**|**Mô Tả**|**Ứng Dụng**|
|---|---|---|
|**B-tree**|Index mặc định, phù hợp cho hầu hết các truy vấn so sánh (`=`, `<`, `>`, v.v.).|Khóa chính, khóa ngoại, cột lọc thông thường.|
|**GIN**|Index cho dữ liệu phức tạp như mảng, JSON, hoặc tìm kiếm full-text.|Tìm kiếm văn bản, JSONB, mảng.|
|**GiST**|Index cho dữ liệu không gian (spatial) hoặc tìm kiếm phức tạp.|Dữ liệu GIS, tìm kiếm tương tự.|
|**BRIN**|Index cho bảng lớn với dữ liệu có thứ tự (như ngày tháng).|Bảng log, dữ liệu thời gian.|
|**Hash**|Index cho so sánh bằng (`=`), nhưng ít phổ biến hơn B-tree.|Truy vấn đơn giản với điều kiện `=`.|

---
## **3. Tạo và Quản Lý Index**

### **Tạo Index**

Tạo index trên một cột:
```sql
CREATE INDEX idx_user_email ON users(email);
```

Tạo index trên nhiều cột (multi-column index):
```sql
CREATE INDEX idx_user_name_age ON users(username, age);
```

- **Ứng dụng**: Hữu ích khi truy vấn thường xuyên sử dụng cả `username` và `age` trong `WHERE` hoặc `ORDER BY`.

Tạo unique index để đảm bảo giá trị không trùng lặp:
```sql
CREATE UNIQUE INDEX idx_user_email_unique ON users(email);
```

### **Xóa Index**

Xóa index khi không còn cần thiết:
```sql
DROP INDEX idx_user_email;
```

### **Kiểm Tra Index**

Xem danh sách các index trong cơ sở dữ liệu:
```sql
SELECT indexname, tablename, indexdef 
FROM pg_indexes 
WHERE schemaname = 'public';
```

- **Kết quả mẫu**:

|indexname|tablename|indexdef|
|---|---|---|
|idx_user_email|users|CREATE INDEX idx_user_email ON public.users USING btree (email)|
|idx_user_name_age|users|CREATE INDEX idx_user_name_age ON public.users USING btree (username, age)|


---
## **4. Kiểm Tra Hiệu Quả Index**

Sử dụng lệnh `EXPLAIN` để xem PostgreSQL có sử dụng index hay không:
```sql
EXPLAIN SELECT * FROM users WHERE email = 'giabao2025@gmail.com';
```

- **Kết quả mẫu** (khi có index):
```
Index Scan using idx_user_email on users  (cost=0.15..8.17 rows=1 width=72)
```

- **Giải thích**: "Index Scan" cho thấy PostgreSQL sử dụng index thay vì quét toàn bảng.

## **5. Ví Dụ Thực Tế**

### **Ví dụ 1: Tăng tốc truy vấn với index**

Giả sử bảng `orders` có hàng triệu dòng. Tạo index trên cột `uid` để tăng tốc truy vấn:
```sql
CREATE INDEX idx_order_uid ON orders(uid);
```

Truy vấn:
```sql
SELECT * FROM orders WHERE uid = 1;
```

- **Kết quả**: Index giúp tìm kiếm nhanh hơn, đặc biệt khi `uid` là khóa ngoại.

### **Ví dụ 2: Index cho tìm kiếm văn bản**

Tạo GIN index cho cột `username` để hỗ trợ tìm kiếm tương tự:
```sql
CREATE INDEX idx_user_username_gin ON users USING gin(username gin_trgm_ops);
```

Truy vấn:
```sql
SELECT * FROM users WHERE username ILIKE '%Bao%';
```

- **Yêu cầu**: Cần cài đặt extension `pg_trgm`:
```sql
CREATE EXTENSION pg_trgm;
```

### **Ví dụ 3: Index cho sắp xếp**

Tạo index trên cột `order_date` để tăng tốc sắp xếp:
```sql
CREATE INDEX idx_order_date ON orders(order_date DESC);
```

Truy vấn:
```sql
SELECT * FROM orders ORDER BY order_date DESC LIMIT 10;
```

## **6. Lưu Ý Khi Sử Dụng Index**

- **Ưu điểm**:
    - Tăng tốc độ truy vấn `SELECT`, `JOIN`, `WHERE`, và `ORDER BY`.
    - Hiệu quả cao với bảng lớn hoặc truy vấn thường xuyên trên cột cụ thể.

- **Nhược điểm**:
    - Tăng dung lượng lưu trữ do index chiếm không gian.
    - Làm chậm các thao tác ghi (`INSERT`, `UPDATE`, `DELETE`) vì phải cập nhật index.
    - Quá nhiều index có thể làm giảm hiệu suất tổng thể.

- **Khi nên tạo index**:
    - Trên các cột thường xuyên xuất hiện trong `WHERE`, `JOIN`, hoặc `ORDER BY`.
    - Trên khóa chính, khóa ngoại, hoặc cột tìm kiếm thường xuyên.

- **Khi không nên tạo index**:
    - Trên bảng nhỏ (ít dòng) vì full scan đã đủ nhanh.
    - Trên cột hiếm khi được truy vấn hoặc có giá trị lặp lại nhiều (như cột `gender` với chỉ hai giá trị `M`/`F`).

- **Quản lý index**:
    - Theo dõi hiệu suất bằng `EXPLAIN` hoặc `EXPLAIN ANALYZE`.
    - Xóa index không cần thiết để tiết kiệm không gian và tăng tốc ghi.
    - Sử dụng `REINDEX` để tái tạo index nếu bị phân mảnh:
    
    ```sql
    REINDEX INDEX idx_user_email;
    ```
