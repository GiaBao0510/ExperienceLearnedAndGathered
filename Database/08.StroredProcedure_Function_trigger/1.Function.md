## **Function (hàm)** 

Là một đối tượng trong cơ sở dữ liệu (CSDL) sử dụng trong các câu lệnh SQL, được biên dịch sẵn và lưu trong CSDL nhằm mục đích thực hiện xử lý nào đó như tính toán phức tạp và trả về kết quả là giá trị nào đó.

#### **Đặc điểm chính**
- Gồm 2 loại: Function hệ thống và Function do người dùng tự định nghĩa
- Nhận tham số: Có thể nhận hoặc không nhận các giá trị đầu vào để xử lý.
- Luôn trả về kết quả: Bắt buộc phải có câu lệnh trả về giá trị (`RETURN`).
- Sử dụng trong câu lệnh: Có thể gọi trực tiếp bên trong các câu lệnh `SELECT`, `WHERE` hoặc `ORDER BY`
- Không tự quản lý được Transaction riêng — nghĩa là bên trong Function, bạn không thể gọi lệnh `COMMIT` hay `ROLLBACK`. Function luôn chạy "ăn theo" transaction của câu lệnh đã gọi nó.

---
### **Tại sao Function lại có giới hạn "không tự COMMIT được"?**

. Vì Function được thiết kế để nhúng vào giữa 1 câu truy vấn (giống như bạn nhúng `SUM`() vào `SELECT`), nó có thể xuất hiện nhiều lần cùng lúc trong 1 câu `SELECT` phức tạp. Nếu cho phép `Function` tự `COMMIT` giữa chừng, dữ liệu mà câu truy vấn đang "nhìn thấy" (snapshot dữ liệu, liên hệ Isolation Level bạn đã học ở Phần 7) sẽ bị thay đổi giữa chừng một cách không kiểm soát được — phá vỡ tính đúng đắn của toàn bộ câu truy vấn. Vì vậy, Postgres cấm hẳn khả năng này ở Function.

### **Khi nào nên dùng Function?**

Khi bạn cần 1 phép tính toán hoặc truy xuất dữ liệu có trả về kết quả, muốn tái sử dụng logic đó ở nhiều nơi, và không cần tự quản lý transaction riêng. Ví dụ: tính giá sau giảm giá, tra cứu số dư tài khoản, kiểm tra 1 điều kiện phức tạp trả về đúng/sai.

---
#### **Cú pháp**
Để tạo một function trong postgreSQL, ta sử dụng cú pháp như dưới đây:
```sql
CREATE [OR REPLACE] FUNCTION ten_ham (tham_so_1 kieu_du_lieu, tham_so_2 kieu_du_lieu)
RETURNS kieu_du_lieu_tra_ve
AS $$
BEGIN
    -- Khối lệnh thực thi
    RETURN gia_tri_tra_ve;
END;
$$ LANGUAGE plpgsql;
```
Giải nghĩa từng từ khóa:

- `CREATE OR REPLACE FUNCTION`: tạo mới hàm, hoặc ghi đè nếu hàm cùng tên đã tồn tại — dùng OR REPLACE để khi sửa hàm không cần DROP trước.
- `RETURNS`: khai báo kiểu dữ liệu mà hàm chắc chắn sẽ trả về. Đây là phần bắt buộc phải có với Function (khác Procedure).
- `$$ ... $$`: gọi là "dollar-quoting" — dùng để đánh dấu điểm bắt đầu/kết thúc phần thân của hàm, tránh việc phải escape dấu nháy đơn (') liên tục khi viết code SQL lồng bên trong.
- `DECLARE`: phần khai báo biến cục bộ sẽ dùng trong hàm (tương tự khai báo biến trong bất kỳ ngôn ngữ lập trình nào).
- `BEGIN ... END`: đánh dấu khối logic chính của hàm.
- `LANGUAGE plpgsql`: khai báo hàm này viết bằng ngôn ngữ PL/pgSQL (ngôn ngữ thủ tục mặc định của Postgres).


***Ví dụ 1***: Function đơn giản — trả về 1 giá trị (scalar)
```sql
CREATE OR REPLACE FUNCTION get_balance(p_account_id INT)
RETURNS NUMERIC AS $$
DECLARE
    v_balance NUMERIC;
BEGIN
    SELECT balance INTO v_balance
    FROM accounts
    WHERE id = p_account_id;

    RETURN v_balance;
END;
$$ LANGUAGE plpgsql;
```

Cách gọi:
```sql
select get_balance(2);
```

*output:* 

| get_balance |
| ----------- |
| 800000.00   |

Giải thích cú pháp:

- `CREATE OR REPLACE FUNCTION`: tạo mới, hoặc ghi đè nếu đã tồn tại (tránh phải `DROP` trước khi sửa).
- `p_account_id` INT: tham số đầu vào (convention: tiền tố p_ cho parameter).
- `RETURNS NUMERIC`: khai báo kiểu dữ liệu trả về.
- `$$ ... $$`: dấu phân cách thân hàm (dollar-quoting) — tránh phải escape dấu nháy đơn liên tục bên trong.
- `DECLARE`: khai báo biến cục bộ (convention: tiền tố v_ cho variable).
- `LANGUAGE` plpgsql: ngôn ngữ viết function — PL/pgSQL là ngôn ngữ thủ tục mặc định của Postgres (tương tự PL/SQL của Oracle).

***Ví dụ 2:*** Tham số input/output
```sql
-- Tham số IN (mặc định), OUT (giá trị trả ra), INOUT (vừa nhận vừa trả)
CREATE OR REPLACE FUNCTION calculate_discount(
    p_price IN NUMERIC,
    p_discount_percent IN NUMERIC,
    p_final_price OUT NUMERIC,
    p_saved_amount OUT NUMERIC
) AS $$
BEGIN
    p_saved_amount := p_price * p_discount_percent / 100;
    p_final_price  := p_price - p_saved_amount;
END;
$$ LANGUAGE plpgsql;
```

Cách gọi (với OUT parameter, kết quả trả về dạng nhiều cột):
```sql
SELECT * FROM calculate_discount(1000000, 15);
```

*Output:*

| p_final_price             | p_saved_amount      |
| ------------------------- | ------------------- |
| 150000000000.000000000000 | 150000.000000000000 |

***Ví dụ 3:*** Function trả về nhiều dòng (Table-returning Function)

```sql
CREATE OR REPLACE FUNCTION get_low_balance_accounts(p_threshold NUMERIC)
RETURNS TABLE (account_id INT, owner_name VARCHAR, current_balance NUMERIC) AS $$
BEGIN
    RETURN QUERY
    SELECT id, owner, balance
    FROM accounts
    WHERE balance < p_threshold;
END;
$$ LANGUAGE plpgsql;
```

```sql
SELECT * FROM get_low_balance_accounts(600000);
```

***Output:***

| account_id | owner_name | current_balance |
| ---------- | ---------- | --------------- |
| 1          | An         | 100000.00       |

**Ví dụ 4:** Function phức tạp cho nghiệp vụ — chuyển tiền, có xử lý lỗi
```sql
CREATE OR REPLACE FUNCTION transfer_money(
    p_from_id INT,
    p_to_id INT,
    p_amount NUMERIC
) RETURNS BOOLEAN AS $$
DECLARE
    v_from_balance NUMERIC;
BEGIN
    -- Kiểm tra số dư trước khi thực hiện
    SELECT balance INTO v_from_balance FROM accounts WHERE id = p_from_id;

    IF v_from_balance IS NULL THEN
        RAISE EXCEPTION 'Tài khoản nguồn không tồn tại: %', p_from_id;
    END IF;

    IF v_from_balance < p_amount THEN
        RAISE EXCEPTION 'Số dư không đủ. Hiện có: %, cần: %', v_from_balance, p_amount;
    END IF;

    UPDATE accounts SET balance = balance - p_amount WHERE id = p_from_id;
    UPDATE accounts SET balance = balance + p_amount WHERE id = p_to_id;

    RETURN TRUE;
END;
$$ LANGUAGE plpgsql;
```

Thử nghiệm:
```sql
select transfer_money(2,1,200000);
```

***Output:***

| transfer_money |
| -------------- |
| true           |

```sql
SELECT transfer_money(1, 2, 99999999);
```

***Output:***
```shell
Failed to run sql query: ERROR:  P0001: Số dư không đủ. Hiện có: 300000.00 cần 99999999d
CONTEXT:  PL/pgSQL function transfer_money(integer,integer,numeric) line 13 at RAISE
```

> Lưu ý quan trọng: cả 2 câu UPDATE bên trong function chạy trong cùng 1 transaction với câu gọi function (do Function không tự COMMIT được — đúng như bảng so sánh ở mục 9.1). Nếu function raise exception giữa chừng, toàn bộ thay đổi trước đó trong cùng transaction cũng tự động rollback — đây chính là tính Atomicity bạn đã học ở Phần 7.

---
### **Ưu/ nhược điểm**
**Ưu điểm**
- Tái sử dụng logic tính toán ở nhiều câu query khác nhau, không cần lặp lại code SQL phức tạp nhiều lần.
- Nhúng được vào `SELECT`, `WHERE`, giúp query gọn gàng, dễ đọc hơn.
- Giảm số lần round-trip giữa ứng dụng và DB nếu 1 nghiệp vụ cần nhiều bước tính toán.

**Nhược điểm**
- Không thể tự `COMMIT`/`ROLLBACK` — không phù hợp cho các tác vụ cần xử lý theo từng đợt lớn (batch) mà cần chia nhỏ transaction.
- Logic nằm trong DB, khó test độc lập như code ứng dụng thông thường, khó version control chung với codebase chính.
- Nếu viết cẩu thả (không khai báo đúng thuộc tính tối ưu — sẽ học ở mục 9.2.9), có thể làm chậm query nghiêm trọng mà không dễ nhận ra.
