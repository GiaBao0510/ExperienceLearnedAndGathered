## **Trigger**

**Định nghĩa:** Trigger là 1 đoạn code (thực chất gọi 1 Function đặc biệt gọi là Trigger Function) được tự động kích hoạt khi có 1 sự kiện xảy ra trên bảng — INSERT, UPDATE, DELETE (hoặc TRUNCATE).

![](https://topdev.vn/blog/wp-content/uploads/2019/09/trigger-trong-sql.png)

### **Đặc điểm chính của Trigger**
- **Tự động chạy:** Không cần gọi thủ công.
- **Gắn với bảng:** Hoạt động dựa trên các thao tác thay đổi dữ liệu (DML).
- **Thời điểm kích hoạt:** Chạy trước (BEFORE) hoặc sau (AFTER) sự kiện.

### **Công dụng thường gặp**
- **Đảm bảo toàn vẹn dữ liệu:** Kiểm tra các quy tắc phức tạp mà ràng buộc thông thường không làm được.
- **Ghi log lịch sử:** Tự động lưu vết lại các thao tác sửa/xóa dữ liệu.
- **Đồng bộ bảng phụ:** Tự động cập nhật dữ liệu liên quan sang các bảng khác

### **Trigger được sử dụng khi nào?**
- Trigger thường được sử dụng để kiểm tra ràng buộc (check constraints) trên nhiều quan hệ (nhiều bảng/table) hoặc trên nhiều dòng (nhiều record) của bảng.
- Ngoài ra việc sử dụng Trigger để chương trình có những hàm chạy ngầm nhằm phục vụ nhưng trường hợp hữu hạn và thường không sử dụng cho mục đích kinh doanh hoặc giao dịch.
- Ngăn chặn việc xóa những dữ liệu quan trọng. (có thể dùng back up các dữ liệu quan trọng sang table khác phòng khi …bị xóa ngoài ý muốn).

Mỗi table thường sẽ có 3 thao tác làm thay đổi dữ liệu đó là: UPDATE, INSERT, DELETE. Và đôi khi mỗi hành động như vậy ta sẽ có những ràng buộc trên bảng để giúp bảo toàn dữ liệu, lúc này sử dụng trigger là một giải pháp tốt.

**Cú pháp Tạo hàm cho Trigger (Trigger Function):**
```sql
CREATE OR REPLACE FUNCTION ten_ham()
RETURNS TRIGGER AS $$
BEGIN
    -- Nội dung xử lý logic (dùng NEW hoặc OLD)
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

**Cú pháp Tạo Trigger (Create Trigger)**
```sql
CREATE TRIGGER ten_trigger
[BEFORE | AFTER | INSTEAD OF] [INSERT | UPDATE | DELETE | TRUNCATE]
ON ten_bang
[FOR EACH ROW | FOR EACH STATEMENT]
EXECUTE FUNCTION ten_ham();
```

Bước 1 — Viết Trigger Function (function đặc biệt, RETURNS TRIGGER, không nhận tham số thông thường mà dùng biến ngầm định NEW/OLD):
```sql
CREATE OR REPLACE FUNCTION fn_log_balance_change()
RETURNS TRIGGER AS $$
BEGIN
    INSERT INTO audit_log (table_name, action, detail)
    VALUES (
        'accounts',
        TG_OP,   -- biến ngầm định: loại thao tác đang xảy ra ('INSERT'/'UPDATE'/'DELETE')
        format('Account %s: balance %s -> %s', OLD.id, OLD.balance, NEW.balance)
    );
    RETURN NEW;  -- bắt buộc với AFTER trigger, trả về NEW để thao tác tiếp tục diễn ra bình thường
END;
$$ LANGUAGE plpgsql;
```

**Bước 2 — Gắn Trigger vào bảng, chỉ định thời điểm kích hoạt:**
```sql
CREATE TRIGGER trg_accounts_balance_update
AFTER UPDATE ON accounts
FOR EACH ROW
WHEN (OLD.balance IS DISTINCT FROM NEW.balance)  -- chỉ chạy khi balance THỰC SỰ thay đổi
EXECUTE FUNCTION fn_log_balance_change();
```

Kiểm tra:
```sql
update accounts set balance = balance + 150000 where id = 1;

select * from audit_log;
```

***Output:***

| id | table_name | action | detail                                     | created_at                 |
| -- | ---------- | ------ | ------------------------------------------ | -------------------------- |
| 1  | accounts   | UPDATE | Account 1: balance 808000.00 -> 908000.00  | 2026-07-25 08:32:38.144919 |
| 2  | accounts   | UPDATE | Account 1: balance 908000.00 -> 1058000.00 | 2026-07-25 08:33:02.216386 |

Giải thích OLD và NEW — 2 biến ngầm định quan trọng nhất

|Loại thao tác|	OLD (dữ liệu trước khi đổi)|	NEW (dữ liệu sau khi đổi)|
|---|---|---|
|INSERT|	không có (NULL)|	có — dòng vừa được thêm|
|UPDATE|	có — dòng trước khi sửa|	có — dòng sau khi sửa|
|DELETE|	có — dòng trước khi xóa	không |có (NULL)|


**BEFORE vs AFTER — khác biệt cực kỳ quan trọng**
```sql
-- BEFORE: chạy TRƯỚC khi thao tác thực sự xảy ra, có thể CHẶN hoặc SỬA dữ liệu trước khi lưu
CREATE OR REPLACE FUNCTION fn_prevent_negative_balance()
RETURNS TRIGGER AS $$
BEGIN
    IF NEW.balance < 0 THEN
        RAISE EXCEPTION 'Số dư không được âm: %', NEW.balance;
    END IF;
    RETURN NEW;  -- cho phép thao tác tiếp tục với dữ liệu (có thể đã bị sửa) trong NEW
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_accounts_before_update
BEFORE UPDATE ON accounts
FOR EACH ROW
EXECUTE FUNCTION fn_prevent_negative_balance();
```

```sql
UPDATE accounts SET balance = -999999999 WHERE id = 1;
```

Output:
```shell
Failed to run sql query: ERROR:  P0001: Số dư không được âm: -999999999.00
CONTEXT:  PL/pgSQL function fn_prevent_negative_balance() line 4 at RAISE
```

**So sánh trực quan:**
|	|BEFORE|	AFTER|
|Thời điểm	|Trước khi ghi vào bảng	|Sau khi đã ghi vào bảng|
|Có thể sửa dữ liệu (NEW.col := ...)|	✅ Có	|❌ Không (dữ liệu đã ghi rồi)|
|Có thể chặn thao tác (RAISE EXCEPTION)|	✅ Có, hiệu quả nhất	|✅ Có, nhưng thao tác đã ghi rồi mới bị rollback (tốn tài nguyên hơn)|
|Use case điển hình	|Validate dữ liệu, tự động tính toán/chuẩn hóa giá trị trước khi lưu|	Ghi log, đồng bộ dữ liệu sang bảng khác, gửi thông báo|

## **Q&A**


**Trigger trong PostgreSQL là gì?**
Trigger là một function được tự động gọi trước hoặc sau khi một sự kiện (như INSERT, UPDATE, DELETE) xảy ra trên một table.

3. OLD và NEW trong Trigger là gì? Chúng khác nhau thế nào tùy loại thao tác (INSERT/UPDATE/DELETE)?

OLD đại diện cho giá trị dòng dữ liệu trước khi thay đổi, NEW đại diện cho giá trị sau khi thay đổi. Với INSERT, chỉ có NEW (không có OLD vì dòng chưa tồn tại trước đó). Với DELETE, chỉ có OLD (không có NEW vì dòng sẽ không còn tồn tại). Với UPDATE, có cả OLD và NEW để so sánh giá trị trước/sau.

4. BEFORE Trigger và AFTER Trigger khác nhau thế nào? Khi nào nên dùng loại nào?

BEFORE Trigger chạy trước khi dữ liệu được ghi vào bảng, có thể sửa đổi giá trị (NEW.col := ...) trước khi lưu, hoặc chặn hoàn toàn thao tác bằng RAISE EXCEPTION một cách hiệu quả (chưa ghi gì cả). AFTER Trigger chạy sau khi dữ liệu đã ghi xong, không thể sửa dữ liệu nữa, thường dùng để ghi log, đồng bộ sang bảng khác, hoặc gửi thông báo. Nên dùng BEFORE cho việc validate/chuẩn hóa dữ liệu, dùng AFTER cho các hành động phụ trợ không ảnh hưởng đến chính dòng dữ liệu đó.
