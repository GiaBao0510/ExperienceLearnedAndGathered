**Stored procedure (thủ tục lưu trữ)** là một tập hợp các câu lệnh SQL được biên dịch sẵn và lưu trữ trực tiếp trong cơ sở dữ liệu. Nó giúp tái sử dụng mã nguồn, tăng tốc độ xử lý và nâng cao tính bảo mật

---
### **Vì sao SQL cần "phần thủ tục" (Procedural Extension)?**

**Vấn đề gốc rễ:** SQL nguyên bản là ngôn ngữ khai báo (declarative) — bạn mô tả "muốn gì" (VD: SELECT dữ liệu thỏa điều kiện X), còn DB tự quyết định "làm thế nào" (execution plan). SQL thuần không có các cấu trúc lập trình thủ tục: không có biến, không có vòng lặp, không có rẽ nhánh điều kiện phức tạp, không xử lý được lỗi theo từng bước.

Nhưng nhiều bài toán nghiệp vụ cần tư duy thủ tục (procedural/imperative) — ví dụ: "nếu số dư đủ THÌ trừ tiền, NẾU KHÔNG thì báo lỗi", hoặc "lặp qua từng dòng và xử lý tuần tự". Đây chính là lý do các RDBMS phát triển thêm ngôn ngữ thủ tục mở rộng nằm ngay bên trong DB — với Postgres là PL/pgSQL (Procedural Language/PostgreSQL SQL), tương tự PL/SQL của Oracle hay T-SQL của SQL Server.

**Bản chất:** Function/Procedure không phải là "tính năng SQL", mà là 1 ngôn ngữ lập trình hoàn chỉnh khác (có biến, vòng lặp, if/else, exception handling) được nhúng và thực thi bên trong DB engine, có thể gọi SQL thuần từ bên trong nó.

---
#### **Lợi ích chính**
- **Tốc độ nhanh:** Mã SQL được biên dịch sẵn nên chạy nhanh hơn các câu lệnh riêng lẻ gửi từ ứng dụng.
- **Tái sử dụng:** Giúp viết một lần và gọi lại nhiều lần từ các ứng dụng khác nhau.
- **Bảo mật tốt:** Hạn chế lỗi tấn công tiêm nhiễm mã độc (SQL Injection) và quản lý quyền truy cập dữ liệu dễ dàng hơn

#### **Nhược điểm cần lưu ý**
- **Phụ thuộc hệ thống:** Mỗi hệ quản trị cơ sở dữ liệu có cú pháp riêng (như SQL Server, MySQL, Oracle), khó chuyển đổi qua lại.
- **Khó gỡ lỗi:** Việc kiểm tra lỗi bên trong thủ tục phức tạp hơn so với code ở ứng dụng thông thường

### **Cú pháp tạo Stored Procedure**
```sql
CREATE [ OR REPLACE ] PROCEDURE ten_procedure (
    [ argmode argname argtype [ = default_expr ] [, ...] ]
)
LANGUAGE lang_name
AS $$
DECLARE
    -- Khai báo biến (nếu có)
BEGIN
    -- Khối lệnh SQL hoặc PL/pgSQL
    -- Có thể dùng COMMIT hoặc ROLLBACK ở đây
END;
$$;
```

Các thành phần chính
- CREATE OR REPLACE PROCEDURE: Tạo mới hoặc ghi đè nếu thủ tục đã tồn tại.
- argmode: Kiểu tham số gồm IN (đầu vào), OUT (đầu ra), hoặc INOUT (vừa vào vừa ra).
- LANGUAGE: Ngôn ngữ lập trình bên trong, thường dùng plpgsql hoặc sql.
- $$: Cặp ký tự giới hạn phần thân hàm (dollar-quoted string)

**Ví dụ cơ bản**
```sql
CREATE OR REPLACE PROCEDURE deposit_money(p_account_id INT, p_amount NUMERIC)
AS $$
BEGIN
    UPDATE accounts SET balance = balance + p_amount WHERE id = p_account_id;
    RAISE NOTICE 'Đã nạp % vào tài khoản %', p_amount, p_account_id;
END;
$$ LANGUAGE plpgsql;
```

Cách gọi (dùng `CALL`, không phải `SELECT`):
```sql
call deposit_money(1, 500000);
```

***Ví dụ 2:*** Procedure với khả năng tự `COMMIT` — điểm khác biệt cốt lõi so với Function
```sql
CREATE OR REPLACE PROCEDURE bulk_update_balance()
AS $$
DECLARE
    v_id INT;
BEGIN
    FOR v_id IN SELECT id FROM accounts LOOP
        UPDATE accounts SET balance = balance * 1.01 WHERE id = v_id;  -- cộng lãi 1%

        -- Procedure có thể tự COMMIT ngay giữa vòng lặp — Function KHÔNG làm được điều này
        COMMIT;
    END LOOP;
END;
$$ LANGUAGE plpgsql;
```

```sql
CALL bulk_update_balance();
```

> Ứng dụng thực tế: xử lý hàng loạt (batch processing) dữ liệu lớn — VD: cập nhật hàng triệu dòng, nếu gộp vào 1 transaction duy nhất sẽ giữ lock quá lâu, tốn bộ nhớ. Procedure cho phép COMMIT theo từng batch nhỏ (VD: mỗi 1000 dòng), giảm áp lực lên hệ thống.

### **Phân biệt Function và Stored Procedure**

|Tiêu chí|Function|Stored Procedure|
|---|---|---|
|Giá trị trả về|	Bắt buộc trả về giá trị (RETURNS)|Không bắt buộc — có thể không trả gì|
|Gọi bằng|SELECT function_name(...)|CALL procedure_name(...)|
|Dùng trong câu SELECT|✅ Có thể nhúng trực tiếp (SELECT col, my_func(col) FROM table)|❌ Không thể|
|Quản lý Transaction|❌ Không thể tự COMMIT/ROLLBACK bên trong (chạy trong transaction của câu gọi nó)|✅ Có thể tự COMMIT/ROLLBACK bên trong (từ Postgres 11+)|
|Xuất hiện từ|Có từ rất sớm|Chỉ chính thức có từ PostgreSQL 11 (2018) — trước đó Postgres chỉ có Function|

## **Q&A**

**1. Phân biệt Function và Stored Procedure trong PostgreSQL.**
Function bắt buộc phải trả về giá trị (RETURNS), gọi bằng SELECT, có thể nhúng trực tiếp trong câu SELECT khác, nhưng không thể tự COMMIT/ROLLBACK bên trong (chạy trong transaction của câu gọi nó). Stored Procedure không bắt buộc trả về giá trị, gọi bằng CALL, và có thể tự COMMIT/ROLLBACK bên trong thân của nó — tính năng này chỉ chính thức có từ PostgreSQL 11.

**2. Vì sao cần Stored Procedure nếu PostgreSQL đã có Function từ trước?**
Vì Function không thể tự COMMIT giữa chừng — mọi thao tác bên trong luôn nằm trong 1 transaction duy nhất với câu lệnh gọi nó. Với các tác vụ xử lý hàng loạt dữ liệu lớn (batch processing), việc giữ 1 transaction quá dài sẽ tốn tài nguyên, giữ lock lâu, dễ gây deadlock. Stored Procedure giải quyết vấn đề này bằng cách cho phép COMMIT theo từng phần nhỏ ngay trong thân procedure.

**3. Vì sao đặt logic này ngay trong DB thay vì ở tầng ứng dụng (Go/Java/...)**

|Ưu điểm đặt logic trong DB	|Nhược điểm đặt logic trong DB|
|---|---|
|Giảm số lần round-trip mạng giữa app và DB (xử lý nhiều bước trong 1 lần gọi)	|Logic nghiệp vụ bị tách rời khỏi codebase chính, khó version control, khó code review như code Go bình thường|
|Đảm bảo tính nhất quán bất kể client nào thao tác (API, script admin, BI tool) đều tuân theo cùng 1 quy tắc|	Khó test unit test như hàm Go thông thường, cần môi trường DB thật để test|
|Tận dụng được tối ưu hóa nội bộ của DB, giảm dữ liệu truyền qua lại|	Gắn chặt (vendor lock-in) vào 1 loại DBMS cụ thể — khó migrate sang DB khác|
|Phù hợp cho ràng buộc toàn vẹn dữ liệu ở mức thấp nhất (Trigger đảm bảo dù ai thao tác cũng không phá vỡ quy tắc)|	Khó scale ngang (horizontal scale) logic nghiệp vụ như tầng ứng dụng (stateless service)|

**4. Stored procedure trong PostgreSQL là gì?**

Stored procedure là một tập hợp các câu lệnh SQL có thể được thực thi trên server cơ sở dữ liệu. Nó cho phép tái sử dụng mã và thực hiện các hoạt động phức tạp.
