**Định nghĩa**

SQL Injection là 1 dạng tấn công, trong đó kẻ tấn công chèn (inject) đoạn mã SQL độc hại vào dữ liệu đầu vào của ứng dụng (VD: ô tìm kiếm, form đăng nhập, tham số URL), khiến câu lệnh SQL cuối cùng được thực thi trên Database khác hoàn toàn với ý định ban đầu của lập trình viên.

Nguyên nhân gốc rễ: xảy ra khi ứng dụng nối chuỗi (string concatenation) dữ liệu người dùng nhập vào trực tiếp thành câu lệnh SQL, mà không qua bước xử lý/validate an toàn.

---
### **Các hình thức và cách hoạt động phổ biến**
- Chèn mã qua ô đăng nhập: Kẻ xấu nhập ký tự đặc biệt như dấu nháy đơn ' hoặc lệnh OR 1=1 vào ô tên người dùng để ép hệ thống hiểu sai câu lệnh.
- Bỏ qua mật khẩu: Ký tự chú thích -- trong SQL làm phần kiểm tra mật khẩu phía sau vô tác dụng, giúp truy cập thẳng vào tài khoản quản trị.
- Đọc dữ liệu qua lỗi (Error-based): Buộc máy chủ bật thông báo lỗi chứa tên bảng hoặc cột dữ liệu bí mật.
- Lấy dữ liệu qua toán tử UNION: Nối thêm bảng dữ liệu khác vào kết quả hiển thị trên trang web

---
### **Tác hại nguy hiểm**
- **Lộ dữ liệu nhạy cảm:** Mất cắp thông tin cá nhân, tài khoản, thẻ ngân hàng của người dùng.
- **Mất quyền kiểm soát hệ thống:** Kẻ xấu có thể xóa toàn bộ dữ liệu hoặc điều khiển máy chủ.
- **Giả mạo người dùng:** Đăng nhập thành công vào tài khoản của người khác mà không cần biết mật khẩu.

**Ví dụ minh họa cách tấn công xảy ra**

Giả sử ứng dụng có chức năng đăng nhập, code (giả lập bằng pseudo-code, không phải Go thật) viết theo cách KHÔNG an toàn:

```txt
query = "SELECT * FROM users WHERE username = '" + input_username + "' AND password = '" + input_password + "'"
```

Trường hợp bình thường, nếu người dùng nhập `username` = an, `password` = 123456, câu lệnh sinh ra là:
```sql
SELECT * FROM users WHERE username = 'an' AND password = '123456';
```

Hoạt động đúng như dự kiến — kiểm tra tồn tại user có username và password khớp.

**Trường hợp bị tấn công**, kẻ tấn công nhập vào ô `username`:
```
' OR'1'='1
```

Câu lệnh SQL cuối cùng được ghép thành:

```sql
SELECT * FROM users WHERE username = '' OR '1'='1' AND password = '';
```

**Giải thích vì sao đây là lỗ hổng nghiêm trọng:** biểu thức `'1'='1'` **luôn luôn đúng** (TRUE) với mọi dòng dữ liệu. Do đó, điều kiện WHERE gần như luôn trả về TRUE cho mọi dòng trong bảng users — kẻ tấn công đăng nhập thành công mà không cần biết bất kỳ mật khẩu thật nào, đơn giản vì đã "tiêm" thêm logic khiến điều kiện xác thực trở nên vô nghĩa.

## **Các dạng tấn công SQL Injection khác — không chỉ dừng ở đăng nhập**

**a) Injection để đánh cắp dữ liệu qua UNION:**

Giả sử trang web có chức năng tìm sản phẩm theo tên, code không an toàn:
```txt
query = "SELECT name, price FROM products WHERE name LIKE '%" + input + "%'"
```

Nếu kẻ tấn công nhập vào ô tìm kiếm:
```txt
' UNION SELECT username, password FROM users --
```

Câu lệnh SQL trở thành:
```sql
SELECT name, price FROM products WHERE name LIKE '%' UNION SELECT username, password FROM users --%'
```

**Giải thích:** `UNION SELECT` (đã học ở Phần 5) ghép thêm 1 tập kết quả hoàn toàn khác (dữ liệu từ bảng `users`) vào kết quả tìm kiếm sản phẩm — nếu trang web hiển thị kết quả tìm kiếm ra màn hình, kẻ tấn công nhìn thấy trực tiếp username/password của người dùng khác. Ký hiệu -- là comment trong SQL, dùng để "vô hiệu hóa" phần còn lại của câu lệnh gốc (dấu `%'` thừa phía sau), tránh gây lỗi cú pháp.

**b) Injection để phá hoại dữ liệu:**

```txt
' ; DROP TABLE users; --
```

Nếu hệ thống cho phép chạy nhiều câu lệnh nối tiếp (multiple statements — 1 số driver kết nối DB cho phép điều này theo mặc định), câu lệnh trở thành:

```sql
SELECT ... WHERE name LIKE '%'; DROP TABLE users; --%'
```

→ Toàn bộ bảng users bị xóa vĩnh viễn. Đây là lý do vì sao ví von "Bobby Tables" (từ truyện tranh nổi tiếng xkcd) trở thành biểu tượng kinh điển khi nói về SQL Injection trong ngành.

## **Cách phòng chống SQL Injection — Prepared Statement / Parameterized Query**

**Định nghĩa:** Là kỹ thuật gửi câu lệnh SQL và dữ liệu đầu vào tách biệt hoàn toàn đến Database, thay vì nối chuỗi chúng lại với nhau trước khi gửi. Database sẽ luôn coi dữ liệu đầu vào là giá trị (data), không bao giờ coi là code (SQL syntax) — dù dữ liệu đó chứa ký tự đặc biệt như dấu nháy đơn hay từ khóa SQL.

Cách viết đúng (dùng dấu $1, $2... làm placeholder trong Postgres):

```sql
-- Đây là câu lệnh mẫu (prepared statement), $1 và $2 là chỗ trống sẽ được điền giá trị sau
SELECT * FROM users WHERE username = $1 AND password = $2;
```
