#### 1.1.Cấu trúc chuẩn của câu SELECT

Thứ tự **viết** khác thứ tự **thực thi** — đây là điểm hay bị hỏi phỏng vấn:

```sql
-- Thứ tự viết
SELECT col1, col2
FROM table_name
WHERE condition
GROUP BY COLUMN
HAVING group_condition
ORDER BY COLUMN
LIMIT n;

 -- Thứ tự thực thi (logical execution order)
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
```

**Tại sao thứ tự quan trọng?** Vì bạn không thể dùng alias đặt trong `SELECT` ở mệnh đề `WHERE` (vì WHERE chạy trước SELECT), nhưng lại dùng được ở `ORDER BY` (vì ORDER BY chạy sau SELECT).

Ví dụ với bảng `products` (e-commerce):

```sql
CREATE TABLE products (
    id          SERIAL PRIMARY KEY,
    name        VARCHAR(255) NOT NULL,
    price       NUMERIC(10,2),
    stock_qty   INT,
    category_id INT,
    created_at  TIMESTAMP DEFAULT now()
);
```

```sql
-- Alias KHÔNG dùng được trong WHERE
SELECT price * 0.9 AS discounted_price
FROM products
WHERE discounted_price < 100;  -- ❌ Lỗi: column "discounted_price" does not exist

-- Nhưng dùng được trong ORDER BY
SELECT price * 0.9 AS discounted_price
FROM products
ORDER BY discounted_price;     -- ✅ OK
```

#### 1.2. WHERE — các toán tử lọc

```sql
-- So sánh cơ bản
SELECT * FROM products WHERE price > 50;

-- IN: kiểm tra trong tập giá trị
SELECT * FROM products WHERE category_id IN (1, 2, 5);

-- BETWEEN: khoảng giá trị (bao gồm cả 2 đầu)
SELECT * FROM products WHERE price BETWEEN 100 AND 500;

-- LIKE: khớp mẫu chuỗi
-- % : bất kỳ chuỗi ký tự nào (kể cả rỗng)
-- _ : đúng 1 ký tự
SELECT * FROM products WHERE name LIKE 'iPhone%';   -- bắt đầu bằng "iPhone"
SELECT * FROM products WHERE name LIKE '%Pro%';     -- chứa "Pro"
SELECT * FROM products WHERE name ILIKE '%pro%';    -- không phân biệt hoa/thường (Postgres riêng)

-- IS NULL / IS NOT NULL
-- Lưu ý: KHÔNG dùng "= NULL" vì NULL không so sánh bằng được với bất kỳ giá trị nào (kể cả NULL)
SELECT * FROM products WHERE category_id IS NULL;
```

⚠️ **Bẫy phỏng vấn hay gặp:** `NOT IN` với danh sách chứa `NULL` sẽ trả về **rỗng** (không có dòng nào), vì so sánh với NULL luôn ra `UNKNOWN`. Đây là lỗi rất phổ biến khi dev viết subquery.

```sql
-- Nếu category_id có giá trị NULL trong bảng con, kết quả sẽ SAI (trả về rỗng)
SELECT * FROM products
WHERE category_id NOT IN (SELECT category_id FROM categories WHERE is_active = true );

-- Cách fix an toàn: dùng NOT EXISTS thay vì NOT IN
SELECT * FROM products p 
WHERE NOT EXISTS (
    SELECT 1 FROM categories c
    WHERE c.id = p.category_id AND c.is_active = false
); 
```

#### **1.3. DISTINCT — loại bỏ trùng lặp**

```sql
-- Lấy danh sách tên sản phẩm duy nhất    
SELECT DISTINCT product_id FROM products;

-- DISTINCT áp dụng toàn bộ tổng hợp cột được chọn, không phải từng cột
SELECT DISTINCT product_name, price FROM products; 
```

#### **1.4. ORDER BY**

```sql
SELECT product_name, price FROM products
ORDER BY price DESC, name ASC; -- sắp theo price giảm dần, nếu trùng thì name tăng dần

-- Sắp theo vị trí cột (không khuyến khích vì khó đọc/maintain)
SELECT name, price FROM products ORDER BY 2 DESC;

-- NULL trong ORDER BY: mặc định NULL được coi là LỚN NHẤT khi ASC (đứng cuối)
-- Postgres cho phép chỉnh:
SELECT * FROM products ORDER BY category_id NULLS LAST;
SELECT * FROM products ORDER BY category_id NULLS FIRST;
```

#### **1.5. LIMIT / OFFSET — phân trang**

```sql
-- Lấy 10 sản phẩm, bỏ qua 20 sản phẩm đầu (trang 3, page size = 10)
SELECT * FROM products
ORDER BY id
LIMIT 10 OFFSET 20; 
```

⚠️ **Vấn đề hiệu năng thực tế:** `OFFSET` lớn sẽ chậm dần vì DB vẫn phải quét qua các dòng bị bỏ. Với bảng lớn, dùng **keyset pagination** (cursor-based) sẽ nhanh hơn nhiều:

```sql
-- Thay vì OFFSET, dùng điều kiện dựa trên id/created_at của dòng cuối trang trước
SELECT * FROM products
WHERE id > 12345  -- id cuối cùng của trang trước
ORDER BY id
LIMIT 10; 
```

#### 1.6. Ví dụ tổng hợp toàn bộ mệnh đề

```sql
SELECT id, name, price
FROM products
WHERE price BETWEEN 100 AND 1000
  AND stock_qty > 0
  AND name ILIKE '%laptop%'
ORDER BY price DESC
LIMIT 5;
```
