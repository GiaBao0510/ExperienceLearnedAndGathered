## 1. Bitcoin Script / Bitcoin Script

### 1.1. Script là gì?

- Mỗi giao dịch Bitcoin có **script** gắn trong **input** và **output**. Script là một **danh sách lệnh** quy định **điều kiện để chi tiêu** số Bitcoin của một output [1][2].
- Bitcoin Script là ngôn ngữ **dựa trên stack** (_stack-based_), tương tự ngôn ngữ Forth. Stack là cấu trúc dữ liệu **vào sau, ra trước** (LIFO): dữ liệu được _push_ lên đỉnh, lệnh lấy (_pop_) dữ liệu từ đỉnh để xử lý.
- Mỗi lệnh gọi là một **opcode** (_operation code_ — mã lệnh, cho bộ xử lý biết phải làm gì với dữ liệu). Mỗi opcode có kích thước **1 byte**.
- Script **không Turing-complete** (_Turing incomplete_): **không có vòng lặp**. Nhờ đó mọi script đều chắc chắn kết thúc, tránh bị lợi dụng làm treo node. Kết quả thực thi là **thành công (true)** hoặc **thất bại (false)** [1][2].

> Stack là **vùng nhớ tạm trong quá trình chạy một script**, không phải chồng các giao dịch.

### 1.2. Locking script và Unlocking script / Khóa và Mở khóa

![Script construction](https://i.ibb.co/3mkNkRxG/image.png)

| |Tên khác|Nằm ở đâu|Vai trò|
|---|---|---|---|
|**Locking script** (script khóa)|`scriptPubKey`|**Output**|Đặt ra điều kiện (_encumbrance_) phải thỏa mãn để chi tiêu output đó|
|**Unlocking script** (script mở khóa)|`scriptSig`|**Input**|Do người chi tiêu cung cấp để thỏa mãn điều kiện trên|

**Ví dụ:** Ross gửi coin cho Joey, output của Ross "khóa" coin vào địa chỉ của Joey. Về sau, khi **Joey muốn chi tiêu** số coin này, Joey phải đưa ra unlocking script gồm **chữ ký (signature) + public key của Joey** để chứng minh mình là chủ sở hữu.

![Script example](https://i.ibb.co/Cshp152T/image.png)

Khi xác thực, các node **ghép unlocking script (từ input) với locking script (từ output được tham chiếu)** thành một script duy nhất rồi chạy. Joey chỉ chi tiêu được nếu kết quả cuối cùng là **true** [1].

### 1.3. Mẫu script phổ biến: P2PKH / Pay-to-Public-Key-Hash

Locking script chuẩn (với địa chỉ dạng cũ, bắt đầu bằng `1`):

```
OP_DUP OP_HASH160 <pubKeyHash> OP_EQUALVERIFY OP_CHECKSIG
```

Unlocking script tương ứng:

```
<signature> <publicKey>
```

Ý nghĩa các lệnh:

|Opcode|Ý nghĩa|
|---|---|
|`OP_DUP`|Nhân đôi phần tử trên đỉnh stack|
|`OP_HASH160`|Băm phần tử trên đỉnh: `RIPEMD160(SHA256(x))`|
|`OP_EQUALVERIFY`|So sánh hai phần tử trên đỉnh; nếu **bằng nhau** thì bỏ cả hai và chạy tiếp, nếu **khác** thì script **thất bại**|
|`OP_CHECKSIG`|Kiểm tra chữ ký có khớp với public key không; đẩy `true` hoặc `false` lên stack|


### 1.4. Thực thi script từng bước / Evaluating a Script

[Execution 1](https://i.ibb.co/8ppVY4H/image.png)

Script ghép: `<sig> <pubKey> OP_DUP OP_HASH160 <pubKeyHash> OP_EQUALVERIFY OP_CHECKSIG`. Con trỏ thực thi chạy từ trái sang phải:

|Bước|Lệnh|Stack sau bước (đỉnh ở bên phải)|
|---|---|---|
|1|push `<sig>`|`sig`|
|2|push `<pubKey>`|`sig, pubKey`|
|3|`OP_DUP`|`sig, pubKey, pubKey`|
|4|`OP_HASH160`|`sig, pubKey, hash(pubKey)`|
|5|push `<pubKeyHash>` (từ locking script)|`sig, pubKey, hash(pubKey), pubKeyHash`|
|6|`OP_EQUALVERIFY` (hai hash bằng nhau → bỏ cả hai)|`sig, pubKey`|
|7|`OP_CHECKSIG`|`true`|

![Execution 2](https://i.ibb.co/mV8qq4KF/image.png)

Kết quả cuối là `true` → giao dịch hợp lệ. **Ý nghĩa:** bước 6 chứng minh public key khớp với địa chỉ; bước 7 chứng minh người chi tiêu nắm giữ private key tương ứng.

### 1.5. Tập lệnh (opcode) của Bitcoin Script

Các nhóm opcode: hằng số (_constants_), điều khiển luồng (_flow control_), thao tác stack, logic bit, số học, mật mã (_crypto_), khóa thời gian (_locktime_), _pseudo-words_ và từ khóa dự trữ (_reserved words_) [2].

### 1.6. Mô phỏng script P2PKH bằng Golang

Ví dụ giúp bạn _thấy_ stack hoạt động (đơn giản hóa: ký trên hash của một thông điệp, không phải cấu trúc giao dịch thật). Cài: `go get github.com/btcsuite/btcd/btcec/v2 github.com/btcsuite/btcd/btcutil` [8].

```go
package main

import (
	"bytes"
	"crypto/sha256"
	"errors"
	"fmt"

	"github.com/btcsuite/btcd/btcec/v2"
	"github.com/btcsuite/btcd/btcec/v2/ecdsa"
	"github.com/btcsuite/btcd/btcutil"
)

// Item là một phần tử của script: lệnh (Op) hoặc dữ liệu cần push
type Item struct {
	Op   string // "PUSH" hoặc tên opcode
	Data []byte
}

// run thực thi script trên stack, trả về true nếu thành công
func run(script []Item, msgHash []byte) (bool, error) {
	var stack [][]byte
	pop := func() ([]byte, error) {
		if len(stack) == 0 {
			return nil, errors.New("stack rỗng")
		}
		v := stack[len(stack)-1]
		stack = stack[:len(stack)-1]
		return v, nil
	}

	for _, it := range script {
		switch it.Op {
		case "PUSH":
			stack = append(stack, it.Data)
		case "OP_DUP":
			v, err := pop()
			if err != nil {
				return false, err
			}
			stack = append(stack, v, v)
		case "OP_HASH160":
			v, err := pop()
			if err != nil {
				return false, err
			}
			stack = append(stack, btcutil.Hash160(v))
		case "OP_EQUALVERIFY":
			a, err1 := pop()
			b, err2 := pop()
			if err1 != nil || err2 != nil {
				return false, errors.New("thiếu dữ liệu cho EQUALVERIFY")
			}
			if !bytes.Equal(a, b) {
				return false, errors.New("hash public key không khớp địa chỉ")
			}
		case "OP_CHECKSIG":
			pubBytes, err1 := pop()
			sigBytes, err2 := pop()
			if err1 != nil || err2 != nil {
				return false, errors.New("thiếu dữ liệu cho CHECKSIG")
			}
			pub, err := btcec.ParsePubKey(pubBytes)
			if err != nil {
				return false, err
			}
			sig, err := ecdsa.ParseDERSignature(sigBytes)
			if err != nil {
				return false, err
			}
			if sig.Verify(msgHash, pub) {
				stack = append(stack, []byte{1})
			} else {
				stack = append(stack, []byte{})
			}
		default:
			return false, fmt.Errorf("opcode chưa hỗ trợ: %s", it.Op)
		}
	}

	if len(stack) == 0 {
		return false, nil
	}
	return len(stack[len(stack)-1]) > 0, nil // đỉnh stack khác rỗng = true
}

func main() {
	// Joey có cặp khóa; coin đã được "khóa" vào hash public key của Joey
	priv, _ := btcec.NewPrivateKey()
	pubBytes := priv.PubKey().SerializeCompressed()
	pubKeyHash := btcutil.Hash160(pubBytes)

	// Thông điệp cần ký (thực tế là hash của giao dịch)
	msgHash := sha256.Sum256([]byte("Joey chi tieu UTXO"))
	sig := ecdsa.Sign(priv, msgHash[:]).Serialize() // chữ ký DER

	// Script ghép = unlocking (sig, pubKey) + locking (P2PKH)
	script := []Item{
		{"PUSH", sig},
		{"PUSH", pubBytes},
		{"OP_DUP", nil},
		{"OP_HASH160", nil},
		{"PUSH", pubKeyHash},
		{"OP_EQUALVERIFY", nil},
		{"OP_CHECKSIG", nil},
	}

	ok, err := run(script, msgHash[:])
	fmt.Println("Hợp lệ:", ok, "| lỗi:", err)
}
```

**Tạo locking script thật bằng thư viện `txscript`** [8]:

```go
addr, _ := btcutil.NewAddressPubKeyHash(pubKeyHash, &chaincfg.MainNetParams)
lockScript, _ := txscript.PayToAddrScript(addr)
asm, _ := txscript.DisasmString(lockScript)
fmt.Println(asm) // OP_DUP OP_HASH160 <hash> OP_EQUALVERIFY OP_CHECKSIG
```

## 2. Mạng Bitcoin và các Node / Bitcoin Network and Nodes

### 2.1. Đặc điểm mạng Bitcoin / Bitcoin Network

![Bitcoin network](https://encrypted-tbn0.gstatic.com/images?q=tbn:ANd9GcRStyJ5wy6W01F1Qq1GiMylifuwqHtkzGtlLSUBv6TWyW3m9L4FysT3bbM&s=10)

- Bitcoin là mạng **ngang hàng (P2P — peer-to-peer)**, hình thành **ad hoc** (tự phát, không có người điều phối) với **cấu trúc kết nối ngẫu nhiên** (_random topology_) [1][3].
- Giao thức chạy trên **TCP, cổng mặc định 8333** (mạng chính — _mainnet_) [3].
- **Mọi node bình đẳng** về mặt giao thức, không có node "trung tâm" [1].
- Node mới có thể **gia nhập bất cứ lúc nào**. Node không phản hồi sẽ dần bị loại khỏi danh sách kết nối.

### 2.2. Bốn chức năng của một node / Four Node Functions

![Network nodes](https://dist.neo4j.com/wp-content/uploads/20180109025607/import-bitcoin-blockchain-neo4j-graph-database.gif)

Một node có thể đảm nhận một hay nhiều trong **4 chức năng** [1]:

|Ký hiệu|Chức năng|Mô tả|
|---|---|---|
|**W**|Wallet (ví)|Quản lý khóa và tạo giao dịch; thường tích hợp trong node đầy đủ ở ứng dụng desktop|
|**M**|Miner (thợ đào)|Tạo khối mới bằng cách giải bài toán Proof-of-Work. Thợ đào cá nhân thường tham gia **mining pool** và không tự giữ blockchain đầy đủ|
|**B**|Full Blockchain (blockchain đầy đủ)|Giữ **bản sao đầy đủ, cập nhật** của blockchain; có thể **tự xác thực** mọi giao dịch mà không cần tin ai|
|**N**|Network routing (định tuyến mạng)|Mọi node đều có, để tham gia mạng: nhận và chuyển tiếp giao dịch, khối|

### 2.3. Các loại node / Types of Bitcoin Nodes

[![oFODIX2.md.png](https://iili.io/oFODIX2.md.png)](https://freeimage.host/i/oFODIX2)

| Loại node                                 | Chức năng                     | Ghi chú                                                                                                |
| ----------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------ |
| **Reference client** (ví dụ Bitcoin Core) | W, B, N (và M theo mô tả gốc) | Phần mềm tham chiếu của Bitcoin                                                                        |
| **Full blockchain node** (node đầy đủ)    | B, N                          | Có blockchain đầy đủ và định tuyến mạng, tự xác thực                                                   |
| **Solo miner** (thợ đào đơn lẻ)           | M, B, N                       | Tự đào, giữ blockchain đầy đủ                                                                          |
| **Lightweight wallet** (ví nhẹ, SPV)      | W, N                          | Không giữ blockchain đầy đủ, dựa vào node khác để xác minh                                             |
| **Pool protocol server**                  | Cổng kết nối                  | Router nối mạng P2P Bitcoin với các node chạy giao thức khác như **Stratum** (giao thức đào theo pool) |
| **Mining node** (thợ đào trong pool)      | M                             | Không giữ blockchain, nối pool qua Stratum hoặc giao thức pool khác                                    |

## 3. Gia nhập mạng Bitcoin / Joining the Bitcoin Network

[![oFeIVCN.md.png](https://iili.io/oFeIVCN.md.png)](https://freeimage.host/i/oFeIVCN)

**Vấn đề:** node mới chưa biết ai trong mạng để kết nối. Giải pháp là **seed**:

1. Node mới hỏi **DNS seeds** (máy chủ DNS do cộng đồng vận hành, trả về danh sách địa chỉ IP của các node đang hoạt động ổn định, thời gian online cao) [3][4].
2. **Dự phòng:** nếu DNS seeds không khả dụng, Bitcoin Core dùng **seed node được ghi cứng (hard-coded)** trong mã nguồn [4].
3. Node chọn một số địa chỉ từ danh sách và **kết nối trực tiếp tới các node ngang hàng (peers)**.
4. Node mới yêu cầu thêm địa chỉ từ peers để mở rộng danh sách kết nối, rồi **tải về blockchain** từ peers (quá trình _Initial Block Download_) và tự xác thực từng khối.

[![oFe7Ejs.md.png](https://iili.io/oFe7Ejs.md.png)](https://freeimage.host/i/oFe7Ejs)


**Ví dụ Golang: truy vấn DNS seed và thử kết nối** (DNS seed `seed.bitcoin.sipa.be` có trong danh sách của Bitcoin Core [4]; danh sách seed có thể thay đổi theo thời gian):

```go
package main

import (
	"fmt"
	"net"
	"time"
)

func main() {
	// 1. Hỏi DNS seed để lấy danh sách IP node
	ips, err := net.LookupHost("seed.bitcoin.sipa.be")
	if err != nil {
		fmt.Println("Không tra cứu được DNS seed:", err)
		return
	}
	fmt.Println("Số IP nhận được:", len(ips))

	// 2. Thử kết nối TCP cổng 8333 tới vài node đầu tiên
	for i, ip := range ips {
		if i >= 3 {
			break
		}
		addr := net.JoinHostPort(ip, "8333")
		conn, err := net.DialTimeout("tcp", addr, 5*time.Second)
		if err != nil {
			fmt.Println("Kết nối thất bại:", addr)
			continue
		}
		fmt.Println("Kết nối thành công:", addr)
		conn.Close()
	}
}
```

> Ví dụ chỉ mở kết nối TCP. Để thực sự "nói chuyện" với node cần bắt tay giao thức Bitcoin (thông điệp `version`/`verack`) [3].

## 4. Khai thác trong Bitcoin Blockchain / Mining

![Mining](https://images.ctfassets.net/q5ulk4bp65r7/77UG0yFqYxqIlehK6snIEO/ae54bbb1ad0dcf55934959bc9ade74ab/Copy_of_Learn_Illustration_What_is_Mining.jpg)

### 4.1. Mining là gì và tạo ra Bitcoin mới như thế nào?

**Mining** (khai thác, đào) là quá trình thợ đào gom giao dịch vào khối mới và chứng minh đã bỏ ra công sức tính toán (**Proof-of-Work — bằng chứng công việc**). Thợ đào thắng nhận **phần thưởng khối** (block subsidy) cộng **phí giao dịch**. Đây là cách Bitcoin mới được tạo ra, thông qua **coinbase transaction** (giao dịch đặc biệt đầu tiên trong mỗi khối) [1][9].

**Phần thưởng giảm một nửa (halving)** sau mỗi 210.000 khối (khoảng 4 năm): 50 → 25 → 12,5 → 6,25 → **3,125 BTC** (từ tháng 4/2024) [9].

### 4.2. Bốn bước của quy trình / The Four Steps

Theo [1], mạng đạt đồng thuận **không cần bên trung tâm** nhờ 4 bước **độc lập** do các node tự thực hiện:

1. **Xác thực độc lập từng giao dịch** _(Independent verification of each transaction)_: mỗi full node kiểm tra giao dịch theo một danh sách tiêu chí (chữ ký, UTXO chưa bị tiêu, cú pháp, script hợp lệ…).
2. **Gom giao dịch thành khối mới** _(Independent aggregation into new blocks)_: thợ đào đưa giao dịch hợp lệ vào một **candidate block** (khối ứng viên) rồi thực hiện Proof-of-Work để "chứng minh" khối.
3. **Xác thực độc lập khối mới** _(Independent verification of new blocks)_: khi thợ đào công bố khối, **mỗi node** tự kiểm tra khối có hợp lệ không (bao gồm bằng chứng PoW).
4. **Chọn chuỗi có tổng công việc lớn nhất** _(Independent selection of the chain with the most cumulative proof-of-work)_: mỗi node chọn chuỗi có **tổng PoW tích lũy lớn nhất** làm chuỗi chính và lắp khối vào đó.

### 4.3. Proof-of-Work trong thực tế

Thợ đào băm **header của khối** (gồm hash khối trước, Merkle root của giao dịch, thời gian, độ khó, **nonce**) bằng **SHA-256 hai lần** và thay đổi `nonce` liên tục cho đến khi hash **nhỏ hơn một giá trị mục tiêu (target)**. Độ khó được điều chỉnh sau mỗi **2016 khối** để trung bình khoảng **10 phút/khối** [1][5].

**Ví dụ Golang mô phỏng PoW** (đơn giản hóa: yêu cầu hash bắt đầu bằng N ký tự `0` hex, thay vì so sánh với target như thực tế):

```go
package main

import (
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"strings"
)

// mine tìm nonce sao cho SHA256(SHA256(data+nonce)) bắt đầu bằng 'difficulty' ký tự '0'
func mine(data string, difficulty int) (int, string) {
	prefix := strings.Repeat("0", difficulty)
	for nonce := 0; ; nonce++ {
		h1 := sha256.Sum256([]byte(fmt.Sprintf("%s%d", data, nonce)))
		h2 := sha256.Sum256(h1[:]) // băm hai lần như Bitcoin
		s := hex.EncodeToString(h2[:])
		if strings.HasPrefix(s, prefix) {
			return nonce, s
		}
	}
}

func main() {
	block := "prevHash|merkleRoot|Ross->Joey:5BTC"
	for d := 1; d <= 5; d++ {
		nonce, hash := mine(block, d)
		fmt.Printf("difficulty=%d nonce=%d hash=%s\n", d, nonce, hash)
	}
}
```

**Quan sát:** mỗi lần tăng độ khó thêm 1 ký tự `0`, số lần thử trung bình tăng khoảng 16 lần. Đó là lý do khó "sửa lén" một khối cũ: phải làm lại PoW cho khối đó và **mọi khối sau nó**.

## 5. Nội dung mở rộng / Extended Content

1. **SegWit và script hiện đại:** địa chỉ `bc1…` (P2WPKH) có locking script dạng `OP_0 <20-byte hash>`, chữ ký và public key được chuyển sang vùng **witness** thay vì `scriptSig` [6].
2. **P2SH và đa chữ ký (multisig):** cho phép điều kiện như "cần 2 trong 3 chữ ký" (`OP_CHECKMULTISIG`), dùng cho ví chung hoặc quỹ chung.
3. **Timelock:** `OP_CHECKLOCKTIMEVERIFY` khóa coin đến một thời điểm hoặc độ cao khối nhất định [2].
4. **Mining pool và Stratum:** thợ đào gộp sức mạnh tính toán, chia phần thưởng theo đóng góp [7].
5. **Full node vs SPV:** tự chạy full node giúp bạn **không phải tin ai** khi kiểm tra giao dịch. Đây là lý do cộng đồng khuyến khích chạy node.
6. **Bài tập Golang gợi ý:** (a) mở rộng trình mô phỏng script ở mục 1.6 thêm `OP_EQUAL`, `OP_ADD`; (b) tạo chuỗi khối đơn giản gồm nhiều khối liên kết hash và đào từng khối; (c) viết chương trình hỏi nhiều DNS seed và đếm số IP khác nhau.
