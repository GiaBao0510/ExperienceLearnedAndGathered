# Chương 3: Các Thao Tác Cơ Bản với Elasticsearch

---

## 3.1 Giới Thiệu

**Elasticsearch** là một công cụ tìm kiếm và phân tích dữ liệu phân tán (distributed search & analytics engine), được xây dựng trên nền tảng Apache Lucene. Elasticsearch thường được dùng để:

- Tìm kiếm full-text (tìm kiếm toàn văn bản)
- Phân tích log và dữ liệu sự kiện (event data)
- Lưu trữ và truy vấn dữ liệu có cấu trúc hoặc bán cấu trúc

Một số khái niệm cần nắm trước khi thực hành:

|Khái niệm|Giải thích|
|---|---|
|**Index**|Tương tự như một "bảng" trong cơ sở dữ liệu quan hệ. Ví dụ: `ecommerce`|
|**Document**|Một bản ghi dữ liệu trong index, được lưu dưới dạng JSON|
|**Field**|Một thuộc tính của document, ví dụ: `username`, `@timestamp`|
|**Shard**|Elasticsearch chia index thành các mảnh nhỏ gọi là shard để phân tán dữ liệu|
|**_id**|Định danh duy nhất của mỗi document (có thể tự đặt hoặc để Elasticsearch tự sinh)|

## 3.4 Các Thao Tác CRUD Cơ Bản

**CRUD** là viết tắt của **Create – Read – Update – Delete**, đây là bốn thao tác cơ bản nhất khi làm việc với dữ liệu.

---

### 3.4.1 Thêm Một Document (Create)

Sử dụng `POST` để thêm một document mới vào index. Nếu index chưa tồn tại, Elasticsearch sẽ tự động tạo mới.

```
POST ecommerce/_doc
{
  "@timestamp": "2026-04-03",
  "username": "Nguyen Van A",
  "role": "client"
}
```

**Giải thích câu lệnh:**

- `POST` — phương thức HTTP dùng để tạo mới
- `ecommerce` — tên index (sẽ được tạo tự động nếu chưa có)
- `_doc` — endpoint mặc định để thêm document
- Phần body `{ ... }` — nội dung document dưới dạng JSON

**Output trả về:**

```json
{
  "_index": "ecommerce",
  "_id": "ET78U50B1HwX1iRJB6Un",
  "_version": 1,
  "result": "created",
  "_shards": {
    "total": 2,
    "successful": 1,
    "failed": 0
  },
  "_seq_no": 0,
  "_primary_term": 1
}
```

**Giải thích output:**

|Trường|Ý nghĩa|
|---|---|
|`_index`|Tên index vừa lưu document|
|`_id`|ID tự động sinh ra để định danh document này|
|`_version`|Phiên bản của document (mỗi lần cập nhật sẽ tăng lên)|
|`result`|Kết quả thao tác: `"created"` = tạo thành công|
|`_shards.successful`|Số lượng shard đã lưu thành công|

### 3.4.2 Thêm Nhiều Documents Cùng Lúc (Bulk Create)

Khi cần thêm nhiều document cùng lúc, ta dùng **Bulk API** (`_bulk`) để tăng hiệu suất, thay vì gửi từng request riêng lẻ.

```
POST ecommerce/_bulk
{"create":{}}
{"@timestamp":"2026-04-03", "product": "pen"}
{"create":{}}
{"@timestamp":"2026-04-04", "product": "scissors"}
{"create":{}}
{"@timestamp":"2026-04-05", "product": "Ruler"}
{"create":{}}
{"@timestamp":"2026-04-06", "product": "eraser"}
```

**Giải thích câu lệnh:**

- Mỗi document gồm **2 dòng**: dòng đầu là **hành động** (`{"create":{}}`), dòng thứ hai là **dữ liệu**
- `{"create":{}}` — yêu cầu tạo document mới với ID tự sinh
- **Không được có dòng trống** giữa các cặp dòng, Elasticsearch sẽ báo lỗi

**Output trả về (rút gọn):**

```json
{
  "errors": false,
  "took": 119,
  "items": [
    {
      "create": {
        "_index": "ecommerce",
        "_id": "Ej4RVJ0B1HwX1iRJyaVK",
        "_version": 1,
        "result": "created",
        "status": 201
      }
    },
    {
      "create": {
        "_index": "ecommerce",
        "_id": "Ez4RVJ0B1HwX1iRJyaVK",
        "_version": 1,
        "result": "created",
        "status": 201
      }
    }
    ...
  ]
}
```

**Giải thích output:**

|Trường|Ý nghĩa|
|---|---|
|`errors`|`false` = không có lỗi nào trong toàn bộ batch|
|`took`|Thời gian xử lý (milliseconds)|
|`items`|Danh sách kết quả của từng document|
|`status: 201`|HTTP status code — 201 có nghĩa là tạo thành công|

> **Lưu ý:** Dù `errors: false`, bạn vẫn nên kiểm tra từng item trong `items` vì một số document có thể bị lỗi riêng lẻ trong khi các document khác vẫn thành công.

### 3.4.3 Xem Thông Tin Các Index (Read Index List)

Câu lệnh sau liệt kê tất cả các index hiện có trong Elasticsearch:

```
GET _cat/indices
```

**Giải thích:**

- `GET` — phương thức HTTP dùng để đọc dữ liệu
- `_cat/indices` — endpoint hiển thị danh sách index dưới dạng dễ đọc (cat = compact and aligned text)

**Output trả về:**

```
yellow open ecommerce lIIIFIqvSwSqIE2a83JEsg 1 1 5 0 10.9kb 10.9kb 10.9kb
```

**Giải thích từng cột:**

|Cột|Giá trị mẫu|Ý nghĩa|
|---|---|---|
|Trạng thái màu|`yellow`|Trạng thái cluster: `green` = tốt, `yellow` = thiếu replica, `red` = có lỗi|
|Trạng thái|`open`|Index đang mở và có thể truy cập|
|Tên index|`ecommerce`|Tên của index|
|UUID|`lIII...`|ID nội bộ của index|
|Số primary shard|`1`|Số shard chính|
|Số replica shard|`1`|Số bản sao (replica)|
|Số document|`5`|Tổng số document trong index|
|Xóa|`0`|Số document đã xóa nhưng chưa được dọn dẹp|
|Dung lượng|`10.9kb`|Dung lượng index trên disk|

> **Lý do trạng thái `yellow`:** Khi chạy Elasticsearch trên một node duy nhất (môi trường học tập), các replica shard không thể được phân bổ vì không có node thứ hai. Đây là **bình thường** trong môi trường development.

### 3.4.4 Đọc Một Document Theo ID (Read by ID)

Để lấy thông tin của một document cụ thể, ta dùng ID của document đó:

```
GET ecommerce/_doc/ET78U50B1HwX1iRJB6Un
```

**Output trả về:**

```json
{
  "_index": "ecommerce",
  "_id": "ET78U50B1HwX1iRJB6Un",
  "_version": 1,
  "found": true,
  "_source": {
    "@timestamp": "2026-04-03",
    "username": "Nguyen Van A",
    "role": "client"
  }
}
```

**Giải thích:**

- `found: true` — tìm thấy document
- `_source` — nội dung gốc của document khi được lưu

### 3.4.5 Tìm Kiếm Tất Cả Documents (Search All)

Câu lệnh sau tìm kiếm tất cả document trong index `ecommerce` và sắp xếp theo thời gian giảm dần (mới nhất lên đầu):

```
GET ecommerce/_search
{
  "query": {
    "match_all": {}
  },
  "sort": [
    {
      "@timestamp": {
        "order": "desc"
      }
    }
  ]
}
```

**Giải thích câu lệnh:**

|Phần|Ý nghĩa|
|---|---|
|`"query": {"match_all": {}}`|Lấy tất cả documents, không lọc gì cả|
|`"sort"`|Sắp xếp kết quả|
|`"@timestamp": {"order": "desc"}`|Sắp xếp theo trường `@timestamp`, giảm dần (mới nhất trước)|

**Output trả về:**

```json
{
  "took": 6,
  "timed_out": false,
  "_shards": {
    "total": 1,
    "successful": 1,
    "skipped": 0,
    "failed": 0
  },
  "hits": {
    "total": {
      "value": 5,
      "relation": "eq"
    },
    "max_score": null,
    "hits": [
      {
        "_index": "ecommerce",
        "_id": "FT4RVJ0B1HwX1iRJyaVK",
        "_score": null,
        "_source": {
          "@timestamp": "2026-04-06",
          "product": "eraser"
        },
        "sort": [1775433600000]
      },
      {
        "_index": "ecommerce",
        "_id": "FD4RVJ0B1HwX1iRJyaVK",
        "_score": null,
        "_source": {
          "@timestamp": "2026-04-05",
          "product": "Ruler"
        },
        "sort": [1775347200000]
      }
      ...
    ]
  }
}
```

**Giải thích output:**

|Trường|Ý nghĩa|
|---|---|
|`took`|Thời gian thực hiện truy vấn (milliseconds)|
|`timed_out`|`false` = truy vấn không bị timeout|
|`hits.total.value`|Tổng số document khớp (ở đây là 5)|
|`hits.hits`|Danh sách các document trả về|
|`_score`|Điểm liên quan (relevance score); `null` khi dùng sort thay vì tìm kiếm theo từ khóa|
|`sort`|Giá trị dùng để sắp xếp (timestamp dạng milliseconds Unix)|

### 3.4.6 Lấy Một Field Cụ Thể (Select Specific Fields)

Khi document có nhiều field nhưng ta chỉ cần một số field nhất định, dùng tham số `fields` và đặt `"_source": false` để bỏ phần dữ liệu gốc:

```
GET ecommerce/_search
{
  "query": {
    "match_all": {}
  },
  "fields": [
    "@timestamp"
  ],
  "_source": false,
  "sort": [
    {
      "@timestamp": {
        "order": "desc"
      }
    }
  ]
}
```

**Giải thích:**

- `"fields": ["@timestamp"]` — chỉ trả về trường `@timestamp`
- `"_source": false` — không trả về toàn bộ document gốc, giúp response nhẹ hơn

**Output trả về:**

```json
{
  "hits": {
    "total": {"value": 5, "relation": "eq"},
    "hits": [
      {
        "_id": "FT4RVJ0B1HwX1iRJyaVK",
        "fields": {
          "@timestamp": ["2026-04-06T00:00:00.000Z"]
        },
        "sort": [1775433600000]
      },
      {
        "_id": "FD4RVJ0B1HwX1iRJyaVK",
        "fields": {
          "@timestamp": ["2026-04-05T00:00:00.000Z"]
        },
        "sort": [1775347200000]
      }
      ...
    ]
  }
}
```

> **Lưu ý:** Khi dùng `fields`, timestamp được trả về dưới dạng chuẩn ISO 8601 (`2026-04-06T00:00:00.000Z`), trong khi `_source` trả về đúng giá trị bạn đã nhập (`2026-04-06`). Đây là sự khác biệt do Elasticsearch **normalize** dữ liệu khi lập chỉ mục.

### 3.4.7 Cập Nhật Một Document (Update)

Để cập nhật một hoặc nhiều field của document đã có, dùng `POST` với endpoint `_update`:

```
POST ecommerce/_update/ET78U50B1HwX1iRJB6Un
{
  "doc": {
    "role": "admin"
  }
}
```

**Giải thích:**

- `ET78U50B1HwX1iRJB6Un` — ID của document cần cập nhật
- `"doc": { ... }` — chỉ cập nhật các field được liệt kê, các field còn lại giữ nguyên

**Output trả về:**

```json
{
  "_index": "ecommerce",
  "_id": "ET78U50B1HwX1iRJB6Un",
  "_version": 2,
  "result": "updated"
}
```

> **Lưu ý:** `_version` tăng từ `1` lên `2`, chứng tỏ document đã được cập nhật thành công.

---

### 3.4.8 Xóa Một Document (Delete)

Để xóa một document theo ID:

```
DELETE ecommerce/_doc/ET78U50B1HwX1iRJB6Un
```

**Output trả về:**

```json
{
  "_index": "ecommerce",
  "_id": "ET78U50B1HwX1iRJB6Un",
  "_version": 3,
  "result": "deleted"
}
```

> **Lưu ý:** Document bị xóa không mất ngay lập tức trên disk mà được đánh dấu là "deleted". Elasticsearch sẽ dọn dẹp định kỳ trong quá trình **merge segment**.

## 3.5 Tổng Kết Các Câu Lệnh Cơ Bản

|Thao tác|Câu lệnh|Mô tả|
|---|---|---|
|Thêm 1 document|`POST <index>/_doc`|Tạo document mới với ID tự sinh|
|Thêm nhiều documents|`POST <index>/_bulk`|Tạo nhiều documents trong một request|
|Xem danh sách index|`GET _cat/indices`|Liệt kê tất cả index|
|Đọc 1 document theo ID|`GET <index>/_doc/<id>`|Lấy document cụ thể|
|Tìm kiếm|`GET <index>/_search`|Tìm kiếm với điều kiện|
|Cập nhật document|`POST <index>/_update/<id>`|Cập nhật một phần document|
|Xóa document|`DELETE <index>/_doc/<id>`|Xóa document theo ID|
|Xóa toàn bộ index|`DELETE <index>`|Xóa cả index (thận trọng!)|

## 3.6 Một Số Lỗi Thường Gặp

| Lỗi                          | Nguyên nhân                                | Cách xử lý                                     |
| ---------------------------- | ------------------------------------------ | ---------------------------------------------- |
| `index_not_found_exception`  | Index chưa tồn tại khi thực hiện `GET`     | Kiểm tra lại tên index bằng `GET _cat/indices` |
| `document_missing_exception` | Không tìm thấy document theo ID khi update | Kiểm tra lại ID document                       |
| `status: yellow`             | Không đủ node để phân bổ replica           | Bình thường trong môi trường dev 1 node        |
| Lỗi cú pháp JSON             | Body JSON viết sai định dạng               | Kiểm tra dấu `{}`, `,`, `"` trong body         |
| Lỗi Bulk API                 | Dòng trống trong body của `_bulk`          | Đảm bảo mỗi cặp hành động-dữ liệu liền nhau    |
