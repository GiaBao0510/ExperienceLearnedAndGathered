# Chương 5: Thực Hành Tìm Kiếm Với Nhiều Trường Hợp

---

## 5.1 Giới Thiệu

Elasticsearch nổi bật với khả năng **tìm kiếm full-text** (toàn văn bản) mạnh mẽ và linh hoạt. Không giống như cơ sở dữ liệu quan hệ chỉ hỗ trợ tìm kiếm chính xác (`WHERE field = 'value'`), Elasticsearch phân tích văn bản, chấm điểm mức độ liên quan và trả về kết quả theo thứ tự phù hợp nhất.

Trong chương này, chúng ta sẽ thực hành với index `players` và lần lượt tìm hiểu các loại query từ cơ bản đến nâng cao:

|Query|Mô tả ngắn|
|---|---|
|`match`|Tìm kiếm full-text cơ bản (OR hoặc AND)|
|`multi_match`|Tìm kiếm trên nhiều field cùng lúc|
|`match_phrase`|Tìm cụm từ theo đúng thứ tự|
|`match_phrase` + `slop`|Tìm cụm từ linh hoạt, cho phép từ chen vào giữa|
|`match_phrase_prefix`|Tìm cụm từ với từ cuối chỉ cần khớp tiền tố|
|`minimum_should_match`|Kiểm soát số từ tối thiểu phải khớp|

> **Khái niệm quan trọng — Relevance Score (`_score`):** Mỗi kết quả tìm kiếm có điểm `_score` thể hiện mức độ liên quan. Document có score cao hơn sẽ xuất hiện trước. Score được tính dựa trên thuật toán BM25 (mặc định từ Elasticsearch 5+), xét đến tần suất từ xuất hiện trong document và trong toàn bộ index.

### 5.2.2 Định Nghĩa Mapping Cho Trường Ngày Tháng

Trường `birth_date` có định dạng `dd/MM/yyyy` (ví dụ: `17/07/1985`). Elasticsearch mặc định không nhận dạng được định dạng này, nên ta cần khai báo mapping rõ ràng:

```
PUT players/_mapping
{
  "properties": {
    "birth_date": {
      "type": "date",
      "format": "dd/MM/yyyy"
    }
  }
}
```

**Output:**

```json
{
  "acknowledged": true
}
```

> **Lưu ý:** Tên field trong mapping phải khớp chính xác với tên field trong dữ liệu. Ở đây ta dùng `birth_date` (có trong data), không phải `birth_day`.

### 5.3.2 Lọc Chỉ Lấy `_source` (Dùng `filter_path`)

Mặc định, `GET _doc` trả về cả metadata (`_index`, `_id`, `_version`...) lẫn dữ liệu (`_source`). Dùng `filter_path` để chỉ lấy phần `_source`, giúp response gọn hơn:

```
GET players/_doc/7?filter_path=_source
```

**Output:**

```json
{
  "_source": {
    "id": 7,
    "name": "Cristiano Ronaldo",
    "email": "cristianoronaldo@mu.com",
    "gender": "male",
    "ip": "12.13.89.143",
    "birth_date": "17/07/1985",
    "team": "Manu",
    "position": "striker",
    "age": 36,
    "country": "Portugal",
    "phrase": "root help striker",
    "salary": 808888
  }
}
```

> **So sánh:** `filter_path=_source` lọc ở tầng HTTP response (bỏ metadata). Còn `?_source=field1,field2` (đã học ở Chương 4) lọc ở tầng dữ liệu (chỉ lấy một số field trong `_source`). Hai cách có thể kết hợp với nhau.

## 5.4 Các Loại Tìm Kiếm (Search Queries)

### 5.4.1 `match` — Tìm Kiếm Full-Text Cơ Bản

`match` là query phổ biến nhất. Nó **phân tích (analyze)** chuỗi tìm kiếm thành các từ riêng lẻ (token), sau đó tìm document chứa các từ đó.

---

#### Tìm Kiếm Theo Dạng OR (Mặc Định)

Khi không chỉ định operator, `match` dùng **OR** — document chỉ cần chứa **ít nhất một** trong các từ là khớp.

```
POST players/_search
{
  "query": {
    "match": {
      "phrase": "juve help striker"
    }
  }
}
```

Query trên tìm document có trường `phrase` chứa **"juve" OR "help" OR "striker"**.

**Output:**

```json
{
  "hits": {
    "total": { "value": 3, "relation": "eq" },
    "max_score": 1.2031468,
    "hits": [
      {
        "_id": "8",
        "_score": 1.2031468,
        "_source": { "phrase": "root help striker juve", ... }
      },
      {
        "_id": "7",
        "_score": 0.28852317,
        "_source": { "phrase": "root help striker", ... }
      },
      {
        "_id": "9",
        "_score": 0.25748682,
        "_source": { "phrase": "root help striker manu", ... }
      }
    ]
  }
}
```

**Phân tích kết quả:**

- Cả 3 player đều khớp vì đều chứa "help" và "striker"
- Player **8** có `_score` cao nhất (1.20) vì chứa **cả 3 từ**: "juve", "help", "striker"
- Player **7** và **9** có score thấp hơn vì chỉ khớp với "help" và "striker" (thiếu "juve")

---

#### Tìm Kiếm Theo Dạng AND

Thêm `"operator": "and"` để yêu cầu document phải chứa **tất cả** các từ:

```
POST players/_search
{
  "query": {
    "match": {
      "phrase": {
        "query": "juve help striker",
        "operator": "and"
      }
    }
  }
}
```

Query trên tìm document có trường `phrase` chứa **"juve" AND "help" AND "striker"**.

**Output:**

```json
{
  "hits": {
    "total": { "value": 1, "relation": "eq" },
    "hits": [
      {
        "_id": "8",
        "_score": 1.2031468,
        "_source": { "phrase": "root help striker juve", ... }
      }
    ]
  }
}
```

**Phân tích kết quả:**

- Chỉ player **8** khớp vì là player duy nhất có phrase chứa đủ cả 3 từ "juve", "help", "striker"
- Player 7 và 9 bị loại vì phrase của họ không có từ "juve"

---

#### `minimum_should_match` — Kiểm Soát Số Từ Tối Thiểu Phải Khớp

`minimum_should_match` cho phép chỉ định **số lượng từ tối thiểu** trong query phải xuất hiện trong document. Đây là mức độ trung gian giữa OR và AND:

```
POST players/_search
{
  "query": {
    "match": {
      "phrase": {
        "query": "juve help striker",
        "minimum_should_match": 2
      }
    }
  }
}
```

Query này tìm document chứa **ít nhất 2 trong 3 từ**: "juve", "help", "striker".

**Output:**

```json
{
  "hits": {
    "total": { "value": 3, "relation": "eq" },
    "hits": [
      { "_id": "8", "_score": 1.2031468, "_source": { "phrase": "root help striker juve" } },
      { "_id": "7", "_score": 0.28852317, "_source": { "phrase": "root help striker" } },
      { "_id": "9", "_score": 0.25748682, "_source": { "phrase": "root help striker manu" } }
    ]
  }
}
```

Cả 3 player đều có ít nhất 2 từ khớp ("help" + "striker"), nên cả 3 đều được trả về.

**Nếu đặt `minimum_should_match: 3`** (tương đương `operator: and`):

```
POST players/_search
{
  "query": {
    "match": {
      "phrase": {
        "query": "juve help striker",
        "minimum_should_match": 3
      }
    }
  }
}
```

Kết quả chỉ còn player 8 (vì phải có đủ cả 3 từ).

> **Lưu ý:** Nếu đặt `minimum_should_match` lớn hơn số từ trong query (ví dụ: query có 3 từ nhưng đặt `minimum_should_match: 4`), thì **không có document nào được trả về** vì điều kiện không bao giờ thỏa mãn.

---

### 5.4.2 `multi_match` — Tìm Kiếm Trên Nhiều Field

`multi_match` cho phép tìm kiếm một chuỗi **trên nhiều field cùng lúc**. Document khớp nếu **bất kỳ field nào** trong danh sách chứa từ khóa:

```
POST players/_search
{
  "query": {
    "multi_match": {
      "query": "Rashford juve",
      "fields": ["name", "phrase"]
    }
  }
}
```

Query này tìm document có field `name` **hoặc** `phrase` chứa "Rashford" hoặc "juve".

**Output:**

```json
{
  "hits": {
    "total": { "value": 1, "relation": "eq" },
    "max_score": 0.94566,
    "hits": [
      {
        "_id": "8",
        "_score": 0.94566,
        "_source": {
          "name": "Cristiano Ronaldo Rashford",
          "phrase": "root help striker juve",
          ...
        }
      }
    ]
  }
}
```

**Phân tích kết quả:**

- Player **8** khớp vì: `name` chứa "Rashford" **và** `phrase` chứa "juve" — khớp ở cả 2 field
- Player 7 và 9 không khớp từ nào trong cả 2 field

> **Mẹo:** Có thể boost (tăng trọng số) cho một field cụ thể bằng ký hiệu `^`. Ví dụ: `"fields": ["name^3", "phrase"]` — khớp trên `name` được tính gấp 3 lần so với khớp trên `phrase`.

---

### 5.4.3 `match_phrase` — Tìm Kiếm Cụm Từ Theo Đúng Thứ Tự

`match` tách query thành các từ độc lập và không quan tâm thứ tự. `match_phrase` yêu cầu các từ phải xuất hiện **liên tiếp và đúng thứ tự** như trong query:

```
POST players/_search
{
  "query": {
    "match_phrase": {
      "phrase": "help striker juve"
    }
  }
}
```

Query này tìm document có phrase chứa đúng cụm **"help striker juve"** theo thứ tự đó, liên tiếp nhau.

**Output:**

```json
{
  "hits": {
    "total": { "value": 1, "relation": "eq" },
    "max_score": 1.2031469,
    "hits": [
      {
        "_id": "8",
        "_score": 1.2031469,
        "_source": { "phrase": "root help striker juve", ... }
      }
    ]
  }
}
```

**Phân tích kết quả:**

- Chỉ player **8** khớp vì phrase là `"root help striker juve"` — chuỗi "help striker juve" xuất hiện liên tiếp và đúng thứ tự
- Player 7 (`"root help striker"`) không khớp vì thiếu "juve"
- Player 9 (`"root help striker manu"`) không khớp vì sau "striker" là "manu", không phải "juve"

---

### 5.4.4 `match_phrase` + `slop` — Tìm Cụm Từ Linh Hoạt

`slop` là tham số mở rộng của `match_phrase`, cho phép có **tối đa N từ chen vào giữa** các từ trong query mà vẫn được tính là khớp.

```
POST players/_search
{
  "query": {
    "match_phrase": {
      "phrase": {
        "query": "help juve",
        "slop": 1
      }
    }
  }
}
```

Query tìm cụm "help juve" nhưng cho phép có **tối đa 1 từ chen vào giữa** "help" và "juve".

**Output:**

```json
{
  "hits": {
    "total": { "value": 1, "relation": "eq" },
    "hits": [
      {
        "_id": "8",
        "_score": 0.12874341,
        "_source": { "phrase": "root help striker juve", ... }
      }
    ]
  }
}
```

**Phân tích kết quả:**

- Player **8** khớp vì phrase là `"root help **striker** juve"` — giữa "help" và "juve" có đúng 1 từ ("striker"), nằm trong giới hạn `slop: 1`
- Player 7 (`"root help striker"`) không khớp vì không có từ "juve"
- Player 9 (`"root help striker manu"`) không khớp vì không có từ "juve"

**Ví dụ thêm để hiểu rõ `slop`:**

|Phrase trong document|Query|slop|Kết quả|
|---|---|---|---|
|"help striker juve"|"help juve"|0|❌ Không khớp (cần "help juve" liền nhau)|
|"help striker juve"|"help juve"|1|✅ Khớp (1 từ chen vào = "striker")|
|"help X Y juve"|"help juve"|2|✅ Khớp (2 từ chen vào = "X Y")|

---

### 5.4.5 `match_phrase_prefix` — Tìm Cụm Từ Với Tiền Tố

`match_phrase_prefix` hoạt động như `match_phrase` nhưng **từ cuối cùng trong query chỉ cần khớp phần đầu (tiền tố)**.

Ứng dụng phổ biến: tính năng **gợi ý tìm kiếm (autocomplete/search-as-you-type)** khi người dùng chưa gõ xong từ.

```
POST players/_search
{
  "query": {
    "match_phrase_prefix": {
      "phrase": {
        "query": "help striker ju"
      }
    }
  }
}
```

Query tìm cụm bắt đầu bằng "help striker" và theo sau là **bất kỳ từ nào bắt đầu bằng "ju"** (ví dụ: "juve", "junior", "jungle"...).

**Output:**

```json
{
  "hits": {
    "total": { "value": 1, "relation": "eq" },
    "max_score": 1.2031469,
    "hits": [
      {
        "_id": "8",
        "_score": 1.2031469,
        "_source": { "phrase": "root help striker juve", ... }
      }
    ]
  }
}
```

**Phân tích kết quả:**

- Player **8** khớp vì phrase là `"root help striker juve"` — cụm "help striker" có mặt, và từ tiếp theo là "juve" bắt đầu bằng "ju"

---

#### Giới Hạn Số Từ Mở Rộng Bằng `max_expansions`

`match_phrase_prefix` phải tìm tất cả các từ trong index bắt đầu bằng tiền tố đã cho. Tham số `max_expansions` giới hạn số lượng từ được xét đến, giúp **tăng tốc độ truy vấn**:

```
POST players/_search
{
  "query": {
    "match_phrase_prefix": {
      "phrase": {
        "query": "help striker ju",
        "max_expansions": 1
      }
    }
  }
}
```

- Với `max_expansions: 1`, Elasticsearch chỉ xét **1 từ** bắt đầu bằng "ju" (từ đầu tiên tìm thấy trong index)
- Kết quả vẫn là player 8 vì "juve" là từ duy nhất bắt đầu bằng "ju" trong index này

> **Lưu ý thực tế:** Giá trị `max_expansions` mặc định là **50**. Trong production, nếu index có nhiều từ bắt đầu bằng cùng tiền tố, giảm `max_expansions` giúp cải thiện hiệu suất nhưng có thể bỏ sót một số kết quả.

## 5.5 Tổng Kết và So Sánh Các Loại Query

### Bảng So Sánh

|Query|Tách từ?|Quan tâm thứ tự?|Yêu cầu liền nhau?|Dùng khi nào|
|---|---|---|---|---|
|`match` (OR)|✅ Có|❌ Không|❌ Không|Tìm kiếm thông thường, ưu tiên recall|
|`match` (AND)|✅ Có|❌ Không|❌ Không|Tìm kiếm chặt hơn, tất cả từ phải có mặt|
|`match` + `minimum_should_match`|✅ Có|❌ Không|❌ Không|Kiểm soát mức độ khớp linh hoạt|
|`multi_match`|✅ Có|❌ Không|❌ Không|Tìm trên nhiều field cùng lúc|
|`match_phrase`|✅ Có|✅ Có|✅ Có|Tìm cụm từ chính xác, đúng thứ tự|
|`match_phrase` + `slop`|✅ Có|✅ Có|⚡ Linh hoạt|Cụm từ gần đúng, cho phép từ chen vào|
|`match_phrase_prefix`|✅ Có|✅ Có|✅ Có|Autocomplete, gợi ý khi chưa gõ xong|

### Khi Nào Dùng Query Nào?

- **Thanh tìm kiếm thông thường** (như Google): dùng `match` với OR
- **Tìm kiếm chính xác toàn bộ từ**: dùng `match` với `operator: and`
- **Tìm kiếm trên nhiều field** (tên + mô tả + tag): dùng `multi_match`
- **Tìm câu/cụm từ cố định**: dùng `match_phrase`
- **Autocomplete/gợi ý**: dùng `match_phrase_prefix`
- **Tìm kiếm linh hoạt** (từ có thể không liền nhau): dùng `match_phrase` + `slop`

---

## 5.6 Lưu Ý Về Analyzer

Tất cả các query trên đều **phân tích (analyze)** văn bản trước khi tìm kiếm, nghĩa là:

- Chữ hoa/thường được chuẩn hóa: `"Juve"` và `"juve"` được xem là giống nhau
- Một số ký tự đặc biệt bị bỏ qua

Đây là lý do các query `match` và `match_phrase` **không phân biệt chữ hoa/thường**. Nếu cần tìm kiếm phân biệt hoa/thường hoặc tìm chính xác 100% (exact match), hãy dùng query `term` trên field kiểu `keyword` — sẽ được trình bày ở chương sau.
