# Thiết lập Elasticsearch và Kibana với Docker Compose

## Tổng quan

**Elasticsearch** là một công cụ tìm kiếm và phân tích dữ liệu phân tán, hiệu năng cao, thường được dùng để lưu trữ và truy vấn dữ liệu dạng văn bản (full-text search), log hệ thống, hoặc dữ liệu thời gian thực.

**Kibana** là giao diện đồ họa (dashboard) đi kèm, cho phép bạn trực quan hóa, khám phá và quản lý dữ liệu trong Elasticsearch ngay trên trình duyệt — không cần viết lệnh.

Cấu hình dưới đây khởi động **một node Elasticsearch duy nhất** (single-node) cùng với **Kibana**, phù hợp cho mục đích **học tập và phát triển cục bộ**.

```
┌──────────────────────────────────────────────────┐
│              Docker Host (máy bạn)               │
│                                                  │
│  ┌─────────────────────┐   ┌──────────────────┐  │
│  │ elasticsearch       │   │ kibana           │  │
│  │                     │   │                  │  │
│  │ cổng 9200 (HTTP) ───────────────────────────── → http://localhost:9200
│  │ cổng 9300 (nội bộ)  │   │ cổng 5601 ───────── → http://localhost:5601
│  └─────────────────────┘   └──────────────────┘  │
│         ↑ depends_on: healthy                    │
│                                                  │
│  Volume: es_data (lưu dữ liệu bền vững)          │
└──────────────────────────────────────────────────┘
```

> ⚠️ Cấu hình này **tắt xác thực bảo mật** (`xpack.security.enabled=false`) để đơn giản hóa việc học. **Không dùng cấu hình này trong môi trường production.**

## Yêu cầu tiên quyết

Kiểm tra Docker và Docker Compose đã được cài đặt:

```bash
docker --version          # Kiểm tra Docker đã được cài chưa
docker-compose --version  # Kiểm tra Docker Compose đã được cài chưa
```

> 💡 Docker cần ít nhất **4GB RAM** được cấp phát để chạy ổn định cả Elasticsearch và Kibana. Nếu dùng Docker Desktop, kiểm tra phần **Settings → Resources → Memory**.

## Tạo file `docker-compose.yml`

Tạo một thư mục mới và tạo file `docker-compose.yml` với nội dung sau:

```yaml
version: '3.8'

services:

  elasticsearch:
    image: docker.elastic.co/elasticsearch/elasticsearch:8.13.4
    container_name: elasticsearch
    environment:
      # --- CẤU HÌNH NODE VÀ CỤM ---
      - node.name=es-node-1          # Tên của node này trong cụm
      - cluster.name=my-es-cluster   # Tên cụm Elasticsearch
      - discovery.type=single-node   # Chế độ một node duy nhất (không cần tìm node khác)

      # --- TẮT BẢO MẬT (chỉ dùng cho học tập) ---
      - xpack.security.enabled=false          # Tắt xác thực username/password
      - xpack.security.http.ssl.enabled=false # Tắt HTTPS, dùng HTTP thuần

      # --- CẤU HÌNH BỘ NHỚ ---
      - bootstrap.memory_lock=true            # Khóa RAM, ngăn hệ điều hành đẩy bộ nhớ Elasticsearch ra swap
      - "ES_JAVA_OPTS=-Xms512m -Xmx512m"     # Giới hạn JVM heap: tối thiểu và tối đa đều là 512MB

    ulimits:
      # Cho phép Elasticsearch khóa bộ nhớ RAM (cần thiết khi bật memory_lock)
      memlock:
        soft: -1   # -1 nghĩa là không giới hạn
        hard: -1
      # Số lượng file tối đa mà process có thể mở đồng thời
      nofile:
        soft: 65536
        hard: 65536

    ports:
      - "9200:9200"   # Cổng HTTP API — dùng để gửi request tìm kiếm, lập chỉ mục dữ liệu
      - "9300:9300"   # Cổng giao tiếp nội bộ giữa các node trong cụm (transport layer)

    volumes:
      - es_data:/usr/share/elasticsearch/data   # Lưu dữ liệu bền vững, không mất khi container khởi động lại

    healthcheck:
      # Gọi API kiểm tra trạng thái cụm; trả về HTTP 200 nghĩa là Elasticsearch đã sẵn sàng
      test: ["CMD-SHELL", "curl -f http://localhost:9200/_cluster/health || exit 1"]
      interval: 10s   # Kiểm tra mỗi 10 giây
      timeout: 5s     # Quá 5 giây không phản hồi thì coi là thất bại
      retries: 10     # Thử lại tối đa 10 lần trước khi báo Unhealthy

  kibana:
    image: docker.elastic.co/kibana/kibana:8.13.4
    container_name: kibana
    environment:
      # Địa chỉ Elasticsearch mà Kibana sẽ kết nối vào
      # "elasticsearch" ở đây là tên service trong Docker Compose, tự resolve được
      - ELASTICSEARCH_HOSTS=http://elasticsearch:9200
      - xpack.security.enabled=false   # Tắt bảo mật phía Kibana cho đồng nhất với Elasticsearch

    ports:
      - "5601:5601"   # Cổng giao diện web của Kibana

    depends_on:
      elasticsearch:
        condition: service_healthy   # Chỉ khởi động Kibana sau khi Elasticsearch đã healthy

    healthcheck:
      # Kiểm tra trang trạng thái của Kibana
      test: ["CMD-SHELL", "curl -f http://localhost:5601/api/status || exit 1"]
      interval: 15s
      timeout: 10s
      retries: 10

# Khai báo volume ở cấp cao nhất để Docker quản lý vùng lưu trữ dữ liệu
volumes:
  es_data:
    driver: local
```

> 💡 **Lưu ý về YAML**: YAML **không chấp nhận ký tự Tab** để thụt lề — bạn phải dùng **dấu cách (space)**. Hầu hết các editor như VS Code đều có thể cấu hình tự động chuyển Tab thành spaces.

## Khởi động dịch vụ

Mở terminal, di chuyển đến thư mục chứa file `docker-compose.yml` vừa tạo và chạy:

```bash
docker-compose up -d
```

Giải thích các tham số:

- `up` : tạo và khởi động tất cả các container được khai báo trong file
- `-d` : chạy ở chế độ nền (detached), không chiếm terminal

## Kiểm tra sau khi khởi động

### 1. Kiểm tra trạng thái container

```bash
docker ps
```

Kết quả mong đợi — cột `STATUS` của cả hai container phải là `healthy`:

```
CONTAINER ID   IMAGE                                      STATUS
a1b2c3d4e5f6   docker.elastic.co/elasticsearch/...       Up 1m (healthy)
b2c3d4e5f6a7   docker.elastic.co/kibana/kibana:8.13.4    Up 45s (healthy)
```

> ⏳ Elasticsearch thường mất **30–60 giây** để đạt trạng thái `healthy`. Kibana sẽ chờ Elasticsearch healthy rồi mới khởi động.

### 2. Kiểm tra Elasticsearch qua API

```bash
curl http://localhost:9200
```

Kết quả mong đợi:

```json
{
  "name" : "es-node-1",
  "cluster_name" : "my-es-cluster",
  "version" : {
    "number" : "8.13.4",
    ...
  },
  "tagline" : "You Know, for Search"
}
```

### 3. Kiểm tra trạng thái cụm

```bash
curl http://localhost:9200/_cluster/health?pretty
```

Kết quả mong đợi — trường `status` phải là `green` hoặc `yellow` (yellow là bình thường với single-node):

```json
{
  "cluster_name" : "my-es-cluster",
  "status" : "yellow",
  "number_of_nodes" : 1,
  ...
}
```

### 4. Truy cập giao diện Kibana

Mở trình duyệt và truy cập: **http://localhost:5601**

Kibana sẽ hiển thị trang chủ với các tính năng như Discover (khám phá dữ liệu), Dashboard, và Dev Tools.

### 5. Xem log nếu có lỗi

```bash
docker logs elasticsearch   # Xem log của Elasticsearch
docker logs kibana          # Xem log của Kibana
```

Hoặc theo dõi log liên tục (nhấn `Ctrl+C` để thoát):

```bash
docker logs -f elasticsearch
```


```bash
# Dừng container nhưng GIỮ LẠI dữ liệu trong volume

```

## Tóm tắt các biến môi trường quan trọng

|Biến|Giá trị|Ý nghĩa|
|---|---|---|
|`discovery.type`|`single-node`|Chạy một node duy nhất, không tìm kiếm node khác|
|`xpack.security.enabled`|`false`|Tắt xác thực bảo mật (chỉ dùng khi học)|
|`bootstrap.memory_lock`|`true`|Khóa RAM, tránh bị đẩy ra swap disk|
|`ES_JAVA_OPTS`|`-Xms512m -Xmx512m`|Giới hạn bộ nhớ JVM cho Elasticsearch|
|`ELASTICSEARCH_HOSTS`|`http://elasticsearch:9200`|Địa chỉ Kibana dùng để kết nối vào Elasticsearch|

## Các lỗi thường gặp

**Elasticsearch ở trạng thái `unhealthy` hoặc liên tục khởi động lại** → Thường do thiếu RAM. Kiểm tra Docker Desktop có được cấp đủ 4GB không. Hoặc giảm giá trị `ES_JAVA_OPTS` xuống `-Xms256m -Xmx256m` nếu máy yếu.

**Lỗi `max virtual memory areas vm.max_map_count [65530] is too low` trên Linux** → Chạy lệnh sau trên máy host (không phải trong container):

```bash
sudo sysctl -w vm.max_map_count=262144
```

**Kibana mãi không lên (trạng thái `starting`)** → Kibana đang chờ Elasticsearch healthy. Kiểm tra log Elasticsearch trước bằng `docker logs elasticsearch`.

**Không truy cập được `http://localhost:9200` từ trình duyệt** → Kiểm tra cổng `9200` có đang bị ứng dụng khác chiếm không bằng lệnh `netstat -an | grep 9200`.
