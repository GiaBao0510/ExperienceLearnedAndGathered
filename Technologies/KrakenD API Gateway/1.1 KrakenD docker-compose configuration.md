# Triển khai KrakenD API Gateway bằng Docker Compose

## 1. Giới thiệu

**API Gateway** là "cổng vào duy nhất" đứng trước các dịch vụ backend. Client chỉ gọi vào gateway, gateway sẽ định tuyến request đến đúng backend, đồng thời xử lý các việc chung như xác thực, CORS, ghi log, cache, giới hạn tốc độ...

**KrakenD** là một API Gateway mã nguồn mở, hiệu năng cao. Điểm đặc trưng: **không cần database**, toàn bộ cấu hình nằm trong một file JSON khai báo (declarative), nên rất dễ đưa vào Git và triển khai bằng container.

Sau bài này bạn sẽ:

- Dựng được KrakenD bằng Docker Compose.
- Khai báo được một endpoint đầu tiên và kiểm tra nó hoạt động.
- Hiểu và dùng được *Flexible Configuration* (cấu hình dạng template) để tách cấu hình theo môi trường.

## 2. Chuẩn bị

| Yêu cầu | Ghi chú |
|---|---|
| Kiến thức Docker cơ bản | Hiểu **image** (bản đóng gói sẵn), **container** (thể hiện đang chạy của image), **volume** (thư mục chia sẻ giữa máy bạn và container) |
| Cài **Docker Desktop** (Windows/macOS) hoặc **Docker Engine + Compose plugin** (Linux) | Đã bao gồm Docker Compose v2 |
| Kết nối Internet | Để tải image và để backend ví dụ truy cập được |

Kiểm tra cài đặt:

```bash
docker --version
docker compose version
```

> **Lưu ý:** Tài liệu này dùng lệnh `docker compose` (có dấu cách, Compose v2). Lệnh `docker-compose` (có dấu gạch ngang) là phiên bản cũ đã ngừng phát triển.

## 3. Cấu trúc thư mục

Chúng ta sẽ tạo cấu trúc sau (phần cơ bản chỉ cần 2 file; thư mục `config/` dùng ở phần 7):

```text
krakend-demo/
├── docker-compose.yml
└── krakend_config/
    ├── krakend.json            # Cấu hình chính (phần 5)
    └── config/                 # Chỉ dùng cho Flexible Configuration (phần 7)
        ├── settings/
        ├── partials/
        └── templates/
```

## 4. Tạo file `docker-compose.yml`

Đây là cấu hình **cơ bản**, đã đủ để chạy KrakenD:

```yaml
services:
  krakend:
    image: krakend:2.10          # Ghim phiên bản cụ thể, kiểm tra tag mới nhất trên Docker Hub
    container_name: krakend
    command: run -c /etc/krakend/krakend.json
    volumes:
      - ./krakend_config:/etc/krakend/
    ports:
      - "8080:8080"
    networks:
      - myservice
    restart: unless-stopped

networks:
  myservice:
    driver: bridge
```

### Giải thích từng dòng

| Khóa | Ý nghĩa |
|---|---|
| `services` | Danh sách các container sẽ chạy. Ở đây chỉ có một service tên `krakend`. |
| `image` | Image chính thức [`krakend`](https://hub.docker.com/_/krakend) trên Docker Hub. Nên ghim số phiên bản thay vì `latest` để môi trường ổn định, tái lập được. |
| `container_name` | Tên cố định của container, giúp dễ gọi lệnh `docker logs krakend`. |
| `command` | Lệnh chạy KrakenD. `run` là khởi động gateway, `-c` (`--config`) chỉ file cấu hình. |
| `volumes` | Gắn (mount) thư mục `./krakend_config` trên máy bạn vào `/etc/krakend/` trong container. Sửa file ở máy thật là container thấy ngay (cần restart để áp dụng). |
| `ports` | `"8080:8080"` nghĩa là *cổng máy bạn : cổng container*. Sau khi chạy, truy cập gateway qua `http://localhost:8080`. |
| `networks` | Mạng nội bộ để các container giao tiếp với nhau. Mạng phải được **khai báo ở khóa `networks` cấp cao nhất** (phần cuối file). |
| `restart: unless-stopped` | Tự khởi động lại container khi lỗi hoặc khi máy khởi động lại, trừ khi bạn chủ động dừng. |

## 5. Tạo file cấu hình `krakend_config/krakend.json`

Phiên bản cơ bản, **chạy được ngay** với KrakenD bản Community (miễn phí):

```json
{
  "$schema": "https://www.krakend.io/schema/krakend.json",
  "version": 3,
  "timeout": "20s",
  "cache_ttl": "300s",
  "extra_config": {
    "telemetry/logging": {
      "level": "INFO",
      "prefix": "[KRAKEND]",
      "syslog": false,
      "stdout": true,
      "format": "default"
    },
    "security/cors": {
      "allow_origins": ["*"],
      "allow_methods": ["GET", "POST", "PUT", "DELETE"],
      "expose_headers": ["Content-Length", "Content-Type"],
      "allow_headers": ["Accept-Language", "Content-Type", "Authorization"],
      "max_age": "12h",
      "allow_credentials": false,
      "debug": false
    }
  },
  "endpoints": [
    {
      "endpoint": "/hello",
      "method": "GET",
      "output_encoding": "json",
      "backend": [
        {
          "host": ["https://jsonplaceholder.typicode.com"],
          "url_pattern": "/posts/1"
        }
      ]
    }
  ]
}
```

### Giải thích các trường

| Trường | Ý nghĩa |
|---|---|
| `$schema` | Giúp trình soạn thảo (VS Code...) gợi ý và kiểm tra lỗi cú pháp khi gõ cấu hình. |
| `version` | Phiên bản định dạng file cấu hình. KrakenD 2.x dùng `3`. |
| `timeout` | Thời gian tối đa gateway chờ backend trả lời. Ví dụ `"20s"` = 20 giây. |
| `cache_ttl` | Thời gian cache mặc định cho các response (TTL = Time To Live). |
| `extra_config` | Nơi khai báo các thành phần mở rộng (log, CORS, xác thực...). Mỗi thành phần có một "tên không gian" như `telemetry/logging`. |
| `telemetry/logging` | Cấu hình log: mức `INFO`, in ra stdout để xem bằng `docker compose logs`. |
| `security/cors` | **CORS** (Cross-Origin Resource Sharing) quyết định trình duyệt có cho web ở domain khác gọi API hay không. `"*"` cho phép mọi nguồn, **chỉ nên dùng khi học/phát triển**; môi trường thật hãy liệt kê domain cụ thể. |
| `endpoints` | Danh sách API mà gateway công bố ra ngoài cho client. |
| `endpoint` / `method` | Đường dẫn và phương thức mà client gọi vào gateway. |
| `backend` | Dịch vụ phía sau mà gateway gọi thay cho client. `host` là địa chỉ máy chủ, `url_pattern` là đường dẫn trên backend đó. |

Ví dụ ở trên: client gọi `GET http://localhost:8080/hello`, KrakenD sẽ gọi `GET https://jsonplaceholder.typicode.com/posts/1` rồi trả kết quả về.

## 6. Chạy và kiểm tra

**Bước 1 – Kiểm tra cú pháp cấu hình trước khi chạy** (tùy chọn nhưng nên làm):

```bash
docker compose run --rm krakend check -c /etc/krakend/krakend.json
```

Kết quả mong đợi có dòng báo cấu hình hợp lệ ("Syntax OK").

**Bước 2 – Khởi động:**

```bash
docker compose up -d
```

`-d` (detached) chạy nền, không chiếm cửa sổ terminal.

**Bước 3 – Xem log:**

```bash
docker compose logs -f krakend
```

`-f` (follow) theo dõi log liên tục, thoát bằng `Ctrl + C`.

**Bước 4 – Gọi thử API:**

```bash
# Endpoint mặc định có sẵn của KrakenD để kiểm tra gateway còn sống
curl http://localhost:8080/__health

# Endpoint bạn vừa khai báo
curl http://localhost:8080/hello
```

Kết quả `/hello` là một JSON của bài viết số 1 (`userId`, `id`, `title`, `body`).

**Bước 5 – Dừng và xóa container:**

```bash
docker compose down
```

### Lỗi thường gặp

| Hiện tượng | Nguyên nhân & cách xử lý |
|---|---|
| `404 page not found` khi gọi `/hello` | Chưa khai báo endpoint trong `endpoints` (mảng rỗng `[]` thì gateway không có API nào). |
| `services must be a mapping` / `unknown key` | Gõ sai khóa YAML (ví dụ `service`, `enviroment`). Đúng là `services`, `environment`. |
| `network myservice declared as external, but could not be found` hoặc `undefined network` | Quên khai báo `networks` ở cấp cao nhất. |
| Container thoát ngay sau khi chạy | Xem `docker compose logs krakend`, thường do JSON sai cú pháp hoặc sai đường dẫn file cấu hình. |
| Sửa `krakend.json` nhưng không thấy đổi | Cần khởi động lại: `docker compose restart krakend`. |

## 7. Flexible Configuration (cấu hình linh hoạt)

Khi dự án lớn dần, file `krakend.json` sẽ dài và lặp lại. **Flexible Configuration (FC)** cho phép dùng *template* (cú pháp Go template `{{ ... }}`) để:

- Tách giá trị thay đổi theo môi trường (dev/staging/prod) ra file riêng.
- Tái sử dụng các đoạn cấu hình lặp lại.

### 7.1. Các biến môi trường của FC

| Biến | Ý nghĩa |
|---|---|
| `FC_ENABLE=1` | Bật tính năng Flexible Configuration. Không đặt biến này thì KrakenD coi file cấu hình là JSON thuần. |
| `FC_SETTINGS` | Thư mục chứa các file **settings** (`.json`) – nơi lưu *giá trị* (cổng, host backend, timeout...). Tên file trở thành tên biến trong template, ví dụ `env.json` được dùng bằng `{{ .env.ten_bien }}`. |
| `FC_PARTIALS` | Thư mục chứa các **partial** – đoạn văn bản tĩnh được chèn nguyên văn vào cấu hình bằng `{{ include "ten_file" }}`. |
| `FC_TEMPLATES` | Thư mục chứa các **template** – đoạn cấu hình có thể chứa logic và tham số, được gọi bằng `{{ template "ten" . }}`. |
| `FC_OUT` | (Tùy chọn) Ghi cấu hình **sau khi render** ra một file, giúp bạn kiểm tra kết quả khi debug. |

### 7.2. Cập nhật `docker-compose.yml`

```yaml
services:
  krakend:
    image: krakend:2.10
    container_name: krakend
    command: run -c /etc/krakend/krakend.tmpl
    volumes:
      - ./krakend_config:/etc/krakend/
    ports:
      - "8080:8080"
    environment:
      - FC_ENABLE=1                                        # Bật Flexible Configuration
      - FC_SETTINGS=/etc/krakend/config/settings/          # Thư mục settings
      - FC_PARTIALS=/etc/krakend/config/partials/          # Thư mục partials
      - FC_TEMPLATES=/etc/krakend/config/templates/        # Thư mục templates
      - FC_OUT=/etc/krakend/output.json                    # Ghi cấu hình đã render để debug
    networks:
      - myservice
    restart: unless-stopped

networks:
  myservice:
    driver: bridge
```

> **Chú ý:** `command` trỏ đến file `krakend.tmpl` (file template gốc), **không phải** `krakend.json`. Đường dẫn trong `FC_*` là đường dẫn **bên trong container** (do volume gắn `./krakend_config` thành `/etc/krakend/`).

### 7.3. Ví dụ minh họa

**`krakend_config/config/settings/env.json`** – các giá trị thay đổi theo môi trường:

```json
{
  "port": 8080,
  "timeout": "20s",
  "backend_host": "https://jsonplaceholder.typicode.com"
}
```

**`krakend_config/config/partials/logging.tmpl`** – đoạn log dùng chung (chèn nguyên văn):

```text
"telemetry/logging": {
  "level": "INFO",
  "prefix": "[KRAKEND]",
  "syslog": false,
  "stdout": true,
  "format": "default"
}
```

**`krakend_config/krakend.tmpl`** – file cấu hình gốc, ghép mọi thứ lại:

```text
{
  "$schema": "https://www.krakend.io/schema/krakend.json",
  "version": 3,
  "port": {{ .env.port }},
  "timeout": "{{ .env.timeout }}",
  "extra_config": {
    {{ include "logging.tmpl" }}
  },
  "endpoints": [
    {
      "endpoint": "/hello",
      "method": "GET",
      "backend": [
        {
          "host": ["{{ .env.backend_host }}"],
          "url_pattern": "/posts/1"
        }
      ]
    }
  ]
}
```

Khi chạy, KrakenD thay `{{ .env.port }}` bằng `8080`, chèn nội dung `logging.tmpl`, rồi ghi kết quả cuối cùng ra `output.json` (nhờ `FC_OUT`). Muốn đổi sang môi trường khác, chỉ cần đổi file settings, không sửa file cấu hình chính.

> **Mẹo:** Mở `krakend_config/output.json` để xem cấu hình thực tế sau khi render. Đây là cách nhanh nhất để tìm lỗi template. Hãy thêm `output.json` vào `.gitignore`.

## 8. Mở rộng

### 8.1. Xác thực bằng API Key (chỉ có ở bản Enterprise)

Đoạn cấu hình `auth/api-keys` dưới đây **chỉ hoạt động với KrakenD Enterprise Edition (trả phí)**; bản Community miễn phí không có tính năng này.

```json
"auth/api-keys": {
  "strategy": "header",
  "identifier": "X-Key",
  "hash": "fnv128",
  "salt": "Senior",
  "@hashed-with": "https://go.dev/play/p/hHksLLCUJy3",
  "keys": [
    {
      "@key-plain": "YourKeyPlain",
      "key": "YourKey",
      "roles": ["all"],
      "@description": "ACME Inc."
    }
  ]
}
```

Giải thích:

- `strategy` / `identifier`: lấy key từ header HTTP tên `X-Key`.
- `hash` / `salt`: key được **băm** (hash) cùng "muối" (salt) để không lưu key gốc dạng văn bản thô.
- `key`: giá trị **đã băm** của key gốc (`@key-plain` chỉ là ghi chú cho người đọc, nên xóa khi triển khai thật).
- `roles`: nhóm quyền của key.
- Khóa bắt đầu bằng `@` là **ghi chú**, KrakenD bỏ qua.
- Ngoài khai báo ở cấp service như trên, mỗi endpoint cần bật xác thực trong `extra_config` của endpoint đó (xem tài liệu API Keys ở phần Tài liệu tham khảo).

> **Cảnh báo bảo mật:** `salt` và key trong ví dụ chỉ để minh họa. Trên môi trường thật, hãy dùng giá trị ngẫu nhiên, dài và không commit lên Git (nên nạp qua settings/biến môi trường).

### 8.2. Giải pháp thay thế miễn phí: xác thực JWT

Bản Community hỗ trợ kiểm tra **JWT** (JSON Web Token) bằng `auth/validator`, đặt trong `extra_config` của **endpoint**:

```json
"extra_config": {
  "auth/validator": {
    "alg": "RS256",
    "jwk_url": "https://your-auth-server/.well-known/jwks.json"
  }
}
```

Client gửi header `Authorization: Bearer <token>`; KrakenD kiểm tra chữ ký token trước khi chuyển request đến backend.

### 8.3. Hướng học tiếp

- **Nhiều backend, một endpoint (aggregation):** khai báo nhiều phần tử trong `backend` để gộp dữ liệu thành một response.
- **Rate limiting:** giới hạn số request mỗi giây để chống lạm dụng (`qos/ratelimit/router`).
- **Gateway + backend thật trong Compose:** thêm service backend vào cùng network `myservice`, khi đó `host` có thể là tên service, ví dụ `["http://my-api:3000"]`.
- **Tắt chế độ debug và siết CORS** trước khi đưa lên production.
- **Công cụ thiết kế trực quan:** KrakenD Designer giúp tạo cấu hình bằng giao diện.

## 9. Tóm tắt

1. Tạo `docker-compose.yml` (khai báo `services`, `ports`, `volumes`, `networks`).
2. Tạo `krakend_config/krakend.json` với ít nhất một endpoint.
3. Chạy `docker compose up -d`, kiểm tra bằng `docker compose logs -f krakend` và `curl`.
4. Khi cấu hình phức tạp, chuyển sang Flexible Configuration (`FC_*`).
