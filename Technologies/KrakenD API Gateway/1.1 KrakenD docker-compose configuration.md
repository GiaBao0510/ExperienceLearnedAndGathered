## 1. API Gateway và KrakenD là gì?

**API Gateway** là "cổng vào duy nhất" đứng trước các dịch vụ backend. Client (web, mobile) chỉ gọi gateway; gateway chuyển tiếp request đến đúng backend, đồng thời xử lý các việc chung như xác thực, giới hạn tốc độ, CORS, ghi log.

**Ví dụ đời thường:** gateway giống quầy lễ tân của một tòa nhà văn phòng. Khách không đi thẳng vào từng phòng, mà qua lễ tân để được kiểm tra và chỉ đường.

**KrakenD** là một API Gateway mã nguồn mở, cấu hình bằng file (không cần database). Nếu bạn đang học AWS, có thể xem KrakenD là lựa chọn tự vận hành tương tự vai trò của **Amazon API Gateway** (dịch vụ gateway được AWS quản lý). KrakenD có thể chạy dưới dạng container, ví dụ trên ECS/EKS, và có tích hợp telemetry với AWS X-Ray [[1]](#trích-dẫn).

> **Lưu ý về phiên bản:** KrakenD có hai bản: **Community Edition (CE)** miễn phí và **Enterprise Edition (EE)** trả phí. Một số tính năng (ví dụ API Key ở mục 9) chỉ có ở EE [[2]](#trích-dẫn).

## 2. Chuẩn bị

- Kiến thức cơ bản về Docker (image, container, volume, port).
- Cài **Docker Desktop** (đã kèm Docker Compose v2, dùng lệnh `docker compose`).
- Một thư mục làm việc trống, ví dụ `krakend-demo/`.

## 3. Cấu trúc thư mục

Tạo cấu trúc sau (thư mục `krakend_config` sẽ được mount vào container tại `/etc/krakend/`):

```text
krakend-demo/
├── docker-compose.yml
└── krakend_config/
    ├── krakend.tmpl              # file cấu hình gốc (template)
    └── config/
        ├── settings/
        │   └── service.json      # các giá trị dùng chung (timeout, cache...)
        ├── partials/             # đoạn văn bản chèn nguyên văn (có thể để trống)
        └── templates/            # template dùng lại (có thể để trống)
```

Tạo nhanh bằng lệnh:

```bash
mkdir -p krakend_config/config/{settings,partials,templates}
```

## 4. Tạo file `docker-compose.yml`

```yaml
services:
  krakend:
    image: krakend:2.13          # nên ghim phiên bản, tránh dùng "latest"
    container_name: krakend
    command: ["run", "-dc", "/etc/krakend/krakend.tmpl"]
    volumes:
      - ./krakend_config:/etc/krakend/
    ports:
      - "8080:8080"
    environment:
      - FC_ENABLE=1                                   # bật Flexible Configuration
      - FC_SETTINGS=/etc/krakend/config/settings/     # thư mục settings
      - FC_PARTIALS=/etc/krakend/config/partials/     # thư mục partials
      - FC_TEMPLATES=/etc/krakend/config/templates/   # thư mục templates
      - FC_OUT=/tmp/krakend-out.json                  # (tùy chọn) xuất cấu hình cuối để debug
    networks:
      - myservice
    restart: unless-stopped

networks:
  myservice:
```

### Giải thích từng phần

| Thành phần | Ý nghĩa |
|---|---|
| `image: krakend:2.13` | Image chính thức của KrakenD trên Docker Hub. Ghim phiên bản để môi trường lặp lại được [[3]](#trích-dẫn). |
| `command` | Lệnh chạy bên trong container. `run` khởi động gateway; `-c` chỉ đường dẫn file cấu hình; `-d` bật chế độ debug (**chỉ dùng khi học/dev**, không bật ở production). |
| `volumes` | Gắn thư mục `./krakend_config` trên máy bạn vào `/etc/krakend/` trong container. Sửa file trên máy là container thấy ngay. |
| `ports: "8080:8080"` | Mở cổng 8080 của container ra cổng 8080 của máy bạn. Địa chỉ truy cập: `http://localhost:8080`. |
| `environment` | Truyền biến môi trường để bật và cấu hình Flexible Configuration (xem mục 5). |
| `networks` | Gắn container vào mạng `myservice`. Mạng này **phải được khai báo** ở khối `networks:` cuối file, nếu không Compose sẽ báo lỗi. Hữu ích khi các service khác (backend, database) dùng chung mạng. |
| `restart: unless-stopped` | Tự khởi động lại container nếu nó lỗi hoặc Docker khởi động lại, trừ khi bạn chủ động dừng. |

## 5. Flexible Configuration (FC) và các biến `FC_*`

Mặc định, KrakenD đọc **một** file cấu hình. Khi cấu hình lớn dần, bạn muốn chia nhỏ thành nhiều file và dùng lại giá trị. **Flexible Configuration** cho phép điều đó: file cấu hình gốc được xử lý như một **Go template**, trong đó `{{ ... }}` là chỗ KrakenD điền giá trị vào [[4]](#trích-dẫn).

| Biến | Ý nghĩa |
|---|---|
| `FC_ENABLE` | Bật Flexible Configuration. Đặt `1` (hoặc giá trị bất kỳ; lưu ý `0` **không** tắt được tính năng). |
| `FC_SETTINGS` | Thư mục chứa các file JSON "giá trị", giống file `.env` nhưng có thể lồng nhau, chia nhiều file. |
| `FC_PARTIALS` | Thư mục chứa các đoạn văn bản **không được xử lý**, chèn nguyên văn vào cấu hình. |
| `FC_TEMPLATES` | Thư mục chứa các template dùng lại, được xử lý bằng Go template. |
| `FC_OUT` | Đường dẫn file ghi lại cấu hình **sau khi render**. Chỉ phục vụ debug, không bắt buộc khi chạy. |

**Ví dụ:** file `settings/service.json` có nội dung `{ "timeout": "20000ms" }` thì trong `krakend.tmpl` bạn viết `"timeout": "{{ .service.timeout }}"`. Tên file (`service`) trở thành tiền tố để truy cập giá trị.

> Nếu bạn chưa cần chia nhỏ cấu hình, vẫn có thể bỏ toàn bộ biến `FC_*` và dùng một file `krakend.json` thông thường.

## 6. Tạo các file cấu hình KrakenD

### 6.1. `krakend_config/config/settings/service.json`

```json
{
  "timeout": "20000ms",
  "cache_ttl": "300s"
}
```

### 6.2. `krakend_config/krakend.tmpl`

```text
{
  "$schema": "https://www.krakend.io/schema/v3.json",
  "version": 3,
  "timeout": "{{ .service.timeout }}",
  "cache_ttl": "{{ .service.cache_ttl }}",
  "extra_config": {
    "telemetry/logging": {
      "level": "INFO",
      "prefix": "[KRAKEND]",
      "syslog": false,
      "stdout": true,
      "format": "default"
    },
    "security/cors": {
      "allow_origins": ["*"],
      "allow_methods": ["GET", "POST", "PUT", "DELETE"],
      "expose_headers": ["Content-Length", "Content-Type"],
      "allow_headers": ["Accept-Language"],
      "max_age": "12h",
      "allow_credentials": false,
      "debug": false
    }
  },
  "endpoints": [
    {
      "endpoint": "/hello",
      "method": "GET",
      "output_encoding": "json",
      "backend": [
        {
          "host": ["https://jsonplaceholder.typicode.com"],
          "url_pattern": "/posts/1"
        }
      ]
    }
  ]
}
```

### Giải thích các khối chính

| Khóa | Ý nghĩa |
|---|---|
| `version` | Phiên bản **định dạng** file cấu hình (không phải phiên bản KrakenD). Giá trị `3` đi cùng dòng KrakenD 2.x. Tài liệu của KrakenD 3.0 dùng `version: 4`, nên hãy khớp `version` với tag image bạn chọn [[2]](#trích-dẫn). |
| `timeout` | Thời gian tối đa gateway chờ backend trả lời. |
| `cache_ttl` | Thời gian giữ cache phản hồi của backend (TTL = time to live). |
| `telemetry/logging` | Cấu hình ghi log. `stdout: true` để xem log bằng `docker compose logs`. |
| `security/cors` | CORS (Cross-Origin Resource Sharing) quy định trình duyệt từ domain nào được gọi API. `"*"` là cho phép mọi domain, **chỉ nên dùng khi học/dev**; production hãy liệt kê domain cụ thể. |
| `endpoints` | Danh sách API mà gateway **công khai ra ngoài**. Danh sách rỗng nghĩa là gateway chưa có API nào để gọi. |
| `endpoint` / `backend` | `endpoint` là đường dẫn client gọi (`/hello`). `backend` là dịch vụ thật phía sau (`host` + `url_pattern`). |

**Luồng hoạt động của ví dụ:**

```text
Client ──GET /hello──▶ KrakenD (localhost:8080) ──GET /posts/1──▶ jsonplaceholder.typicode.com
Client ◀──────────────── JSON ──────────────────┘
```

## 7. Chạy, kiểm tra log và test API

**Bước 1: kiểm tra cú pháp cấu hình** (nên làm trước khi chạy):

```bash
docker compose run --rm krakend check -c /etc/krakend/krakend.tmpl
```

Kết quả mong đợi có dòng `Syntax OK!`.

**Bước 2: khởi động** (chế độ nền):

```bash
docker compose up -d
```

**Bước 3: xem log** (thoát bằng `Ctrl + C`):

```bash
docker compose logs -f krakend
```

**Bước 4: test API:**

```bash
# Endpoint do bạn định nghĩa, trả về dữ liệu JSON từ backend
curl http://localhost:8080/hello

# Endpoint kiểm tra sức khỏe có sẵn của KrakenD
curl http://localhost:8080/__health
```

> Gateway chỉ có endpoint `/hello` **sau khi** bạn khai báo nó trong `endpoints`. Với danh sách rỗng, gọi `/hello` sẽ nhận lỗi `404`.

**Xem cấu hình sau khi render** (do `FC_OUT`):

```bash
docker compose exec krakend cat /tmp/krakend-out.json
```

**Dừng và xóa container:**

```bash
docker compose down
```

## 8. Xử lý lỗi thường gặp

| Triệu chứng | Nguyên nhân thường gặp | Cách xử lý |
|---|---|---|
| Compose báo lỗi về `service`/`enviroment` | Gõ sai tên khóa (đúng là `services`, `environment`) | Sửa chính tả khóa trong YAML |
| `service "krakend" refers to undefined network myservice` | Dùng `networks` ở service nhưng chưa khai báo ở cấp cao nhất | Thêm khối `networks: myservice:` cuối file |
| `404` khi gọi `/hello` | Chưa khai báo endpoint | Thêm endpoint vào `endpoints` |
| Lỗi đọc cấu hình, không tìm thấy file | `command` trỏ sai tên file (`.tmpl` vs `.json`) | Đảm bảo tên trong `command` khớp tên file thật |
| Lỗi quyền khi ghi `FC_OUT` | Container chạy bằng user không phải root, không ghi được vào thư mục mount | Ghi ra `/tmp` như ví dụ ở trên [[3]](#trích-dẫn) |

## 9. Phần mở rộng: bảo vệ endpoint bằng API Key (chỉ bản Enterprise)

Nếu bạn dùng **KrakenD Enterprise**, có thể yêu cầu client gửi API Key. Việc này gồm hai bước [[2]](#trích-dẫn):

**Bước 1:** khai báo danh sách key và vai trò (role) ở cấp gốc `extra_config`:

```json
"auth/api-keys": {
  "strategy": "header",
  "identifier": "X-Key",
  "hash": "fnv128",
  "salt": "mySalt",
  "keys": [
    {
      "@description": "ACME Inc.",
      "key": "<giá trị đã băm>",
      "roles": ["all"]
    }
  ]
}
```

**Bước 2:** gắn bảo vệ vào từng endpoint cần bảo vệ (endpoint nào không khai báo thì vẫn công khai):

```json
{
  "endpoint": "/hello",
  "backend": [ { "host": ["https://jsonplaceholder.typicode.com"], "url_pattern": "/posts/1" } ],
  "extra_config": {
    "auth/api-keys": { "roles": ["all"] }
  }
}
```

Điểm cần nhớ:

- Khi dùng `hash` khác `plain`, trường `key` trong cấu hình phải là **giá trị đã băm** của chuỗi `salt + api_key`; client vẫn gửi key gốc.
- Trong khối CORS, hãy thêm `X-Key` vào `allow_headers` nếu client là trình duyệt, nếu không request sẽ bị chặn.
- Gọi thử: `curl -H "X-Key: <key gốc>" http://localhost:8080/hello`. Sai key hoặc sai role sẽ nhận `401 Unauthorized`.

### Mở rộng

- **Biến thành image bất biến (immutable image):** viết `Dockerfile` copy cấu hình vào image thay vì mount volume, để rollback an toàn hơn (khuyến nghị của KrakenD cho production).
- **Chạy trên AWS:** triển khai KrakenD trên ECS/Fargate hoặc EKS, đặt sau Application Load Balancer; so sánh với Amazon API Gateway (chi phí, mức độ quản lý, tính năng).
- **Xác thực với JWT** (có ở bản Community) và tích hợp Keycloak/Auth0.
- **Rate limiting, Circuit Breaker** để bảo vệ backend khi quá tải.
- **Gộp dữ liệu (API composition/aggregation):** một endpoint gọi nhiều backend rồi trả về một phản hồi.
- **Quan sát hệ thống (observability):** Prometheus, Grafana, OpenTelemetry, AWS X-Ray.
- **Hot reload với image `krakend:watch`** để sửa cấu hình mà không cần khởi động lại thủ công.
- **TLS/HTTPS** cho gateway và **Docker Compose profiles/`.env`** để quản lý nhiều môi trường (dev/prod).
