## **Docker Engine**

![](https://media2.dev.to/dynamic/image/width=800%2Cheight=%2Cfit=scale-down%2Cgravity=auto%2Cformat=auto/https%3A%2F%2Fdev-to-uploads.s3.amazonaws.com%2Fuploads%2Farticles%2Fwniavj37cpvw4qrosgff.jpg)

Docker Engine là nền tảng chính để chạy container, với kiến trúc **client-server**.

Có hai phiên bản chính:
- **Docker Community Edition (CE)**: Phiên bản **miễn phí**, mã nguồn mở, phù hợp cho sinh viên, lập trình viên cá nhân và đội ngũ nhỏ để học tập, phát triển ứng dụng container.

- **Docker Enterprise Edition (EE)**: Phiên bản **trả phí** dành cho doanh nghiệp lớn, cung cấp thêm tính năng quản lý cluster, bảo mật nâng cao, giám sát và hỗ trợ chuyên nghiệp.

Các thành phần chính của Docker Engine gồm: 
- **Server** hay còn gọi là **docker daemon (dockerd):** chịu trách nhiệm tạo, quản lý các Docker object như images, containers, networks, volume.
- **REST API:** docker daemon cung cấp các api cho Client sử dụng để thao tác với Docker
- **Client** là thành phần đầu cuối cung cấp một tập hợp các câu lệnh để sử dụng api để người dùng có thể thao tác với Docker ( *ví dụ docker image, docker ps,...*)

## **Kiến trúc Docker**

![](https://miro.medium.com/0*G82uZfX0ozIih3-_)

Docker sử dụng kiến trúc client-server. **Docker server** (hay còn gọi là **Daemon**) sẽ chịu trách nhiệm cho việc build, run, distrubute Docker Container. Docker client và Docker Server có thể nằm trên cùng một server hoặc khác server. Chúng giao tiếp với nhau thông quan REST API dựa trên UNIX sockets hoặc network interface.

---
## **Docker daemon**

**Docker deamon (dockerd)** là thành phần **core**, lắng nghe **API request** và quản lý các Docker object. **Docker daemon host** này cũng có thể giao tiếp được với Docker daemon ơ host khác

---
## **Docker registry**

Docker rgistry là một kho chứa các Image. Nổi tiếng nhất là Docker hub, ngoài ra bạn có thể tự xây dựng một Docker registry cho riêng mình

---
### **Images**

**Image** là một template read-only sử dụng để chạy **container**.

Một image có thể base trên một image khác. Ví dụ bạn muốn tạo một image nginx, tất nhiên nginx phải chạy trên linux ubuntu chẳng hạn. Khi đó image nginx trước hết sẽ phải base trên ubuntu trước đã.
Bạn có thể tự build image cho riêng mình hoặc tải các image có sẵn của người khác trên Docker registry.

---

**Container**

Container được chạy dựa trên 1 image cụ thể. Bạn có thể tạo, start, stop, move, delete container.

Bạn cũng có thể kết nối các container với nhau hoặc attach storage cho nó, thậm chí là tạo lại một image từ chính state hiện tại của container

Container cô lập tài nguyên với host và các container khác.
