## 1. Interactive và Terminal Parameters

### 1.1. `-i` (--interactive)

**Mục đích:** Duy trì STDIN mở, cho phép tương tác với container.

**Khi nào dùng:**

- Cần nhập lệnh vào container
- Chạy shell interactively
- Chạy scripts cần input

**Ví dụ 1: Không dùng -i (không tương tác được)**

```bash
docker run ubuntu bash
```

**Kết quả:** Container khởi động và thoát ngay, không làm gì được.

**Ví dụ 2: Dùng -i (tương tác được)**

```bash
docker run -i ubuntu bash
```

**Kết quả:** Có thể nhập lệnh, nhưng không hiển thị prompt đẹp.

```bash
ls
# Output: bin boot dev etc home lib...
pwd
# Output: /
```

### 1.2. `-t` (--tty)

**Mục đích:** Cấp phát pseudo-TTY (terminal ảo), hiển thị prompt và format đẹp.

**Ví dụ: So sánh -i vs -i -t**

**Chỉ dùng -i:**

```bash
docker run -i ubuntu bash
```

```
ls
bin
boot
dev
# Không có prompt, khó biết đang ở đâu
```

**Dùng -i -t (hoặc -it):**

```bash
docker run -it ubuntu bash
```

```
root@a1b2c3d4e5f6:/# ls
bin  boot  dev  etc  home  lib  lib32  lib64
root@a1b2c3d4e5f6:/# pwd
/
root@a1b2c3d4e5f6:/# 
```

**So sánh:**

|Tham số|STDIN|Terminal|Prompt|Use Case|
|---|---|---|---|---|
|Không có|❌|❌|❌|Chạy lệnh đơn|
|`-i`|✅|❌|❌|Scripts cần input|
|`-t`|❌|✅|✅|Hiển thị đẹp|
|`-it`|✅|✅|✅|**Interactive shell**|

**Ví dụ thực tế:**

```bash
# Vào shell của Ubuntu
docker run -it ubuntu bash

# Vào shell của Alpine (nhẹ hơn)
docker run -it alpine sh

# Chạy Python interactive
docker run -it python:3.11 python

# Vào bash của container đang chạy
docker exec -it my-container bash
```

## 2. Container Lifecycle Parameters

### 2.1. `--rm` (Auto Remove)

**Mục đích:** Tự động xóa container khi nó dừng.

**Khi nào dùng:**

- Test nhanh
- Chạy một lần rồi xóa
- Tiết kiệm disk space

**Ví dụ 1: Không dùng --rm**

```bash
docker run ubuntu echo "Hello World"
```

**Kết quả:**

```
Hello World
```

**Kiểm tra:**

```bash
docker ps -a
```

```
CONTAINER ID   IMAGE    COMMAND              CREATED         STATUS                     
a1b2c3d4e5f6   ubuntu   "echo 'Hello...'"    5 seconds ago   Exited (0) 4 seconds ago
```

> Container vẫn còn! Phải xóa thủ công.

**Ví dụ 2: Dùng --rm**

```bash
docker run --rm ubuntu echo "Hello World"
```

**Kết quả:**

```
Hello World
```

**Kiểm tra:**

```bash
docker ps -a
```

```
CONTAINER ID   IMAGE    COMMAND   CREATED   STATUS
(trống - container đã tự động xóa)
```

> Container tự động xóa sau khi chạy xong!

**Ví dụ thực tế:**

```bash
# Test một image nhanh
docker run --rm nginx nginx -v
# Output: nginx version: nginx/1.25.3

# Chạy script Python một lần
docker run --rm -v $(pwd):/app python:3.11 python /app/script.py

# Test database connection
docker run --rm mysql:8.0 mysql --version
# Output: mysql  Ver 8.0.35 for Linux on x86_64
```

### 2.2. `-d` (--detach)

**Mục đích:** Chạy container ở chế độ nền (background).

**So sánh foreground vs background:**

**Foreground (không có -d):**

```bash
docker run nginx
```

```
/docker-entrypoint.sh: Configuration complete; ready for start up
2024/03/03 10:30:45 [notice] 1#1: using the "epoll" event method
2024/03/03 10:30:45 [notice] 1#1: nginx/1.25.3
2024/03/03 10:30:45 [notice] 1#1: start worker processes
# Terminal bị block, không làm gì được
# Phải Ctrl+C để thoát
```

**Background (dùng -d):**

```bash
docker run -d nginx
```

```
a1b2c3d4e5f6a7b8c9d0e1f2g3h4i5j6k7l8m9n0o1p2q3r4s5t6
```

> Trả về Container ID và terminal tự do!

**Kiểm tra container chạy nền:**

```bash
docker ps
```

```
CONTAINER ID   IMAGE   COMMAND                  STATUS         PORTS
a1b2c3d4e5f6   nginx   "/docker-entrypoint..."  Up 10 seconds  80/tcp
```

**Xem logs container chạy nền:**

```bash
docker logs a1b2c3d4e5f6
```

**Ví dụ thực tế:**

```bash
# Web server
docker run -d -p 8080:80 --name web nginx

# Database
docker run -d -e MYSQL_ROOT_PASSWORD=pass123 --name db mysql:8.0

# Redis cache
docker run -d -p 6379:6379 --name cache redis

# Kết hợp nhiều tham số
docker run -d -p 3000:3000 -v $(pwd):/app --name myapp node:18
```

### 2.3. `-f` (--force)

**Mục đích:** Xóa container đang chạy mà không cần dừng trước.

**Cách thông thường (2 bước):**

```bash
# Bước 1: Dừng
docker stop my-container
# my-container

# Bước 2: Xóa
docker rm my-container
# my-container
```

**Dùng -f (1 bước):**

```bash
docker rm -f my-container
```

**Output:**

```
my-container
```

**Ví dụ: Xóa container đang chạy**

```bash
# Tạo và chạy container
docker run -d --name test-nginx nginx

# Kiểm tra
docker ps
# CONTAINER ID   IMAGE   STATUS        NAMES
# a1b2c3d4e5f6   nginx   Up 5 seconds  test-nginx

# Xóa không force (bị lỗi)
docker rm test-nginx
# Error: You cannot remove a running container... Stop the container before attempting removal or force remove

# Xóa với force (thành công)
docker rm -f test-nginx
# test-nginx

# Kiểm tra lại
docker ps -a
# (trống)
```

**Ví dụ: Xóa nhiều containers**

```bash
# Xóa tất cả containers đang chạy
docker rm -f $(docker ps -aq)

# Xóa containers theo pattern
docker rm -f $(docker ps -a | grep "test-" | awk '{print $1}')
```

### 2.4. `--name`

**Mục đích:** Đặt tên cho container (dễ nhớ hơn ID).

**Không dùng --name:**

```bash
docker run -d nginx
# a1b2c3d4e5f6
```

**Sử dụng:**

```bash
docker stop a1b2c3d4e5f6  # Khó nhớ!
docker logs a1b2c3d4e5f6
```

**Dùng --name:**

```bash
docker run -d --name web-server nginx
# a1b2c3d4e5f6
```

**Sử dụng:**

```bash
docker stop web-server      # Dễ nhớ!
docker logs web-server
docker exec -it web-server bash
```

**Quy tắc đặt tên:**

- Chữ cài, số, gạch ngang `-`, gạch dưới `_`
- Không dùng dấu cách
- Phải unique (không trùng)

**Ví dụ thực tế:**

```bash
# Môi trường dev
docker run -d --name dev-web nginx
docker run -d --name dev-db mysql:8.0
docker run -d --name dev-redis redis

# Môi trường staging
docker run -d --name staging-web nginx
docker run -d --name staging-db mysql:8.0

# Theo dự án
docker run -d --name blog-frontend nginx
docker run -d --name blog-backend node:18
docker run -d --name blog-database postgres:15
```

## 3. Volume và Storage Parameters

### 3.1. `-v` (Volume Mount)

**Mục đích:** Mount thư mục/file từ host vào container.

**Cú pháp:**

```bash
-v host_path:container_path[:options]
```

**Ví dụ 1: Mount thư mục**

```bash
# Tạo thư mục trên host
mkdir -p /home/user/html
echo "<h1>Hello Docker</h1>" > /home/user/html/index.html

# Mount vào nginx
docker run -d -p 8080:80 -v /home/user/html:/usr/share/nginx/html --name web nginx
```

**Test:**

```bash
curl http://localhost:8080
```

**Output:**

```html
<h1>Hello Docker</h1>
```

**Thay đổi trên host:**

```bash
echo "<h1>Updated!</h1>" > /home/user/html/index.html
```

**Kiểm tra lại:**

```bash
curl http://localhost:8080
```

**Output:**

```html
<h1>Updated!</h1>
```

> Thay đổi trên host → tự động cập nhật trong container!

**Ví dụ 2: Mount read-only**

```bash
docker run -d -v /home/user/config:/etc/nginx:ro nginx
```

**Giải thích:**

- `:ro` = read-only
- Container chỉ đọc, không ghi được

**Ví dụ 3: Named Volume**

```bash
# Tạo volume
docker volume create my-data

# Dùng volume
docker run -d -v my-data:/data --name app1 ubuntu
docker run -d -v my-data:/data --name app2 ubuntu

# app1 và app2 share cùng data!
```

**Ví dụ thực tế:**

```bash
# Development: Mount source code
docker run -d -p 3000:3000 \
  -v $(pwd)/src:/app/src \
  --name dev-app node:18

# Database: Persist data
docker run -d \
  -v mysql-data:/var/lib/mysql \
  -e MYSQL_ROOT_PASSWORD=pass123 \
  --name db mysql:8.0

# Config files
docker run -d \
  -v $(pwd)/nginx.conf:/etc/nginx/nginx.conf:ro \
  --name web nginx

# Logs
docker run -d \
  -v $(pwd)/logs:/var/log/nginx \
  --name web-logs nginx
```

### 3.2. `--mount`

**Mục đích:** Cách mới, rõ ràng và linh hoạt hơn `-v`.

**Cú pháp:**

```bash
--mount type=TYPE,source=SOURCE,target=TARGET[,options]
```

**Types:**

- `bind`: Mount từ host
- `volume`: Dùng Docker volume
- `tmpfs`: Mount vào RAM

**Ví dụ 1: Bind mount**

```bash
docker run -d \
  --mount type=bind,source=/home/user/html,target=/usr/share/nginx/html \
  --name web nginx
```

**Tương đương với:**

```bash
docker run -d -v /home/user/html:/usr/share/nginx/html --name web nginx
```

**Ví dụ 2: Volume mount**

```bash
docker run -d \
  --mount type=volume,source=my-vol,target=/data \
  --name app ubuntu
```

**Ví dụ 3: Read-only bind mount**

```bash
docker run -d \
  --mount type=bind,source=$(pwd)/config,target=/etc/app,readonly \
  --name app myapp:latest
```

**Ví dụ 4: tmpfs (RAM)**

```bash
docker run -d \
  --mount type=tmpfs,target=/tmp \
  --name fast-app myapp:latest
```

> Data lưu trong RAM, mất khi container dừng, nhưng rất nhanh!

**So sánh -v vs --mount:**

|Feature|`-v`|`--mount`|
|---|---|---|
|Cú pháp|Ngắn gọn|Rõ ràng|
|Tạo folder tự động|✅|❌|
|Nhiều options|❌|✅|
|Production|OK|✅ Recommended|

**Ví dụ thực tế với --mount:**

```bash
# Web app với nhiều mounts
docker run -d \
  --name webapp \
  --mount type=bind,source=$(pwd)/app,target=/app \
  --mount type=bind,source=$(pwd)/config,target=/config,readonly \
  --mount type=volume,source=app-data,target=/data \
  --mount type=tmpfs,target=/tmp \
  -p 3000:3000 \
  node:18
```

### 3.3. `--volumes-from`

**Mục đích:** Chia sẻ volumes từ container khác.

**Ví dụ: Data container pattern**

```bash
# Bước 1: Tạo data container
docker create -v /data --name data-store alpine

# Bước 2: App 1 dùng data từ data-store
docker run -d --volumes-from data-store --name app1 nginx

# Bước 3: App 2 cũng dùng data từ data-store
docker run -d --volumes-from data-store --name app2 nginx

# App 1 và App 2 share cùng /data folder!
```

**Ví dụ: Backup container**

```bash
# Container chính
docker run -d -v my-data:/data --name main-app alpine

# Backup container share volume với main-app
docker run --rm \
  --volumes-from main-app \
  -v $(pwd):/backup \
  alpine \
  tar czf /backup/backup.tar.gz /data
```

**Giải thích:**

1. Backup container mount volume từ `main-app`
2. Mount thư mục host vào `/backup`
3. Nén `/data` → `/backup/backup.tar.gz`
4. `--rm`: Tự xóa sau khi backup xong

**Restore:**

```bash
docker run --rm \
  --volumes-from main-app \
  -v $(pwd):/backup \
  alpine \
  sh -c "cd / && tar xzf /backup/backup.tar.gz"
```

## 4. Network Parameters

### 4.1. `-p` (Port Publish)

**Mục đích:** Map port từ container ra host.

**Cú pháp:**

```bash
-p host_port:container_port
-p host_ip:host_port:container_port
```

**Ví dụ 1: Map một port**

```bash
docker run -d -p 8080:80 --name web nginx
```

**Giải thích:**

- Host port 8080 → Container port 80
- Truy cập: `http://localhost:8080`

**Test:**

```bash
curl http://localhost:8080
```

**Output:**

```html
<!DOCTYPE html>
<html>
<head>
<title>Welcome to nginx!</title>
...
```

**Ví dụ 2: Map nhiều ports**

```bash
docker run -d \
  -p 80:80 \
  -p 443:443 \
  --name web-server nginx
```

**Ví dụ 3: Bind vào IP cụ thể**

```bash
docker run -d -p 127.0.0.1:8080:80 --name local-web nginx
```

> Chỉ truy cập được từ localhost, không từ network

**Ví dụ 4: Random port**

```bash
docker run -d -p 80 --name web nginx
```

**Kiểm tra port được gán:**

```bash
docker port web
```

**Output:**

```
80/tcp -> 0.0.0.0:32768
```

> Host tự động gán port 32768

**Ví dụ 5: Map range ports**

```bash
docker run -d -p 8080-8090:80-90 --name multi-port nginx
```

**Ví dụ thực tế:**

```bash
# Web server
docker run -d -p 80:80 -p 443:443 --name web nginx

# Database (chỉ localhost)
docker run -d -p 127.0.0.1:3306:3306 --name db mysql:8.0

# Node.js app
docker run -d -p 3000:3000 --name app node:18

# Multiple instances
docker run -d -p 8081:80 --name web1 nginx
docker run -d -p 8082:80 --name web2 nginx
docker run -d -p 8083:80 --name web3 nginx
```

**Kiểm tra ports:**

```bash
docker ps --format "table {{.Names}}\t{{.Ports}}"
```

**Output:**

```
NAMES     PORTS
web1      0.0.0.0:8081->80/tcp
web2      0.0.0.0:8082->80/tcp
web3      0.0.0.0:8083->80/tcp
```

### 4.2. `--network`

**Mục đích:** Chỉ định network cho container.

**Các loại networks:**

- `bridge`: Mặc định, containers có thể giao tiếp
- `host`: Dùng network của host
- `none`: Không có network
- `custom`: Network tự tạo

**Ví dụ 1: Network mặc định**

```bash
docker run -d --name web nginx
# Tự động dùng bridge network
```

**Ví dụ 2: Host network**

```bash
docker run -d --network host --name web nginx
```

> Container dùng IP của host, không cần -p

**Ví dụ 3: Tạo custom network**

```bash
# Tạo network
docker network create my-network

# Chạy containers trong network
docker run -d --network my-network --name web nginx
docker run -d --network my-network --name db mysql:8.0
```

**Test connectivity:**

```bash
# Từ web ping db
docker exec web ping db
```

**Output:**

```
PING db (172.18.0.3) 56(84) bytes of data.
64 bytes from db.my-network (172.18.0.3): icmp_seq=1 ttl=64 time=0.123 ms
```

> Containers có thể ping nhau qua tên!

**Ví dụ 4: Multi-container app**

```bash
# Tạo network
docker network create app-network

# Frontend
docker run -d \
  --network app-network \
  --name frontend \
  -p 80:80 \
  nginx

# Backend
docker run -d \
  --network app-network \
  --name backend \
  -e DATABASE_HOST=database \
  node:18

# Database
docker run -d \
  --network app-network \
  --name database \
  -e POSTGRES_PASSWORD=pass123 \
  postgres:15
```

**Ví dụ 5: Kết nối vào nhiều networks**

```bash
# Tạo 2 networks
docker network create frontend-network
docker network create backend-network

# App server kết nối cả 2
docker run -d \
  --network frontend-network \
  --name app-server \
  nginx

docker network connect backend-network app-server

# Kiểm tra
docker inspect app-server | grep -A 10 Networks
```

## 5. Environment và Configuration

### 5.1. `-e` (Environment Variable)

**Mục đích:** Set biến môi trường trong container.

**Cú pháp:**

```bash
-e VAR_NAME=value
-e VAR_NAME=value -e VAR2=value2
```

**Ví dụ 1: Database password**

```bash
docker run -d \
  -e MYSQL_ROOT_PASSWORD=mypassword \
  -e MYSQL_DATABASE=mydb \
  -e MYSQL_USER=myuser \
  -e MYSQL_PASSWORD=userpass \
  --name db mysql:8.0
```

**Kiểm tra biến môi trường:**

```bash
docker exec db env | grep MYSQL
```

**Output:**

```
MYSQL_ROOT_PASSWORD=mypassword
MYSQL_DATABASE=mydb
MYSQL_USER=myuser
MYSQL_PASSWORD=userpass
```

**Ví dụ 2: Node.js app**

```bash
docker run -d \
  -e NODE_ENV=production \
  -e PORT=3000 \
  -e DATABASE_URL=mysql://user:pass@db:3306/mydb \
  -p 3000:3000 \
  --name app node:18
```

**Ví dụ 3: Đọc từ file .env**

**File `.env`:**

```
DB_HOST=localhost
DB_USER=admin
DB_PASS=secret123
```

**Chạy với --env-file:**

```bash
docker run -d --env-file .env --name app myapp:latest
```

**Ví dụ 4: Override giá trị**

```bash
# Image có ENV PORT=8080
# Override thành 3000
docker run -d -e PORT=3000 -p 3000:3000 --name app myapp:latest
```

**Ví dụ thực tế:**

```bash
# WordPress
docker run -d \
  -e WORDPRESS_DB_HOST=db:3306 \
  -e WORDPRESS_DB_USER=wpuser \
  -e WORDPRESS_DB_PASSWORD=wppass \
  -e WORDPRESS_DB_NAME=wordpress \
  -p 8080:80 \
  --name wordpress \
  wordpress:latest

# Redis
docker run -d \
  -e REDIS_PASSWORD=myredispass \
  -p 6379:6379 \
  --name redis \
  redis:latest --requirepass myredispass

# PostgreSQL
docker run -d \
  -e POSTGRES_USER=admin \
  -e POSTGRES_PASSWORD=admin123 \
  -e POSTGRES_DB=myapp \
  -e POSTGRES_HOST_AUTH_METHOD=scram-sha-256 \
  -p 5432:5432 \
  --name postgres \
  postgres:15
```

## 6. Logging Parameters

### 6.1. `--tail`

**Mục đích:** Hiển thị N dòng logs cuối cùng.

**Ví dụ 1: 10 dòng cuối**

```bash
docker logs --tail 10 my-container
```

**Output:**

```
2024/03/03 10:45:23 [notice] Connection established
2024/03/03 10:45:24 [info] Processing request
2024/03/03 10:45:25 [info] Request completed
2024/03/03 10:45:26 [notice] New connection
2024/03/03 10:45:27 [info] Processing request
2024/03/03 10:45:28 [info] Request completed
2024/03/03 10:45:29 [notice] Connection closed
2024/03/03 10:45:30 [notice] New connection
2024/03/03 10:45:31 [info] Processing request
2024/03/03 10:45:32 [info] Request completed
```

**Ví dụ 2: So sánh với không dùng --tail**

```bash
# Tất cả logs (có thể rất nhiều!)
docker logs my-container

# Chỉ 50 dòng cuối
docker logs --tail 50 my-container

# Chỉ 1 dòng cuối
docker logs --tail 1 my-container
```

### 6.2. `--since`

**Mục đích:** Hiển thị logs từ thời điểm cụ thể.

**Ví dụ 1: Từ 10 phút trước**

```bash
docker logs --since 10m my-container
```

**Ví dụ 2: Từ 1 giờ trước**

```bash
docker logs --since 1h my-container
```

**Ví dụ 3: Từ ngày cụ thể**

```bash
docker logs --since 2024-03-03 my-container
```

**Ví dụ 4: Từ timestamp cụ thể**

```bash
docker logs --since 2024-03-03T10:30:00 my-container
```

**Ví dụ 5: Kết hợp với --tail**

```bash
# 20 dòng logs từ 5 phút trước
docker logs --since 5m --tail 20 my-container
```

### 6.3. `--until`

**Mục đích:** Hiển thị logs đến thời điểm cụ thể.

**Ví dụ 1: Đến 1 giờ trước**

```bash
docker logs --until 1h my-container
```

**Ví dụ 2: Logs trong khoảng thời gian**

```bash
# Từ 2h trước đến 1h trước
docker logs --since 2h --until 1h my-container
```

**Ví dụ 3: Logs trong ngày cụ thể**

```bash
docker logs \
  --since 2024-03-03T00:00:00 \
  --until 2024-03-03T23:59:59 \
  my-container
```

### 6.4. Kết hợp các tham số logs

**Ví dụ: Debug production**

```bash
# Xem 100 dòng logs gần đây nhất
docker logs --tail 100 production-app

# Xem logs 30 phút trước
docker logs --since 30m production-app

# Follow logs real-time với timestamp
docker logs -f -t production-app

# Lọc logs theo từ khóa (dùng grep)
docker logs production-app | grep ERROR

# Export logs ra file
docker logs --since 1h production-app > app-logs.txt

# Logs với nhiều điều kiện
docker logs \
  --since 1h \
  --until 30m \
  --tail 50 \
  -t \
  production-app | grep -i error
```

**Output mẫu:**

```

2024-03-03T10:30:45.456Z [ERROR] Timeout waiting for response
2024-03-03T10:31:20.789Z [ERROR] Invalid user credentials
```

## 7. Resource Limits

### 7.1. `--memory` (RAM limit)

**Mục đích:** Giới hạn bộ nhớ RAM cho container.

**Cú pháp:**

```bash
--memory="<number><unit>"
# Units: b, k, m, g (bytes, kilobytes, megabytes, gigabytes)
```

**Ví dụ:**

```bash
# Giới hạn 512MB RAM
docker run -d --memory="512m" --name app nginx

# Giới hạn 1GB RAM
docker run -d --memory="1g" --name app nginx

# Giới hạn 2GB RAM
docker run -d --memory="2g" --name heavy-app myapp:latest
```

**Kiểm tra:**

```bash
docker stats app --no-stream
```

**Output:**

```
CONTAINER   CPU %   MEM USAGE / LIMIT   MEM %   NET I/O   BLOCK I/O
app         0.5%    45MiB / 512MiB     8.8%    0B / 0B   0B / 0B
```

### 7.2. `--cpus` (CPU limit)

**Mục đích:** Giới hạn số CPU cores.

**Ví dụ:**

```bash
# Giới hạn 0.5 CPU (50% của 1 core)
docker run -d --cpus="0.5" --name app nginx

# Giới hạn 2 CPUs
docker run -d --cpus="2.0" --name app nginx

# Giới hạn 1.5 CPUs
docker run -d --cpus="1.5" --name app myapp:latest
```

**Kết hợp memory và CPU:**

```bash
docker run -d \
  --name production-app \
  --memory="2g" \
  --cpus="1.5" \
  -p 3000:3000 \
  myapp:latest
```

**Kiểm tra:**

```bash
docker stats production-app
```

**Output:**

```
CONTAINER        CPU %   MEM USAGE / LIMIT   MEM %
production-app   45.2%   1.2GiB / 2GiB      60%
```

## 8. Tổng hợp và So sánh

### 8.1. Bảng tham số thường dùng

|Tham số|Mục đích|Ví dụ|
|---|---|---|
|`-i`|Interactive STDIN|`docker run -i ubuntu bash`|
|`-t`|TTY/Terminal|`docker run -t ubuntu bash`|
|`-it`|Interactive + Terminal|`docker run -it ubuntu bash`|
|`-d`|Detached/Background|`docker run -d nginx`|
|`--rm`|Auto remove|`docker run --rm ubuntu echo hi`|
|`--name`|Đặt tên|`docker run --name web nginx`|
|`-p`|Port mapping|`docker run -p 8080:80 nginx`|
|`-v`|Volume mount|`docker run -v /data:/app/data ubuntu`|
|`-e`|Environment variable|`docker run -e VAR=value ubuntu`|
|`--network`|Network|`docker run --network my-net nginx`|
|`--memory`|RAM limit|`docker run --memory="512m" nginx`|
|`--cpus`|CPU limit|`docker run --cpus="1.0" nginx`|

### 8.2. Template lệnh đầy đủ

```bash
docker run \
  -d \                              # Background
  --name my-app \                   # Tên container
  --rm \                            # Tự xóa khi dừng
  -p 8080:80 \                      # Port mapping
  -v $(pwd)/data:/app/data \        # Volume mount
  -e NODE_ENV=production \          # Environment
  -e DB_HOST=database \
  --network app-network \           # Network
  --memory="1g" \                   # RAM limit
  --cpus="1.5" \                    # CPU limit
  --restart unless-stopped \        # Restart policy
  myapp:latest                      # Image
```

### 8.3. Các tình huống thực tế

**Tình huống 1: Development**

```bash
docker run -it \
  --rm \
  -v $(pwd):/app \
  -p 3000:3000 \
  --name dev-app \
  node:18 \
  npm run dev
```

**Tình huống 2: Production Web Server**

```bash
docker run -d \
  --name production-web \
  -p 80:80 \
  -p 443:443 \
  -v /etc/ssl:/etc/nginx/ssl:ro \
  -v /var/log/nginx:/var/log/nginx \
  --memory="2g" \
  --cpus="2.0" \
  --restart always \
  nginx:latest
```

**Tình huống 3: Database**

```bash
docker run -d \
  --name production-db \
  -p 127.0.0.1:5432:5432 \
  -v postgres-data:/var/lib/postgresql/data \
  -e POSTGRES_PASSWORD=securepass \
  -e POSTGRES_DB=myapp \
  --memory="4g" \
  --cpus="2.0" \
  --restart unless-stopped \
  postgres:15
```

**Tình huống 4: Microservices**

```bash
# Service 1
docker run -d --name service1 \
  --network microservices \
  -e SERVICE_NAME=auth \
  -e DB_HOST=database \
  myapp/auth:latest

# Service 2
docker run -d --name service2 \
  --network microservices \
  -e SERVICE_NAME=api \
  -e AUTH_SERVICE=service1 \
  myapp/api:latest

# Service 3
docker run -d --name service3 \
  --network microservices \
  -e SERVICE_NAME=frontend \
  -e API_SERVICE=service2 \
  -p 80:80 \
  myapp/frontend:latest
```
