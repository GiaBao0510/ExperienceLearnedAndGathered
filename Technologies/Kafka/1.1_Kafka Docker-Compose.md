# Thiết lập Kafka với Docker Compose

## Yêu cầu tiên quyết

Trước tiên, máy tính phải được cài đặt **Docker** và **Docker Compose**. Ở những phiên bản Docker mới (từ 20.10 trở lên), Docker Compose đã được tích hợp sẵn dưới dạng plugin (`docker compose`), tuy nhiên lệnh `docker-compose` (có dấu gạch ngang) vẫn hoạt động nếu bạn đã cài riêng.

Sử dụng các lệnh sau trong terminal để kiểm tra:

```bash
docker --version          # Kiểm tra Docker đã được cài chưa
docker-compose --version  # Kiểm tra Docker Compose đã được cài chưa
```

Kết quả mong đợi sẽ trông như sau:

```
Docker version 26.1.0, build ...
Docker Compose version v2.27.0
```

> ⚠️ Nếu lệnh `docker-compose` báo lỗi "command not found", hãy thử `docker compose` (không có dấu gạch ngang) — đây là cú pháp plugin tích hợp của Docker phiên bản mới.

---

## Tổng quan kiến trúc

File Docker Compose dưới đây sẽ khởi động **một node Kafka duy nhất** chạy ở chế độ **KRaft** (không cần Zookeeper). Đây là cấu hình đơn giản, phù hợp cho mục đích **học tập và phát triển cục bộ**.

```
┌─────────────────────────────────────┐
│         Docker Host (máy bạn)       │
│                                     │
│  ┌──────────────────────────────┐   │
│  │   Container: my-kafka        │   │
│  │                              │   │
│  │  [Broker]  cổng 9092 ──────────── → Client kết nối (app Java/Python)
│  │  [Controller] cổng 9093     │   │
│  │                              │   │
│  └──────────────────────────────┘   │
│                                     │
│  Volume: kafka_data (lưu dữ liệu)   │
└─────────────────────────────────────┘
```

---

### ***Tạo file `kafka-compose.yaml` Không  Zookeepers:*

Tạo một thư mục mới và tạo file `kafka-compose.yaml` với nội dung sau:

```yaml
version: '3'      # Phiên bản cú pháp của Docker Compose

services:         # Danh sách các dịch vụ (container) cần chạy
  kafka:          # Tên dịch vụ trong Docker Compose
    image: apache/kafka:3.8.1   # Tải image Kafka bản 3.8.1 từ Docker Hub
    container_name: my-kafka    # Đặt tên cố định cho container để dễ quản lý

    ports:
      - "9092:9092"   # Ánh xạ cổng: <cổng máy host>:<cổng trong container>
                      # Client bên ngoài sẽ kết nối vào cổng 9092 của máy bạn

    environment:

      # --- CẤU HÌNH ĐỊNH DANH NODE ---
      KAFKA_NODE_ID: 1                        # ID duy nhất của node Kafka này trong cụm (Cluster)
      KAFKA_PROCESS_ROLES: broker,controller  # Node này vừa làm Broker (chứa dữ liệu)
                                              # vừa làm Controller (điều phối cụm)

      # --- CẤU HÌNH KRAFT (THAY THẾ ZOOKEEPER) ---
      # Danh sách các node tham gia bầu cử Controller, theo định dạng: <node_id>@<hostname>:<port>
      # Hostname "kafka" ở đây chính là tên dịch vụ trong Docker Compose (tự resolve được)
      KAFKA_CONTROLLER_QUORUM_VOTERS: 1@kafka:9093

      # --- CẤU HÌNH KẾT NỐI (NETWORKING) ---
      # Các địa chỉ và cổng mà Kafka sẽ lắng nghe kết nối từ bên trong container
      KAFKA_LISTENERS: PLAINTEXT://:9092,CONTROLLER://:9093

      # Địa chỉ Kafka quảng bá ra ngoài để Client biết cách kết nối đến
      # Dùng "localhost" vì Client chạy trên cùng máy host
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://localhost:9092

      # Chỉ định tên listener nào được dùng cho giao tiếp nội bộ giữa các Controller
      KAFKA_CONTROLLER_LISTENER_NAMES: CONTROLLER

      # Ánh xạ tên listener với kiểu bảo mật tương ứng
      # PLAINTEXT = không mã hóa, phù hợp cho môi trường học tập
      KAFKA_LISTENER_SECURITY_PROTOCOL_MAP: CONTROLLER:PLAINTEXT,PLAINTEXT:PLAINTEXT

      # --- THÔNG SỐ CỤM (CLUSTER) ---
      CLUSTER_ID: "my-kafka-cluster-1"              # ID định danh cho toàn bộ cụm Kafka
      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1     # Số bản sao dữ liệu cho topic nội bộ
      KAFKA_TRANSACTION_STATE_LOG_REPLICATION_FACTOR: 1  # Đặt là 1 vì chỉ có 1 node
      KAFKA_TRANSACTION_STATE_LOG_MIN_ISR: 1        # Số replica tối thiểu phải đồng bộ

    volumes:
      - kafka_data:/var/lib/kafka/data  # Gắn volume để dữ liệu không bị mất khi container khởi động lại

    healthcheck:
      # Lệnh kiểm tra xem Kafka đã thực sự "sống" và sẵn sàng phục vụ chưa
      test:
        [
          "CMD-SHELL",
          "/opt/kafka/bin/kafka-broker-api-versions.sh --bootstrap-server localhost:9092 || exit 1",
        ]
      interval: 10s  # Cứ 10 giây kiểm tra một lần
      timeout: 5s    # Quá 5 giây không phản hồi thì coi như lần đó thất bại
      retries: 10    # Thử lại tối đa 10 lần trước khi báo trạng thái "Unhealthy"

# Khai báo volume ở cấp cao nhất để Docker quản lý vùng lưu trữ dữ liệu
volumes:
  kafka_data:
```

### ***Tạo file `kafka-compose.yaml` có  Zookeepers - broker:*

> 💡 **Lưu ý về YAML**: YAML **không chấp nhận ký tự Tab** để thụt lề — bạn phải dùng **dấu cách (space)**. Hầu hết các editor hiện đại (VS Code, IntelliJ...) đều có thể cấu hình tự động chuyển Tab thành spaces.

## Khởi động Kafka

Mở terminal, di chuyển đến thư mục chứa file `kafka-compose.yaml` vừa tạo và chạy lệnh:

```bash
docker-compose -f kafka-compose.yaml up -d
```

Giải thích các tham số:

- `-f kafka-compose.yaml` : chỉ định tên file cấu hình (mặc định Docker tìm file `docker-compose.yml`)
- `up` : tạo và khởi động các container
- `-d` : chạy ở chế độ nền (detached), không chiếm terminal

---

## Kiểm tra sau khi khởi động

### 1. Kiểm tra container đang chạy

```bash
docker ps
```

Kết quả mong đợi — cột `STATUS` phải hiển thị `healthy`:

```
CONTAINER ID   IMAGE                  COMMAND                  STATUS
a1b2c3d4e5f6   apache/kafka:3.8.1     "/__cacert_entrypoin…"   Up 30s (healthy)
```

> ⏳ Lần đầu khởi động có thể mất 30–60 giây để Kafka đạt trạng thái `healthy`.

### 2. Xem log của container

```bash
docker logs my-kafka
```

Hoặc theo dõi log liên tục (nhấn `Ctrl+C` để thoát):

```bash
docker logs -f my-kafka
```

### 3. Tạo thử một Topic để kiểm tra

```bash
docker exec -it my-kafka \
  /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --create \
  --topic test-topic \
  --partitions 1 \
  --replication-factor 1
```

Kết quả mong đợi:

```
Created topic test-topic.
```

### 4. Liệt kê các Topic hiện có

```bash
docker exec -it my-kafka \
  /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --list
```

## Dừng và dọn dẹp

```bash
# Dừng container nhưng GIỮ LẠI dữ liệu trong volume
docker-compose -f kafka-compose.yaml down

# Dừng container và XÓA LUÔN dữ liệu trong volume (dùng khi muốn reset hoàn toàn)
docker-compose -f kafka-compose.yaml down -v
```

## Tóm tắt các biến môi trường quan trọng

| Biến                             | Giá trị                                | Ý nghĩa                                    |
| -------------------------------- | -------------------------------------- | ------------------------------------------ |
| `KAFKA_NODE_ID`                  | `1`                                    | ID duy nhất của node trong cụm             |
| `KAFKA_PROCESS_ROLES`            | `broker,controller`                    | Node đảm nhận cả 2 vai trò                 |
| `KAFKA_CONTROLLER_QUORUM_VOTERS` | `1@kafka:9093`                         | Danh sách node tham gia bầu cử Controller  |
| `KAFKA_LISTENERS`                | `PLAINTEXT://:9092,CONTROLLER://:9093` | Địa chỉ lắng nghe bên trong container      |
| `KAFKA_ADVERTISED_LISTENERS`     | `PLAINTEXT://localhost:9092`           | Địa chỉ Kafka quảng bá ra ngoài cho Client |
| `CLUSTER_ID`                     | `my-kafka-cluster-1`                   | ID định danh cụm                           |

## Các lỗi thường gặp

**Container khởi động xong nhưng ở trạng thái `unhealthy`** → Xem log bằng `docker logs my-kafka`. Thường do thiếu `CLUSTER_ID` hoặc cấu hình `KAFKA_CONTROLLER_QUORUM_VOTERS` sai hostname.

**Client không kết nối được vào Kafka** → Kiểm tra `KAFKA_ADVERTISED_LISTENERS`. Nếu Client chạy trên cùng máy host thì dùng `localhost`. Nếu Client chạy trong Docker network thì thay bằng tên service (ví dụ: `kafka`).

**Lỗi "Illegal character in hostname" khi khởi động** → `CLUSTER_ID` chỉ được dùng chữ cái, số và dấu gạch ngang (`-`). Không dùng ký tự đặc biệt khác.
