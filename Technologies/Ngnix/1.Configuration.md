# Hướng dẫn Thiết lập Cấu hình Nginx với Golang Backend

## Mục tiêu

Sau khi hoàn thành hướng dẫn này, bạn sẽ có một hệ thống gồm:

- Nginx hoạt động như **reverse proxy** và **load balancer**
- Hai server Golang backend chạy ở cổng `8080` và `8081`
- Nginx nhận toàn bộ request từ bên ngoài và phân phối đến hai server đó

**Mô hình tổng quan:**

```
Client (Browser/Postman)
        │
        ▼ port 80 / 443
   [ Nginx Container ]
        │
        ├──▶ Golang Server 1 (port 8080)
        └──▶ Golang Server 2 (port 8081)
```

## Cấu trúc thư mục dự án

Tạo cấu trúc thư mục như sau trước khi bắt đầu:

```
my-nginx-project/
├── docker-compose.yml        # Định nghĩa các container
├── nginx/
│   └── conf.d/
│       └── default.conf      # File cấu hình Nginx chính
├── server1/
│   └── main.go               # Golang server chạy ở port 8080
└── server2/
    └── main.go               # Golang server chạy ở port 8081
```

Tạo thư mục:

```bash
mkdir -p my-nginx-project/nginx/conf.d
mkdir -p my-nginx-project/server1
mkdir -p my-nginx-project/server2
cd my-nginx-project
```

## Bước 1 — Viết hai Golang Backend Server

Hai server này chỉ đơn giản trả về một thông điệp để phân biệt xem Nginx đang điều hướng đến server nào.

**`server1/main.go`**

```go
package main

import (
    "fmt"
    "net/http"
)

func main() {
    http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
        fmt.Fprintln(w, "Hello from Golang Server 1 (port 8080)!")
    })
    fmt.Println("Server 1 starting on port 8080...")
    http.ListenAndServe(":8080", nil)
}
```

**`server2/main.go`**

```go
package main

import (
    "fmt"
    "net/http"
)

func main() {
    http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
        fmt.Fprintln(w, "Hello from Golang Server 2 (port 8081)!")
    })
    fmt.Println("Server 2 starting on port 8081...")
    http.ListenAndServe(":8081", nil)
}
```

> **Lưu ý:** Hai server này lắng nghe ở hai cổng khác nhau (`8080` và `8081`). Nginx sẽ biết địa chỉ của chúng vì cả ba (Nginx + 2 server Go) cùng nằm trong một Docker network nội bộ.

## Bước 2 — Tạo file `docker-compose.yml`

File này định nghĩa tất cả các container cần chạy và cách chúng kết nối với nhau.

```yaml
# docker-compose.yml

services:

  # Container Nginx — nhận request từ bên ngoài
  webserver:
    image: nginx:alpine                        # Dùng image nhẹ hơn
    container_name: nginx_webserver
    restart: unless-stopped
    ports:
      - "80:80"                                # Cổng 80 bên ngoài → cổng 80 bên trong container
    volumes:
      - ./nginx/conf.d:/etc/nginx/conf.d:ro   # Mount thư mục cấu hình (chỉ đọc)
    depends_on:
      - golang_server1                         # Đợi server Go khởi động trước
      - golang_server2
    networks:
      - app-network

  # Container Golang Server 1
  golang_server1:
    image: golang:1.22-alpine
    container_name: golang_server1
    working_dir: /app
    volumes:
      - ./server1:/app                         # Mount code Go vào container
    command: go run main.go                    # Lệnh chạy khi container khởi động
    expose:
      - "8080"                                 # Chỉ expose nội bộ, không mở ra ngoài
    networks:
      - app-network

  # Container Golang Server 2
  golang_server2:
    image: golang:1.22-alpine
    container_name: golang_server2
    working_dir: /app
    volumes:
      - ./server2:/app
    command: go run main.go
    expose:
      - "8081"
    networks:
      - app-network

# Định nghĩa network nội bộ để các container giao tiếp với nhau
networks:
  app-network:
    driver: bridge
```

> **Giải thích `ports` vs `expose`:**
> 
> - `ports: "80:80"` — mở cổng ra ngoài, người dùng bên ngoài có thể truy cập.
> - `expose: "8080"` — chỉ mở trong mạng nội bộ Docker, bên ngoài không truy cập trực tiếp được. Đây là cách bảo mật đúng: chỉ Nginx mới giao tiếp được với server Go.

## Bước 3 — Tạo file cấu hình Nginx

Đây là phần quan trọng nhất. Tạo file `nginx/conf.d/default.conf`:

```nginx
# nginx/conf.d/default.conf

# Định nghĩa nhóm upstream (các server backend Golang)
upstream golang_backends {
    # Tên container trong Docker network = hostname có thể dùng được
    server golang_server1:8080;   # Container golang_server1, cổng 8080
    server golang_server2:8081;   # Container golang_server2, cổng 8081

    # Thuật toán mặc định: round-robin (phân phối đều, lần lượt)
    # Các request sẽ được gửi luân phiên: req1→server1, req2→server2, req3→server1...
}

# Cấu hình server Nginx lắng nghe
server {
    listen 80;                    # Lắng nghe cổng 80 (HTTP)
    server_name localhost;        # Tên miền hoặc IP của server

    # Ghi log để theo dõi và debug
    access_log /var/log/nginx/access.log;
    error_log  /var/log/nginx/error.log;

    # Xử lý tất cả các request đến "/"
    location / {
        # Chuyển tiếp request đến nhóm upstream đã định nghĩa ở trên
        proxy_pass http://golang_backends;

        # Các header quan trọng cần gửi kèm để backend biết thông tin thực của client
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Cấu hình timeout (giây) để tránh request bị treo quá lâu
        proxy_connect_timeout 5s;
        proxy_read_timeout    30s;
        proxy_send_timeout    30s;
    }

    # Trang lỗi tùy chỉnh (không bắt buộc, nhưng chuyên nghiệp hơn)
    error_page 502 503 504 /50x.html;
    location = /50x.html {
        root /usr/share/nginx/html;
    }
}
```

> **Tại sao dùng tên container thay vì `localhost`?**
> 
> Trong Docker network, các container giao tiếp với nhau qua **tên container** (không phải `localhost`). Ví dụ: `golang_server1:8080` có nghĩa là "container tên `golang_server1`, cổng `8080`". Docker tự động phân giải tên này thành địa chỉ IP nội bộ.

## Bước 4 — Khởi động hệ thống

Đứng ở thư mục gốc của dự án (`my-nginx-project/`), chạy lệnh:

```bash
# Khởi động tất cả container ở chế độ nền (-d = detached)
docker compose up -d
```

Kiểm tra các container đang chạy:

```bash
docker compose ps
```

Kết quả mong đợi:

```
NAME               IMAGE             STATUS
nginx_webserver    nginx:alpine      Up
golang_server1     golang:1.22-alpine  Up
golang_server2     golang:1.22-alpine  Up
```

## Bước 5 — Kiểm tra hoạt động

Mở trình duyệt hoặc dùng `curl` để gửi nhiều request liên tiếp:

```bash
curl http://localhost
curl http://localhost
curl http://localhost
curl http://localhost
```

Kết quả mong đợi (Nginx phân phối luân phiên):

```
Hello from Golang Server 1 (port 8080)!
Hello from Golang Server 2 (port 8081)!
Hello from Golang Server 1 (port 8080)!
Hello from Golang Server 2 (port 8081)!
```

Điều này chứng minh Nginx đang hoạt động đúng với thuật toán **round-robin**: mỗi request được gửi đến một server khác nhau theo vòng tròn.

```bash

docker compose logs webserver

# Khởi động lại Nginx sau khi thay đổi cấu hình

# Vào bên trong container Nginx để kiểm tra
docker exec -it nginx_webserver sh

docker exec nginx_webserver nginx -t
```

## Giải thích nhanh các khái niệm trong file cấu hình

| Khái niệm               | Ý nghĩa                                                                         |
| ----------------------- | ------------------------------------------------------------------------------- |
| `upstream`              | Nhóm các server backend. Nginx phân phối request đến các server trong nhóm này. |
| `server { listen 80; }` | Nginx lắng nghe kết nối đến ở cổng 80.                                          |
| `location /`            | Quy tắc xử lý request có URL bắt đầu bằng `/` (tức là tất cả request).          |
| `proxy_pass`            | Địa chỉ Nginx sẽ chuyển tiếp request đến.                                       |
| `proxy_set_header`      | Thêm hoặc ghi đè header HTTP khi chuyển tiếp request đến backend.               |
| `X-Real-IP`             | Địa chỉ IP thực của client — backend cần cái này nếu muốn biết ai đang gọi.     |
| `round-robin`           | Thuật toán mặc định của Nginx: phân phối request lần lượt theo vòng tròn.       |

## Mở rộng: Thêm server thứ ba

Nếu muốn thêm một server backend nữa, chỉ cần:

1. Thêm container mới vào `docker-compose.yml`:

```yaml
golang_server3:
  image: golang:1.22-alpine
  container_name: golang_server3
  working_dir: /app
  volumes:
    - ./server3:/app
  command: go run main.go
  expose:
    - "8082"
  networks:
    - app-network
```

2. Thêm dòng vào block `upstream` trong `default.conf`:

```nginx
upstream golang_backends {
    server golang_server1:8080;
    server golang_server2:8081;
    server golang_server3:8082;   # Thêm dòng này
}
```

3. Khởi động lại:

```bash
docker compose up -d
docker compose restart webserver
```

## Chú thích về các thay đổi lớn so với tài liệu gốc

1. **Sửa lỗi cú pháp `docker-compose.yml` bản gốc:** Trường `version: '3'` bị ngắt dòng sai (không hợp lệ YAML). Thuộc tính `networks` bị thụt lề sai (lồng vào trong `services` thay vì ngang cấp). Đã sửa toàn bộ.

2. **Bổ sung hoàn toàn file `nginx.conf`:** Bản gốc chỉ có khung trống `events {}` và `http {}` với comment `#bổ sung`. Đã viết đầy đủ cấu hình thực tế có giải thích từng dòng.

3. **Sử dụng tên container thay vì `localhost/8080`:** Bản gốc ghi `http://localhost/8080` là sai — trong Docker network, phải dùng tên container làm hostname. Ngoài ra `localhost/8080` là đường dẫn URI, không phải địa chỉ server. Địa chỉ đúng là `golang_server1:8080`.

4. **Thêm Golang server mẫu:** Bản gốc không có code backend để chạy thử, sinh viên không biết cần chuẩn bị gì. Đã thêm hai file `main.go` đơn giản.

5. **Thêm hướng dẫn kiểm tra kết quả:** Bản gốc không có bước xác nhận hệ thống hoạt động đúng. Đã thêm lệnh `curl` và kết quả mong đợi.

6. **Dùng `nginx:alpine` thay vì `nginx`:** Image `alpine` nhỏ hơn (~40 MB so với ~180 MB), phù hợp hơn cho môi trường học tập và development.
