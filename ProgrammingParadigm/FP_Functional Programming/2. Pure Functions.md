# Pure Functions

_Hàm thuần khiết trong Functional Programming_

---

## 1. Giới thiệu

**Pure Function (Hàm thuần khiết)** là một khái niệm nền tảng trong **Functional Programming (FP)**. Đây là loại hàm hoạt động theo một quy tắc đơn giản: chỉ nhận đầu vào, tính toán, và trả về kết quả — mà không tác động lên bất cứ thứ gì bên ngoài hàm đó.

Hãy hình dung như một máy tính toán: bạn nhấn các số và phép toán vào, máy cho bạn kết quả. Máy không nhớ lần tính trước, không thay đổi trạng thái của bất cứ thứ gì, và với cùng một đầu vào nó luôn cho cùng một kết quả.

---

## 2. Điều kiện để là Pure Function

Một hàm được gọi là pure nếu thỏa mãn tất cả các điều kiện sau:

| STT | Điều kiện                                           | Giải thích                                                                         |
| :-: | --------------------------------------------------- | ---------------------------------------------------------------------------------- |
|  1  | **Phải có ít nhất một tham số đầu vào**             | Hàm cần nhận dữ liệu từ bên ngoài để xử lý                                         |
|  2  | **Phải có giá trị trả về**                          | Kết quả tính toán phải được trả lại cho người gọi hàm                              |
|  3  | **Không thay đổi giá trị của tham số đầu vào**      | Đầu vào chỉ được đọc, không được sửa đổi bên trong hàm                             |
|  4  | **Không truy cập hoặc tác động lên biến bên ngoài** | Hàm chỉ làm việc với dữ liệu được truyền vào, không phụ thuộc vào trạng thái ngoài |
|  5  | **Cùng đầu vào luôn cho cùng đầu ra**               | Kết quả không thay đổi dù hàm được gọi ở bất kỳ thời điểm nào                      |
|  6  | **Không có Side Effect (tác dụng phụ)**             | Hàm không tác động ra ngoài như: ghi file, gửi request, thay đổi database          |

---

## 3. Ví dụ thực tế bằng Golang

### 3.1 Ví dụ đơn giản — Cộng hai số

Đây là ví dụ cơ bản nhất của pure function. Hàm chỉ nhận hai số, cộng lại và trả về kết quả. Không chạm vào bất cứ thứ gì bên ngoài.

```go
package main

import "fmt"

// Pure function: chỉ nhận đầu vào, trả về kết quả
func Add(a, b int) int {
    return a + b
}

func main() {
    fmt.Println(Add(3, 5)) // => 8
    fmt.Println(Add(3, 5)) // => 8 (luôn giống nhau)
}
```

> **Lưu ý:** Gọi `Add(3, 5)` bao nhiêu lần cũng luôn trả về `8`. Đây chính là đặc trưng của pure function.

---

### 3.2 Pure vs Impure — So sánh trực tiếp

Hãy xem xét hai hàm cùng mục đích: tính tổng của một danh sách số.

**Impure — Không đúng:**

```go
var total int // biến toàn cục

func SumImpure(nums []int) {
    for _, n := range nums {
        total += n // thay đổi biến ngoài!
    }
    // không trả về gì cả
}
```

**Pure — Đúng cách:**

```go
func SumPure(nums []int) int {
    total := 0 // biến cục phạm vi
    for _, n := range nums {
        total += n
    }
    return total // trả về kết quả
}
```

Vấn đề của hàm `SumImpure`: nó phụ thuộc vào biến toàn cục `total`. Mỗi lần gọi, giá trị của `total` thay đổi, khiến kết quả không lặp lại được. Hàm `SumPure` không chạm đến biến nào bên ngoài nên hoạt động độc lập và an toàn.

---

### 3.3 Không thay đổi đầu vào (Immutability)

Pure function không được sửa đổi đầu vào của nó. Ví dụ sau cho thấy cách xử lý đúng khi cần thêm phần tử vào một slice:

**Impure — Sửa đầu vào:**

```go
func AddItem(items []string, item string) []string {
    // SAI: thay đổi slice gốc
    items = append(items, item)
    return items
}
```

**Pure — Tạo kết quả mới:**

```go
func AddItem(items []string, item string) []string {
    // ĐÚNG: tạo slice mới
    result := make([]string, len(items))
    copy(result, items)
    result = append(result, item)
    return result
}
```

> **Tại sao quan trọng?** Nếu hàm thay đổi slice gốc, các phần khác của chương trình đang dùng slice đó sẽ bị ảnh hưởng một cách không lường trước được.

---

### 3.4 Ví dụ thực tế — Tính giá sau thuế

Trong ứng dụng thực, pure function rất hữu ích để tính toán giá trị. Ví dụ sau tính giá sản phẩm sau khi áp dụng discount và thuế:

```go
package main

import "fmt"

// Pure function: tính giá sau discount
func ApplyDiscount(price, discountPercent float64) float64 {
    return price - (price * discountPercent / 100)
}

// Pure function: tính giá sau thuế
func ApplyTax(price, taxPercent float64) float64 {
    return price + (price * taxPercent / 100)
}

// Pure function: tính giá cuối cùng
func FinalPrice(price, discountPercent, taxPercent float64) float64 {
    afterDiscount := ApplyDiscount(price, discountPercent)
    return ApplyTax(afterDiscount, taxPercent)
}

func main() {
    price := 1000000.0   // 1,000,000 VND
    discount := 10.0     // 10% discount
    tax := 8.0           // 8% VAT

    fmt.Printf("Giá gốc:      %.0f VND\n", price)
    fmt.Printf("Sau discount:  %.0f VND\n", ApplyDiscount(price, discount))
    fmt.Printf("Giá cuối cùng: %.0f VND\n", FinalPrice(price, discount, tax))
}
```

Mỗi hàm chỉ đảm nhận một việc, không phụ thuộc vào nhau về trạng thái. Bạn có thể test từng hàm một cách độc lập và dễ dàng kết hợp chúng.

## 4. Side Effect là gì?

**Side Effect (tác dụng phụ)** là bất cứ hành động nào mà hàm thực hiện ra ngoài phạm vi của nó. Đây chính là thứ khiến một hàm trở thành **impure**.

|Loại Side Effect|Ví dụ|
|---|---|
|Thay đổi biến ngoài|Ghi giá trị vào biến toàn cục hoặc biến của scope khác|
|Đọc/Ghi file|Đọc dữ liệu từ file hoặc tạo/sửa file trên ổ cứng|
|Gửi yêu cầu mạng|Gửi HTTP request đến server|
|Thay đổi database|INSERT, UPDATE, DELETE dữ liệu trong CSDL|
|In ra console|`fmt.Println()`, `log.Println()` — đây cũng là side effect|

### 4.1 Ví dụ Side Effect trong Golang

**Impure — Có Side Effect:**

```go
var logMessages []string // biến toàn cục

func ProcessImpure(data string) string {
    // Side effect 1: thay đổi biến ngoài
    logMessages = append(logMessages, data)

    // Side effect 2: in ra console
    fmt.Println("Processing:", data)

    return strings.ToUpper(data)
}
```

**Pure — Side Effect tách ra:**

```go
func ProcessPure(data string) string {
    // Chỉ xử lý đầu vào và trả về kết quả
    // Không chạm biến ngoài, không print
    return strings.ToUpper(data)
}

// Side effect được tách ra ngoài:
func LogAndProcess(data string) {
    result := ProcessPure(data)     // pure
    fmt.Println("Result:", result)  // side effect
}
```

> **Kỹ thuật:** Thay vì loại bỏ hoàn toàn side effect (không thể được), chúng ta tách chúng ra khỏi hàm pure. Đây là cách Functional Programming xử lý side effect.

---

## 5. Tại sao Pure Function quan trọng?

Pure function mang lại nhiều lợi ích thực tế trong quá trình phát triển phần mềm:

- **Dễ test:** Chỉ cần truyền đầu vào và kiểm tra đầu ra. Không cần setup database, mock server hay tạo môi trường phức tạp.
- **Dễ debug:** Hàm không phụ thuộc trạng thái ngoài, nên lỗi chỉ có thể nằm trong logic của hàm đó.
- **Dễ refactor:** Có thể thay đổi nội dung hàm miễn là đầu vào và đầu ra không đổi, mà không lo ảnh hưởng phần khác.
- **Hỗ trợ song song (concurrency):** Vì không chia sẻ trạng thái, nhiều goroutine có thể gọi cùng hàm pure một cách an toàn.
- **Kết quả có thể cache:** Cùng đầu vào luôn cho cùng đầu ra, nên kết quả có thể lưu tạm để tránh tính lại.

---

## 6. Giới hạn của Pure Function

**Functional Programming không thể loại bỏ hoàn toàn side effect** — mà chỉ có thể **cô lập** chúng. Phần mềm thực tế cần tương tác với thế giới bên ngoài: đọc input từ người dùng, ghi dữ liệu vào database, gửi email. Những hành động này đều là side effect và không thể tránh.

**Mục tiêu của Functional Programming:** Tối thiểu hóa số lượng impure code. Cố gắng để phần lớn logic nghiệp vụ nằm trong pure function, còn phần impure chỉ là "lớp bao bì" giao tiếp với thế giới ngoài.

```
// Kiến trúc lý tưởng trong Go:
//
// ┌─────────────────────────────────┐
// │       main() — Impure layer   │  <-- Giao tiếp với thế giới ngoài
// │  ┌─────────────────────────┐    │
// │  │  Pure Business Logic  │    │  <-- Toàn bộ logic nghiệp vụ ở đây
// │  │  (Calculate, Transform)│   │
// │  └─────────────────────────┘    │
// └─────────────────────────────────┘
//
// Pure layer:   không biết về database, file, network...
// Impure layer: gọi pure functions và tương tác với thế giới ngoài.
```
