# Giới thiệu về Git

## **Git là gì?**

Git là một hệ thống quản lý phiên bản phân tán (Distributed Version Control System - viết tắt là DVCS) được sử dụng để theo dõi các thay đổi trong mã nguồn của dự án. Git giúp nhiều lập trình viên có thể cộng tác trên cùng một dự án một cách hiệu quả và quản lý các phiên bản của hệ thống một cách khoa học.

### **Ví dụ đơn giản để hiểu Git:**

Hãy tưởng tượng bạn đang viết luận văn:

- **Không dùng Git**: Bạn tạo các file `luan_van_v1.docx`, `luan_van_v2.docx`, `luan_van_final.docx`, `luan_van_final_2.docx`... Rất lộn xộn và khó quản lý!
    
- **Dùng Git**: Bạn chỉ có 1 file `luan_van.docx`, nhưng Git ghi nhớ toàn bộ lịch sử thay đổi. Bạn có thể xem lại hoặc quay về bất kỳ phiên bản nào trước đó.
    

### **Chức năng chính của Git:**

1. **Theo dõi lịch sử thay đổi**: Ghi lại ai đã sửa gì, khi nào, tại sao. Cho phép quay lại các phiên bản cũ hoặc điều tra lịch sử khi có lỗi xảy ra.
    
2. **Quản lý nhánh (Branch)**: Git cho phép tách nhánh dễ dàng để thử nghiệm hoặc phát triển tính năng mới mà không ảnh hưởng đến nhánh chính (main/master), sau đó có thể hợp nhất tính năng vào nhánh chính để phát hành.
    
3. **Lưu trữ phân tán**: Mỗi người tham gia dự án đều có một bản sao đầy đủ của lịch sử dự án trên máy của mình. Nếu server bị hỏng, bạn vẫn có thể làm việc và khôi phục dữ liệu.
    
4. **Làm việc nhóm hiệu quả**: Nhiều người có thể làm việc cùng lúc trên cùng một dự án mà không lo đè lên code của nhau.

## **Vì sao nên học Git?**

Ngày nay, Git đã trở thành một công cụ bắt buộc trong hầu hết các dự án phát triển phần mềm. Theo thống kê, **hơn 90% các công ty công nghệ yêu cầu ứng viên biết Git**. Vì vậy, việc học Git sẽ mang lại rất nhiều lợi ích quan trọng:

### **1. Quản lý mã nguồn hiệu quả**

Giúp bạn theo dõi được mọi thay đổi của mã nguồn và xử lý được các tình huống phát sinh khi làm việc (ví dụ: code bị lỗi sau khi update, muốn xem ai đã sửa đoạn code nào).

**Ví dụ thực tế**: Bạn code tính năng mới, nhưng làm hỏng tính năng cũ. Với Git, bạn chỉ cần quay lại phiên bản trước đó trong vài giây thay vì phải nhớ lại và viết lại từ đầu.

### **2. Nâng cao chất lượng làm việc nhóm**

Cho phép nhiều lập trình viên làm việc đồng thời mà không ảnh hưởng lẫn nhau, rút ngắn thời gian phát triển dự án.

**Ví dụ thực tế**: Trong nhóm 5 người, mỗi người phát triển một tính năng riêng. Git giúp tích hợp tất cả tính năng lại một cách thông minh mà không xung đột.

### **3. Tách biệt luồng phát triển**

Phát triển tính năng mới hoặc thử nghiệm mà không làm ảnh hưởng đến nhánh chính, đảm bảo hệ thống hoạt động ổn định.

**Ví dụ thực tế**: Website đang chạy ổn định. Bạn muốn thêm tính năng thanh toán mới. Bạn tạo nhánh riêng để phát triển, test kỹ, rồi mới merge vào nhánh chính. Nhánh chính vẫn hoạt động bình thường trong suốt quá trình phát triển.

### **4. Tiết kiệm thời gian**

Các thao tác như merge (hợp nhất), pull (kéo code mới), push (đẩy code lên) được thực hiện nhanh chóng, giúp tiết kiệm thời gian so với các phương pháp truyền thống (như copy-paste qua USB, email, chat).

### **5. Cơ hội nghề nghiệp**

Git là kỹ năng bắt buộc trong CV của mọi lập trình viên. Biết Git giúp bạn dễ dàng xin việc và làm việc chuyên nghiệp hơn.

## **Những khái niệm quan trọng trong Git**

Dưới đây là các thuật ngữ bạn sẽ gặp thường xuyên khi làm việc với Git. Đừng lo nếu bây giờ chưa hiểu hết, chúng ta sẽ học chi tiết từng phần.

### **1. Repository (Kho lưu trữ)**

Là nơi chứa toàn bộ dự án và lịch sử thay đổi của nó. Có 2 loại:

- **Local Repository**: Kho trên máy tính của bạn
- **Remote Repository**: Kho trên server (GitHub, GitLab, Bitbucket...)

**Ví dụ**: Giống như Google Drive, bạn có folder trên máy (local) và folder trên cloud (remote).

### **2. Branch (Nhánh)**

Là một "đường phát triển" độc lập trong dự án. Bạn có thể tạo nhiều nhánh để làm việc song song mà không ảnh hưởng lẫn nhau.

**Ví dụ**:

- Nhánh `main`: Code ổn định, đang chạy thật
- Nhánh `feature-login`: Đang phát triển tính năng đăng nhập
- Nhánh `feature-payment`: Đang phát triển tính năng thanh toán

Mỗi nhánh có thể tiến triển độc lập, sau đó được hợp nhất (merge) lại.

### **3. Commit (Xác nhận)**

Là một "điểm lưu" (snapshot/checkpoint) của mã nguồn tại một thời điểm cụ thể, kèm theo mô tả về thay đổi đó.

**Ví dụ**: Giống như bạn save game. Mỗi lần save, bạn ghi chú "Đã qua màn 3", "Đã mua được súng mới". Sau này có thể load lại bất kỳ lúc nào.

**Mỗi commit bao gồm**:

- Nội dung thay đổi (code mới/sửa/xóa)
- Tác giả (ai đã làm)
- Thời gian
- Message mô tả (ví dụ: "Thêm tính năng đăng nhập")

### **4. HEAD**

Là con trỏ đặc biệt trỏ đến commit hiện tại mà bạn đang làm việc. Thường thì HEAD trỏ đến commit mới nhất của nhánh hiện tại.

**Ví dụ**: Giống như dấu trang trong sách, cho biết bạn đang đọc đến trang nào.

### **5. Checkout**

Lệnh dùng để chuyển đổi giữa các nhánh hoặc di chuyển đến một commit cụ thể trong lịch sử.

**Ví dụ**:

- `git checkout main` → Chuyển sang nhánh main
- `git checkout feature-login` → Chuyển sang nhánh feature-login

### **6. Merge (Hợp nhất)**

Kết hợp các thay đổi từ nhánh này vào nhánh khác. Git sẽ tự động hợp nhất code, hoặc báo conflict nếu có xung đột.

**Ví dụ**: Bạn làm xong tính năng đăng nhập ở nhánh `feature-login`, giờ muốn đưa nó vào nhánh `main` → dùng merge.

**Kết quả**: Tạo ra một commit mới có nội dung kết hợp từ cả 2 nhánh.

### **7. Rebase (Sắp xếp lại)**

Cũng là hợp nhất 2 nhánh, nhưng khác với Merge:

- Rebase sắp xếp lại các commit theo thứ tự thời gian một cách tuyến tính
- Không tạo ra commit merge, lịch sử trông "sạch" hơn

**Khi nào dùng**:

- **Merge**: Khi làm việc nhóm, muốn giữ nguyên lịch sử
- **Rebase**: Khi muốn lịch sử commit gọn gàng, dễ đọc

### **8. Conflict (Xung đột)**

Xảy ra khi 2 người sửa cùng một đoạn code, và Git không biết nên giữ phiên bản nào.

**Ví dụ**:

- Bạn A sửa dòng 10: `color = "red"`
- Bạn B cũng sửa dòng 10: `color = "blue"`
- Khi merge → Conflict! Bạn phải tự quyết định giữ "red", "blue", hay cả hai.

**Cách giải quyết**: Mở file bị conflict, chọn code muốn giữ, sau đó commit lại.

### **9. Push (Đẩy lên)**

Cập nhật các commit mới từ repository cục bộ (máy bạn) lên repository từ xa (server).

**Ví dụ**: Bạn code xong trên máy → `git push` → Code được cập nhật lên GitHub để team cùng xem.

### **10. Fetch (Tải về)**

Lấy các commit mới từ repository từ xa về máy, nhưng **KHÔNG** tự động hợp nhất với code đang làm.

**Ví dụ**: Bạn muốn xem đồng nghiệp đã làm gì, nhưng chưa muốn áp dụng ngay → dùng `git fetch`.

### **11. Pull (Kéo về)**

Kết hợp của `Fetch + Merge`: Vừa tải code mới về, vừa tự động hợp nhất với nhánh hiện tại.

**Ví dụ**: Đồng nghiệp push code mới lên GitHub. Bạn dùng `git pull` để lấy code mới nhất về và tự động merge với code của bạn.

**So sánh**:

- `git fetch` = Tải về nhưng chưa merge (an toàn hơn, kiểm soát được)
- `git pull` = Tải về + merge luôn (nhanh hơn, nhưng có thể gây conflict)

### **12. Tag (Gắn nhãn)**

Đánh dấu một phiên bản quan trọng của dự án (thường là các phiên bản phát hành chính thức).

**Ví dụ**:

- `v1.0.0` → Phiên bản đầu tiên phát hành
- `v1.1.0` → Thêm tính năng mới
- `v2.0.0` → Nâng cấp lớn

Tag giúp bạn dễ dàng quay lại phiên bản cụ thể thay vì phải nhớ mã commit (vd: `a1b2c3d4`).

## **Quy trình làm việc cơ bản với Git**

Để dễ hình dung, đây là quy trình bạn sẽ làm hàng ngày:

```
1. Clone/Pull: Lấy code mới nhất về máy
   ↓
2. Branch: Tạo nhánh mới cho tính năng
   ↓
3. Code: Viết code, sửa lỗi
   ↓
4. Add: Thêm file thay đổi vào staging
   ↓
5. Commit: Lưu thay đổi với message
   ↓
6. Push: Đẩy code lên server
   ↓
7. Pull Request: Yêu cầu review và merge
   ↓
8. Merge: Hợp nhất vào nhánh chính
```

## **Git vs GitHub - Khác nhau như thế nào?**

Nhiều sinh viên hay nhầm lẫn giữa Git và GitHub:

|Git|GitHub|
|---|---|
|Là phần mềm quản lý phiên bản|Là dịch vụ lưu trữ code trên cloud|
|Cài đặt trên máy tính|Truy cập qua web hoặc app|
|Làm việc offline được|Cần internet|
|Miễn phí, mã nguồn mở|Có gói miễn phí và trả phí|
|Tạo bởi Linus Torvalds (2005)|Thuộc sở hữu của Microsoft|

**Ví dụ đơn giản**:

- **Git** = Microsoft Word (phần mềm để viết)
- **GitHub** = Google Docs/OneDrive (nơi lưu trữ và chia sẻ)

**Các dịch vụ tương tự GitHub**:

- GitLab
- Bitbucket
- Azure DevOps

## **Tại sao Git lại phổ biến đến vậy?**

1. **Miễn phí và mã nguồn mở**: Ai cũng có thể dùng
2. **Nhanh và mạnh mẽ**: Xử lý dự án lớn rất hiệu quả
3. **Phân tán**: Không phụ thuộc vào server trung tâm
4. **Cộng đồng lớn**: Hàng triệu lập trình viên sử dụng
5. **Được dùng bởi các dự án lớn**: Linux Kernel, Android, React, TensorFlow...
6. **Tích hợp tốt**: Hầu hết IDE đều hỗ trợ Git sẵn
