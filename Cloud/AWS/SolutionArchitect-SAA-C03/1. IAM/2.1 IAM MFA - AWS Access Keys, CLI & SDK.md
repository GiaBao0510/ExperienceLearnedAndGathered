## IAM – Password Policy

Mật khẩu càng mạnh, tài khoản của bạn càng khó bị tấn công dò mật khẩu (brute-force). Vì vậy AWS cho phép bạn thiết lập **chính sách mật khẩu (password policy)** áp dụng cho toàn bộ IAM User trong tài khoản, gồm các tùy chọn:

- Quy định độ dài tối thiểu cho mật khẩu.
- Yêu cầu các loại ký tự cụ thể: chữ in hoa, chữ thường, chữ số, ký tự đặc biệt (không phải chữ cái hay chữ số).
- Cho phép IAM User tự thay đổi mật khẩu của họ.
- Yêu cầu đổi mật khẩu định kỳ (hết hạn mật khẩu sau một khoảng thời gian).
- Ngăn việc dùng lại mật khẩu cũ.

Password policy giúp phòng chống hiệu quả các cuộc tấn công dò mật khẩu hàng loạt (brute-force attack). Tuy nhiên, đây chỉ là lớp bảo vệ đầu tiên — còn một cơ chế phòng vệ thứ hai quan trọng không kém mà bạn cần nắm khi đi thi: **Multi-Factor Authentication (MFA)**.

## Multi-Factor Authentication - MFA

### MFA là gì?

**MFA = một thứ bạn biết (mật khẩu) + một thiết bị bảo mật bạn sở hữu.** Kết hợp cả hai giúp bảo mật cao hơn nhiều so với chỉ dùng mật khẩu đơn thuần.

**Ví dụ:** Alice biết mật khẩu của mình, đồng thời sở hữu một thiết bị tạo mã MFA (ví dụ: app trên điện thoại). Khi đăng nhập, cô cần nhập cả mật khẩu **và** mã MFA do thiết bị tạo ra thì mới đăng nhập thành công.

**Lợi ích chính:** nếu mật khẩu của Alice bị đánh cắp hoặc bị dò ra, kẻ tấn công vẫn **không thể** đăng nhập vào tài khoản — vì họ còn cần chiếm được thiết bị vật lý của Alice (ví dụ: điện thoại), điều này khó xảy ra hơn nhiều.

![](https://i.ibb.co/m5yXkXNX/image.png)

### Vì sao cần bật MFA?

Bất kỳ ai có quyền truy cập vào tài khoản AWS của bạn — đặc biệt nếu họ có quyền quản trị — đều có thể thay đổi cấu hình hoặc xóa tài nguyên trong tài khoản. Do đó bạn nên bảo vệ cả **tài khoản Root** lẫn **IAM User** bằng MFA.

> 📌 **Cập nhật quan trọng (tính đến giữa năm 2025):** Trước đây MFA trên AWS chỉ được _khuyến nghị_, không bắt buộc. Nhưng kể từ tháng 6/2025, AWS đã **bắt buộc** bật MFA cho **user root** trên mọi loại tài khoản (standalone, management account, và member account trong AWS Organizations) — nếu không bật MFA, user root sẽ không thể đăng nhập vào AWS Management Console [^1]. Đối với các **IAM User thông thường** (không phải root), MFA hiện vẫn là _khuyến nghị mạnh mẽ_ chứ chưa bị AWS bắt buộc mặc định — nhưng quản trị viên hoàn toàn có thể tự ép buộc bằng IAM policy. Vì vậy trong mọi trường hợp, hãy coi MFA là việc bắt buộc phải làm.

## MFA Devices Options in AWS

### Virtual MFA Device

Đây là loại thiết bị bạn sẽ dùng trong phần thực hành. Về bản chất, đây là một ứng dụng tạo mã OTP (One-Time Password) cài trên điện thoại, ví dụ:

- **Google Authenticator** — chỉ hoạt động trên **một điện thoại tại một thời điểm**.
- **Authy** — hỗ trợ lưu **nhiều mã MFA (token) trên cùng một thiết bị**, nên nếu bạn quản lý nhiều tài khoản (root, nhiều IAM User khác nhau...), bạn có thể đăng ký MFA cho tất cả trên cùng một app.

- **Authy (phone only)** — hỗ trợ nhiều token trên cùng một thiết bị

### Universal 2nd Factor (U2F) Security Key

Đây là một **thiết bị vật lý** dùng làm yếu tố xác thực thứ hai — bạn cắm nó vào cổng USB (hoặc chạm NFC) khi đăng nhập.

- **YubiKey (Yubico)** — sản phẩm của bên thứ ba (không phải do AWS sản xuất). Một chiếc YubiKey duy nhất có thể dùng để bảo vệ **nhiều user root và IAM User khác nhau**, nên bạn không cần mua một chìa khóa riêng cho mỗi user.

# AWS Access Keys, CLI & SDK

## How can users access AWS?

![](https://encrypted-tbn0.gstatic.com/images?q=tbn:ANd9GcS3QL9_V_B1Gr372mj-iMrB33S216GarYN82Oa0xvsO1w&s=10)

Có ba cách để truy cập AWS:

|Cách truy cập|Được bảo vệ bằng|Dùng để|
|---|---|---|
|**AWS Management Console**|Mật khẩu + MFA|Thao tác qua giao diện web|
|**AWS Command Line Interface (CLI)**|Access keys|Gõ lệnh trực tiếp từ terminal trên máy tính|
|**AWS Software Development Kit (SDK)**|Access keys|Lập trình, gọi API AWS từ trong code ứng dụng|

## AWS Access Keys

**Access keys** là cặp thông tin đăng nhập dùng để CLI và SDK xác thực với AWS (thay cho mật khẩu — vốn chỉ dùng cho Console). Access keys được tạo trực tiếp từ AWS Console và chỉ hiển thị/tải xuống được **một lần duy nhất** ngay khi tạo.

Một cặp access keys gồm hai phần:

- **Access Key ID** — tương đương _tên người dùng (username)_, dùng để nhận diện.
- **Secret Access Key** — tương đương _mật khẩu (password)_, dùng để xác thực.

> ⚠️ **Quy tắc bắt buộc:** Access keys là thông tin bảo mật, tương đương mật khẩu — **tuyệt đối không chia sẻ** với bất kỳ ai, kể cả đồng nghiệp. Mỗi người dùng nên tự tạo và tự quản lý access keys của riêng mình.

### Ví dụ access keys (giả lập)

```
Access key ID:     AKIASK4E37PV4983d6C

```

_(Đây chỉ là ví dụ minh họa, không phải khóa thật — nhưng ngoài đời, hãy luôn xử lý access keys thật của bạn với mức độ cẩn trọng tương tự như mật khẩu.)_

Sau khi tải access keys về, bạn cấu hình chúng vào AWS CLI trên máy (thường qua lệnh `aws configure`) để có thể gọi API AWS trực tiếp từ terminal.

## AWS CLI Là Gì?

**CLI** là viết tắt của **Command Line Interface** (giao diện dòng lệnh). **AWS CLI** là công cụ giúp bạn tương tác với các dịch vụ AWS bằng cách gõ lệnh trong terminal, thay vì click chuột trên Console.

- Truy cập trực tiếp vào các API công khai của AWS.
- Có thể viết thành script để tự động hóa việc quản lý tài nguyên.
- Là mã nguồn mở: https://github.com/aws/aws-cli
- Là một giải pháp thay thế cho AWS Management Console — phù hợp khi bạn cần thao tác nhanh, lặp lại, hoặc tự động hóa.

Ví dụ: lệnh dưới đây upload một file lên S3, sau đó liệt kê nội dung của bucket:

```
➜  ~ aws s3 cp myfile.txt s3://ccp-mybucket/myfile.txt
upload: ./myfile.txt to s3://ccp-mybucket/myfile.txt
➜  ~ aws s3 ls s3://ccp-mybucket
2021-05-14 03:22:52          0 myfile.txt
➜  ~
```

## AWS SDK Là Gì?

**SDK** là viết tắt của **Software Development Kit** — một bộ thư viện lập trình, có phiên bản riêng cho từng ngôn ngữ. SDK cho phép bạn truy cập và quản lý các dịch vụ AWS **bằng code**, nhúng trực tiếp vào ứng dụng bạn đang xây dựng (khác với CLI — vốn được gõ tay trên terminal).

- **API dành riêng cho từng ngôn ngữ** (mỗi ngôn ngữ có một bộ thư viện SDK riêng).
- Cho phép truy cập và quản lý dịch vụ AWS thông qua lập trình, tích hợp trực tiếp vào ứng dụng.
- **Hỗ trợ đa nền tảng:**
    - SDK cho ngôn ngữ lập trình: JavaScript, Python, PHP, .NET, Ruby, Java, Go, Node.js, C++...
    - SDK di động: Android, iOS...
    - SDK cho thiết bị IoT: Embedded C, Arduino...

> 📌 **Ghi chú kỹ thuật:** Bản thân AWS CLI được xây dựng dựa trên **Botocore** — thư viện Python cấp thấp làm nền tảng chung cho cả AWS CLI lẫn **Boto3** (AWS SDK for Python) [^2]. Nói cách khác, AWS CLI và Boto3 dùng chung một "lõi" xử lý API, chứ AWS CLI không trực tiếp gọi Boto3.

## Mở Rộng

- **IAM Roles** — cấp quyền tạm thời cho ứng dụng/dịch vụ AWS thay vì dùng access keys cố định (an toàn hơn, đặc biệt khi chạy trên EC2, Lambda...).
- **AWS Secrets Manager / Parameter Store** — nơi lưu trữ access keys và các bí mật khác một cách an toàn, thay vì hard-code trong source code.
- **IAM Credential Report & Access Advisor** — công cụ giúp kiểm tra user nào chưa bật MFA, hoặc access keys nào lâu ngày không dùng.
- **AWS CLI Named Profiles** — cách quản lý nhiều bộ access keys (nhiều tài khoản/nhiều role) cùng lúc trên một máy.
- **FIDO2 Passkey** — phương thức xác thực không mật khẩu mà AWS mới bổ sung, có thể dùng thay cho MFA truyền thống.
