## **AWS là gì?**

**AWS (Amazon Web Services)** là nền tảng điện toán đám mây (Cloud Computing) hàng đầu thế giới, được cung cấp bởi Amazon.

![](https://viettuans.vn/uploads/2023/04/aws-la-gi-3.jpg)
### Đặc điểm chính:
- **Dịch vụ theo yêu cầu (On-demand):** Bạn chỉ trả tiền cho những gì bạn sử dụng
- **Khả năng mở rộng (Scalability):** Dễ dàng tăng/giảm tài nguyên theo nhu cầu
- **Phạm vi toàn cầu:** Triển khai ứng dụng trên khắp thế giới trong vài phút
- **Độ tin cậy cao:** Cơ sở hạ tầng được thiết kế với khả năng chịu lỗi

### Các công ty lớn sử dụng AWS:
| Công ty    | Lĩnh vực             |
| ---------- | -------------------- |
| Netflix    | Streaming video      |
| Airbnb     | Đặt phòng trực tuyến |
| NASA       | Nghiên cứu khoa học  |
| Samsung    | Công nghệ            |
| Amazon.com | Thương mại điện tử   |

## **AWS Regions**

**Region** là một khu vực địa lý riêng biệt, chứa nhiều Availability Zones.

![](https://help.mypurecloud.com/wp-content/uploads/2022/03/All-Regions-1024x692.png)
### Quy tắc đặt tên Region:
```
┌────────────────────────────────────────────────┐
│  Cú pháp: <châu lục>-<vùng>-<số thứ tự>        │
│                                                 │
│  Ví dụ:                                         │
│  • us-east-1      → Mỹ, bờ Đông, region 1      │
│  • eu-west-3      → Châu Âu, phía Tây, region 3│
│  • ap-southeast-1 → Châu Á TBD, Đông Nam, #1   │
└────────────────────────────────────────────────┘
```

### Các Region gần Việt Nam:
| Region Code | Tên | Vị trí |
|-------------|-----|--------|
| `ap-southeast-1` | Singapore | Singapore 🇸🇬 |
| `ap-southeast-2` | Sydney | Australia 🇦🇺 |
| `ap-northeast-1` | Tokyo | Nhật Bản 🇯🇵 |
| `ap-south-1` | Mumbai | Ấn Độ 🇮🇳 |

> ⚠️ **Lưu ý quan trọng:** Hầu hết dịch vụ AWS có phạm vi **Region-scoped** (chỉ hoạt động trong 1 region). Một số dịch vụ là **Global** (như IAM, Route 53, CloudFront).

## **Làm thế nào để chọn khu vực AWS hợp lý?**

Khi chọn Region, cần cân nhắc **4 yếu tố chính**:

### 1. 📜 Tuân thủ pháp lý (Compliance)
```
┌─────────────────────────────────────────────────────────────┐
│  Một số quốc gia yêu cầu dữ liệu phải lưu trữ trong nước:  │
│                                                             │
│  🇻🇳 Việt Nam: Luật An ninh mạng - dữ liệu quan trọng      │
│  🇪🇺 EU: GDPR - dữ liệu công dân EU                        │
│  🇨🇳 Trung Quốc: Dữ liệu phải ở trong lãnh thổ             │
└─────────────────────────────────────────────────────────────┘
```

### 2. ⚡ Độ trễ (Latency)
- Chọn Region **gần người dùng cuối nhất**
- Ví dụ: Người dùng ở Việt Nam → Chọn `ap-southeast-1` (Singapore)

```
Độ trễ ước tính từ Việt Nam:
├── Singapore (ap-southeast-1): ~30-50ms  ✅ Tốt nhất
├── Tokyo (ap-northeast-1):     ~80-100ms
├── Sydney (ap-southeast-2):    ~150-180ms
└── US East (us-east-1):        ~200-250ms ❌ Không khuyến khích
```

### 3. 🛠️ Tính khả dụng dịch vụ (Service Availability)
- **Không phải tất cả dịch vụ đều có ở mọi Region**
- Các dịch vụ mới thường ra mắt ở `us-east-1` trước

> 💡 Kiểm tra tại: https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/

### 4. 💰 Giá cả (Pricing)
- **Giá dịch vụ khác nhau giữa các Region**
- Thường `us-east-1` có giá rẻ nhất

| Dịch vụ       | us-east-1 | ap-southeast-1 | Chênh lệch |
| ------------- | --------- | -------------- | ---------- |
| EC2 t3.medium | $0.0416/h | $0.052/h       | +25%       |
| S3 Storage    | $0.023/GB | $0.025/GB      | +9%        |

> 💡 So sánh giá: https://calculator.aws/

### Bảng tổng hợp quyết định:

```
┌─────────────────────────────────────────────────────────────┐
│           FLOWCHART CHỌN AWS REGION                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Có yêu cầu pháp lý về vị trí dữ liệu?                     │
│       │                                                     │
│       ├── CÓ → Chọn Region theo quy định pháp luật         │
│       │                                                     │
│       └── KHÔNG ↓                                           │
│                                                             │
│  Dịch vụ cần dùng có ở Region gần nhất không?              │
│       │                                                     │
│       ├── CÓ → Chọn Region gần người dùng nhất             │
│       │                                                     │
│       └── KHÔNG → Chọn Region gần nhất có dịch vụ đó       │
│                                                             │
│  Cuối cùng: So sánh giá nếu có nhiều lựa chọn              │
└─────────────────────────────────────────────────────────────┘
```

## **AWS Availability Zones**

**Availability Zone (AZ)** là một hoặc nhiều data center riêng biệt trong một Region.

![](https://www.researchgate.net/profile/Ivan_Beres/publication/360541079/figure/fig1/AS:1154856056291328@1652350548135/AWS-Regions-and-Availability-Zones-Scott-nd.ppm)
### Đặc điểm của AZ:

```
┌─────────────────────────────────────────────────────────────┐
│                    REGION (vd: ap-southeast-1)              │
│  ┌─────────────────────────────────────────────────────┐   │
│  │                                                     │   │
│  │   ┌─────────┐    ┌─────────┐    ┌─────────┐        │   │
│  │   │  AZ-1a  │    │  AZ-1b  │    │  AZ-1c  │        │   │
│  │   │ ┌─────┐ │    │ ┌─────┐ │    │ ┌─────┐ │        │   │
│  │   │ │ DC  │ │    │ │ DC  │ │    │ │ DC  │ │        │   │
│  │   │ │ DC  │ │    │ │ DC  │ │    │ │ DC  │ │        │   │
│  │   │ └─────┘ │    │ └─────┘ │    │ └─────┘ │        │   │
│  │   └────┬────┘    └────┬────┘    └────┬────┘        │   │
│  │        │              │              │              │   │
│  │        └──────────────┼──────────────┘              │   │
│  │                       │                             │   │
│  │            Kết nối băng thông cao,                  │   │
│  │            độ trễ < 2ms giữa các AZ                 │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  📍 Khoảng cách giữa các AZ: vài chục km                   │
│  ⚡ Độ trễ giữa các AZ: < 2 milliseconds                   │
└─────────────────────────────────────────────────────────────┘
```

### Thông số kỹ thuật:

| Thuộc tính | Giá trị |
|------------|---------|
| Số AZ tối thiểu/Region | 3 |
| Số AZ tối đa/Region | 6 |
| Khoảng cách giữa các AZ | Vài chục km |
| Độ trễ giữa các AZ | < 2ms |

### Quy tắc đặt tên AZ:
```
<region-code> + <ký tự a/b/c/...>

Ví dụ:
• us-east-1a
• us-east-1b  
• us-east-1c
• ap-southeast-1a
• ap-southeast-1b
```

### Thiết kế chịu lỗi (Fault Tolerance):

```
┌─────────────────────────────────────────────────────────────┐
│  Mỗi AZ có:                                                 │
│  ✅ Nguồn điện riêng biệt                                   │
│  ✅ Hệ thống làm mát riêng                                  │
│  ✅ Kết nối mạng riêng                                      │
│  ✅ Vị trí địa lý cách xa nhau                              │
│                                                             │
│  → Nếu 1 AZ gặp sự cố (mất điện, thiên tai),               │
│    các AZ khác vẫn hoạt động bình thường                   │
└─────────────────────────────────────────────────────────────┘
```

### Best Practice - Triển khai Multi-AZ:

```
                    ┌─────────────────┐
                    │  Load Balancer  │
                    └────────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              ▼              ▼              ▼
         ┌────────┐    ┌────────┐    ┌────────┐
         │ EC2    │    │ EC2    │    │ EC2    │
         │ AZ-1a  │    │ AZ-1b  │    │ AZ-1c  │
         └───┬────┘    └───┬────┘    └───┬────┘
             │             │             │
             ▼             ▼             ▼
         ┌────────┐    ┌────────┐    ┌────────┐
         │ RDS    │◄──►│ RDS    │◄──►│ RDS    │
         │Primary │    │Standby │    │Read    │
         └────────┘    └────────┘    └────────┘
```

## **Edge Locations & Points of Presence**

### Edge Location là gì?

**Edge Location** là các điểm phân phối nội dung (PoP - Points of Presence) giúp đưa nội dung đến gần người dùng hơn.

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│    Người dùng ở Việt Nam                                    │
│           │                                                 │
│           ▼                                                 │
│    ┌──────────────┐     Thay vì request đến                │
│    │Edge Location │     Singapore (30-50ms),                │
│    │  Hà Nội/HCM  │     → Request đến Edge (<10ms)          │
│    └──────┬───────┘                                         │
│           │ (cache miss)                                    │
│           ▼                                                 │
│    ┌──────────────┐                                         │
│    │   Origin     │                                         │
│    │  (S3/EC2)    │                                         │
│    └──────────────┘                                         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Dịch vụ sử dụng Edge Locations:

| Dịch vụ | Chức năng |
|---------|-----------|
| **CloudFront** | CDN - Phân phối nội dung tĩnh/động |
| **Route 53** | DNS - Phân giải tên miền |
| **AWS Shield** | DDoS Protection |
| **AWS WAF** | Web Application Firewall |
| **Lambda@Edge** | Chạy code tại Edge |

## **Các dịch vụ AWS phổ biến**

### Phân loại theo chức năng:

```
┌─────────────────────────────────────────────────────────────┐
│                    AWS SERVICES MAP                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  💻 COMPUTE                    📦 STORAGE                   │
│  ├── EC2 (Virtual Servers)    ├── S3 (Object Storage)      │
│  ├── Lambda (Serverless)      ├── EBS (Block Storage)      │
│  ├── ECS/EKS (Containers)     ├── EFS (File Storage)       │
│  └── Elastic Beanstalk        └── Glacier (Archive)        │
│                                                             │
│  🗄️ DATABASE                   🌐 NETWORKING                │
│  ├── RDS (Relational)         ├── VPC (Virtual Network)    │
│  ├── DynamoDB (NoSQL)         ├── Route 53 (DNS)           │
│  ├── ElastiCache (Cache)      ├── CloudFront (CDN)         │
│  └── Redshift (Data Warehouse)└── API Gateway              │
│                                                             │
│  🔒 SECURITY                   📊 ANALYTICS                 │
│  ├── IAM (Identity)           ├── Athena (Query S3)        │
│  ├── KMS (Encryption)         ├── Kinesis (Streaming)      │
│  ├── Cognito (User Auth)      ├── EMR (Big Data)           │
│  └── WAF & Shield             └── QuickSight (BI)          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Dịch vụ Global vs Regional:

| Global Services | Regional Services |
|-----------------|-------------------|
| IAM | EC2 |
| Route 53 | S3 |
| CloudFront | RDS |
| WAF & Shield | Lambda |

## **Tóm tắt & Key Points cho kỳ thi SAA-C03**

```
┌─────────────────────────────────────────────────────────────┐
│                   📝 KEY TAKEAWAYS                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. Region = Khu vực địa lý độc lập                        │
│     → Chọn dựa trên: Compliance > Latency > Services > $   │
│                                                             │
│  2. AZ = Data center(s) trong Region                       │
│     → Tối thiểu 3 AZ/Region, kết nối <2ms latency          │
│     → Triển khai Multi-AZ cho High Availability            │
│                                                             │
│  3. Edge Location = Điểm phân phối nội dung               │
│     → Dùng cho CloudFront, Route 53                        │
│     → Số lượng Edge > AZ > Region                          │
│                                                             │
│  4. Hầu hết services là Region-scoped                      │
│     → Trừ: IAM, Route 53, CloudFront, WAF                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```
