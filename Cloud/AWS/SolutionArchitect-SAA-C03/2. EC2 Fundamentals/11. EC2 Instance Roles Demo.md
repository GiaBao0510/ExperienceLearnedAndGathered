## Mục Tiêu

Bài này thực hành gắn **IAM Role** vào một EC2 Instance để instance đó có quyền gọi API của AWS (ví dụ xem danh sách IAM User) — mà **không cần** nhúng Access Key vào bên trong instance. Đây là cách làm chuẩn và an toàn nhất để cấp quyền cho ứng dụng chạy trên EC2.

![](https://i.ibb.co/b575w5dt/image.png)

## Khái Niệm Nền: Instance Profile Là Gì

 nói đơn giản là "gắn Role vào Instance", nhưng về mặt kỹ thuật, bạn không gắn IAM Role trực tiếp vào EC2 Instance — bạn gắn một **Instance Profile**, và Instance Profile đó mới chứa IAM Role bên trong. Khi bạn chọn Role trong Console (như ở Bước 4 dưới đây), AWS **tự động tạo Instance Profile tương ứng giúp bạn** nên trong thực hành thường thấy việc này "vô hình" — nhưng khi dùng AWS CLI hoặc CloudFormation để gắn Role cho EC2, bạn sẽ cần thao tác trực tiếp với Instance Profile [^1].

Khi Role đã được gắn, EC2 Instance sẽ tự động nhận được **thông tin xác thực tạm thời** (temporary credentials) thông qua **Instance Metadata Service (IMDS)** — AWS tự sinh, tự xoay vòng (rotate) các credentials này theo định kỳ, bạn không bao giờ thấy hay phải quản lý Access Key thủ công. Đây chính là lý do tại sao sau khi gắn Role, lệnh `aws iam list-users` chạy được ngay mà không cần `aws configure`.

## Bước 1: Kết Nối Vào Instance

Kết nối vào EC2 Instance bằng SSH hoặc **EC2 Instance Connect** đều được — ở đây dùng EC2 Instance Connect vì tiện lợi, chạy ngay trên trình duyệt.

![](https://i.ibb.co/8gqLJs1T/image.png)

Sau khi đăng nhập, bạn sẽ thấy dấu nhắc dạng `ec2-user@ip-xxx-xxx-xxx-xxx`, xác nhận bạn đang ở trong instance — dù dùng cách kết nối nào (SSH qua terminal, PuTTY, hay EC2 Instance Connect), kết quả vào bên trong instance đều giống nhau. Bạn có thể thử vài lệnh Linux cơ bản như `ping google.com` (nhấn `Ctrl + C` để thoát) để xác nhận instance có kết nối mạng bình thường.

## Bước 2: Thử Chạy Lệnh IAM Khi Chưa Có Quyền

Amazon Linux đi kèm sẵn **AWS CLI** (đã cài đặt từ trước, không cần cài thêm). Gõ `clear` để xóa màn hình, rồi thử chạy:

```bash
aws iam list-users
```

![](https://i.ibb.co/PZv4BYWY/image.png)

Lệnh này sẽ báo lỗi vì instance **chưa có quyền truy cập AWS API** nào cả:

```
Unable to locate credentials. You can configure credentials by running "aws configure".
```

## Vì Sao KHÔNG Nên Chạy `aws configure` Trên EC2

Về lý thuyết, bạn có thể chạy `aws configure` và nhập **Access Key ID**, **Secret Access Key**, **Region** cá nhân để lệnh trên chạy được — nhưng đây là **một ý tưởng rất tệ**.

![](https://i.ibb.co/LDKF3sM5/image.png)

Lý do: nếu bạn nhập thông tin xác thực cá nhân vào một EC2 Instance, thì **bất kỳ ai khác có quyền truy cập vào tài khoản AWS** (ví dụ qua EC2 Instance Connect hoặc SSH) đều có thể đăng nhập vào instance đó và **đọc lại được** Access Key/Secret Key đã lưu trong file cấu hình — từ đó mạo danh chính bạn để gọi API AWS ở bất kỳ đâu khác, không chỉ giới hạn trong instance này.

> **Nguyên tắc chung:** không bao giờ nhúng Access Key ID / Secret Access Key cá nhân vào bên trong một EC2 Instance (hay bất kỳ server nào). Thay vào đó, luôn dùng **IAM Role** gắn cho instance.

## Bước 3: Xem Lại IAM Role Demo Đã Tạo

Quay lại **IAM Console > Roles**, mở lại Role demo đã tạo ở bài trước:

![](https://i.ibb.co/v6TSW4mw/image.png) ![](https://i.ibb.co/ymXKLMXY/image.png) ![](https://i.ibb.co/FFxXZdp/image.png)

Role này (`DemoRoleForEC2`) đã có sẵn chính sách được đính kèm tên **`IAMReadOnlyAccess`** — một AWS Managed Policy cho phép xem (read-only) thông tin IAM như danh sách User, Role, Policy, nhưng không cho phép chỉnh sửa.

![](https://i.ibb.co/84nR2Q24/image.png) ![](https://i.ibb.co/Xk3fwJsW/image.png)

## Bước 4: Gắn Role Vào Instance

Vào EC2 Instance `First_01`, chọn **Actions > Security > Modify IAM role**, rồi chọn Role `DemoRoleForEC2` để gắn vào instance:

![](https://i.ibb.co/DBCDhnh/image.png)

Sau khi gắn, kiểm tra lại bằng cách cuộn xuống phần **Instance summary**, chọn tab **Security** — mục **IAM Role** trong phần Security details sẽ hiển thị đúng `DemoRoleForEC2` đã thiết lập.

![](https://i.ibb.co/spVQJgBs/image.png)

Nếu muốn chỉnh sửa lại sau này, luôn có thể quay lại qua **Actions > Security > Modify IAM role**:

![](https://i.ibb.co/TMfYGbSq/image.png) ![](https://i.ibb.co/vvZRXRQK/image.png)

Tại màn hình này, bạn có thể tự do đổi sang Role khác cho instance bất kỳ lúc nào:

![](https://i.ibb.co/qLBzYZST/image.png)

## Bước 5: Kiểm Tra Sau Khi Gắn Role

Quay lại phần **Connect to instance**, chọn **EC2 Instance Connect**, nhấn **Connect**:

![](https://i.ibb.co/Mjmfrfz/image.png)

Chạy lại đúng lệnh lúc nãy:

```bash
aws iam list-users
```

![](https://i.ibb.co/chsGLDtS/image.png)

Lần này lệnh chạy **thành công**, trả về danh sách IAM User trong tài khoản — dù ta **không hề chạy `aws configure`** hay nhập bất kỳ Access Key nào. Chỉ cần gắn đúng IAM Role là đủ để instance tự động có quyền gọi API tương ứng.

## Bước 6: Gỡ Role Và Quan Sát Hậu Quả

Để kiểm chứng ngược lại, quay lại **Actions > Security > Modify IAM role**, đổi về **No IAM Role** để gỡ bỏ quyền đã gắn:

![](https://i.ibb.co/vvvsR4vL/image.png)

Quay lại phiên kết nối cũ (không cần kết nối lại từ đầu), chạy lại lệnh:

```
[ec2-user@ip-172-31-20-22 ~]$ aws iam list-users

Unable to locate credentials. You can configure credentials by running "aws configure".
```

Lệnh lại báo lỗi y hệt Bước 2 — xác nhận rằng quyền gọi API hoàn toàn đến từ IAM Role đang gắn, **không phải** từ bất kỳ cấu hình nào lưu sẵn trên instance. Gắn lại Role `DemoRoleForEC2` sẽ khôi phục quyền truy cập như cũ.

## Mở Rộng

- **Instance Profile qua AWS CLI** — khi tự động hóa (Terraform, CloudFormation, AWS CLI) thay vì dùng Console, bạn cần tạo Instance Profile rồi gắn Role vào đó bằng lệnh `aws iam add-role-to-instance-profile`, sau đó mới gắn Instance Profile cho EC2 bằng `aws ec2 associate-iam-instance-profile`.
- **IMDSv2 (Instance Metadata Service version 2)** — phiên bản bảo mật hơn của cơ chế lấy credentials tạm thời trên EC2, giúp chống lại một số kiểu tấn công SSRF.
- **Least Privilege cho IAM Role** — thay vì dùng policy rộng như `IAMReadOnlyAccess`, trong thực tế nên tạo policy tùy chỉnh chỉ cấp đúng quyền ứng dụng cần.
- **AWS Secrets Manager / Parameter Store** — nếu ứng dụng thật sự cần một số loại "secret" khác (không phải AWS credentials, ví dụ mật khẩu database), đây là nơi lưu trữ an toàn hơn so với việc hardcode trong code hoặc file cấu hình trên instance.
