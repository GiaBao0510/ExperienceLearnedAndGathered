## Mục Tiêu Bài Thực Hành

Trong bài này, bạn sẽ tạo **EC2 Instance đầu tiên** chạy Amazon Linux bằng AWS Console. Cụ thể, bạn sẽ:

- Khởi tạo một máy chủ ảo (EC2 Instance) bằng AWS Console.
- Làm quen với các tham số khi khởi chạy instance — có rất nhiều tham số, nhưng chúng ta chỉ tập trung vào những tham số quan trọng nhất.
- Dựng một **web server** tự động bằng **EC2 User Data** (một đoạn script được truyền vào instance để chạy khi khởi động lần đầu).
- Biết cách **dừng (stop), khởi động (start) và chấm dứt (terminate)** một instance.

> ⚠️ AWS khuyến nghị chuyển sang **Amazon Linux 2023** [^1]. Khi thực hành hôm nay, hãy ưu tiên chọn **Amazon Linux 2023**. Script User Data ở Bước 8 vẫn chạy được trên Amazon Linux 2023, vì lệnh `yum` ở đó được giữ lại như một lối tắt trỏ đến `dnf` [^4].

> ⚠️ Danh sách instance type đủ điều kiện Free Tier cũng khác: với tài khoản mới, có `t3.micro`, `t3.small`, `t4g.micro`, `t4g.small`, `c7i-flex.large`, `m7i-flex.large` [^2]. Hãy luôn nhìn nhãn **"Free tier eligible"** trên Console trước khi chọn.

> ⚠️ **3. Địa chỉ Public IPv4 giờ có phí.** Từ **01/02/2024**, AWS tính **0,005 USD/giờ** cho mỗi địa chỉ public IPv4 đang được dùng, kể cả địa chỉ tự động gán cho EC2 [^3]. Con số này tương đương khoảng **3,65 USD/tháng** cho một instance chạy liên tục (0,005 × 730 giờ). Free Tier cũ (tài khoản trước 15/07/2025) có kèm 750 giờ public IPv4 mỗi tháng trong 12 tháng đầu [^3]; tài khoản mới thì khoản này được trừ vào credit.

> 💡 Nếu chưa làm, hãy **đặt ngân sách cảnh báo (AWS Budget)** trước khi tạo instance đầu tiên — xem lại bài _AWS Budget Setup_.

## Thuật Ngữ Cần Biết Trước Khi Bắt Đầu

| Thuật ngữ                      | Ý nghĩa                                                                                                                                 |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| **Instance**                   | Một máy chủ ảo (virtual server) chạy trên hạ tầng của AWS.                                                                              |
| **AMI (Amazon Machine Image)** | "Bản mẫu" hệ điều hành (kèm phần mềm cài sẵn) dùng để khởi tạo instance. Trong video, phần này được gọi là "hình ảnh cơ sở".            |
| **Instance type**              | Cấu hình phần cứng của instance (số CPU, dung lượng RAM...), quyết định giá tiền. Ví dụ: `t2.micro`.                                    |
| **Key pair (cặp khóa)**        | Cặp khóa mật mã gồm khóa công khai (AWS giữ) và khóa riêng (file bạn tải về), dùng để đăng nhập instance qua SSH.                       |
| **SSH**                        | Giao thức đăng nhập từ xa an toàn vào máy chủ Linux, chạy qua cổng (port) 22.                                                           |
| **Security Group**             | "Tường lửa ảo" của instance: quy định lưu lượng mạng nào được phép đi vào (inbound) và đi ra (outbound).                                |
| **EBS (Elastic Block Store)**  | Ổ đĩa ảo gắn vào instance để lưu dữ liệu.                                                                                               |
| **Tag**                        | Nhãn dạng cặp _khóa – giá trị_ (key–value) để gắn vào tài nguyên cho dễ quản lý. Tag có khóa `Name` chính là tên hiển thị của instance. |
| **Public / Private IPv4**      | Public IPv4: địa chỉ để truy cập instance từ Internet. Private IPv4: địa chỉ chỉ dùng trong mạng nội bộ của AWS.                        |

## Bước 4: Chọn Instance Type

**Instance type** khác nhau ở số lượng CPU, dung lượng bộ nhớ và chi phí. Trong video, `t2.micro` được chọn sẵn và có nhãn Free tier eligible: nếu chạy một instance như vậy suốt cả tháng thì vẫn nằm trong hạn mức miễn phí (theo Free Tier cũ).

![](https://i.ibb.co/nsRNTthR/image.png)

Bạn có thể cuộn xuống để xem các instance type khác. Một số loại đủ điều kiện Free Tier, một số thì không. Ví dụ `t1.micro` cũng từng nằm trong Free Tier, nhưng đó là thế hệ cũ hơn. Theo mặc định, loại miễn phí được đề xuất là `t2.micro` (hoặc `t3.micro` ở những region không có `t2.micro`), và ta sẽ dùng loại này rất nhiều trong khóa học.

![](https://i.ibb.co/MDqxyb8K/image.png)

Nếu muốn so sánh các instance type, hãy nhấn vào liên kết so sánh; bảng sẽ cho bạn thấy dung lượng bộ nhớ, số CPU, v.v. của từng loại.

## Bước 5: Tạo Key Pair

**Key pair** dùng để đăng nhập vào instance. Nó là bắt buộc nếu ta truy cập instance bằng **SSH** — và khóa học này sẽ dùng SSH. Hiện chưa có key pair nào; bạn có thể tiếp tục mà không có key pair, nhưng ta sẽ không làm vậy.

![](https://i.ibb.co/Ld17qJSn/image.png)

Hãy chọn **Create new key pair**, đặt tên (video dùng `FisrtKeyEC2`; bạn có thể đặt tên tùy ý), chọn **loại khóa là RSA**, rồi chọn **định dạng file**:

- **`.pem`**: dùng cho macOS, Linux và Windows 10 trở lên (dùng với SSH có sẵn trong hệ điều hành).
- **`.ppk`**: dùng cho **PuTTY** — công cụ SSH trên các bản Windows cũ như Windows 7 và Windows 8.

Nói ngắn gọn: nếu không dùng Windows 7 hoặc 8, hãy chọn **`.pem`**; ngược lại thì chọn `.ppk`.

![](https://i.ibb.co/v4vVFQt9/image.png)

Nhấn tạo key pair; file khóa sẽ được **tải về máy ngay lập tức** và key pair này được tự động chọn cho instance.

![](https://i.ibb.co/4ZHWWJg2/image.png)

> ⚠️ **Lưu ý:** AWS chỉ cho tải file khóa riêng **một lần duy nhất** lúc tạo. Hãy cất giữ file cẩn thận và không chia sẻ. Trên macOS/Linux, khi dùng file `.pem` để SSH, bạn thường cần thu hẹp quyền truy cập file bằng lệnh `chmod 400 ten-file.pem`, nếu không SSH sẽ từ chối dùng khóa.

## Bước 6: Network Settings Và Security Group

Ở phần **Network settings**, ta tạm thời giữ nguyên mọi thứ. Instance sẽ được gán một **public IP** để ta kết nối tới.

Instance được gắn với một **Security Group** để kiểm soát lưu lượng đi vào và đi ra. Security Group đầu tiên được tạo tự động bởi Console, có tên **`launch-wizard-1`**. Ta có thể định nghĩa nhiều quy tắc (rule):

- **Quy tắc 1 — SSH:** giữ nguyên lựa chọn cho phép lưu lượng **SSH từ mọi nơi**. Rule này để ta đăng nhập vào instance.
- **Quy tắc 2 — HTTP:** đánh dấu ô **cho phép lưu lượng HTTP từ Internet**, vì ta sắp chạy một web server trên instance này.
- **HTTPS:** ta **không dùng HTTPS** trong bài này, nên **không cần đánh dấu ô thứ ba**.

![](https://i.ibb.co/dsTqqJjr/image.png)

> ⚠️ **Lưu ý bảo mật:** Cho phép SSH từ "mọi nơi" (`0.0.0.0/0`) chỉ nên dùng để học tập. Mở cổng 22 cho toàn Internet làm tăng nguy cơ bị dò mật khẩu hàng loạt (brute-force) và các cuộc tấn công khác; khuyến nghị thực tế là giới hạn nguồn SSH chỉ cho địa chỉ IP tin cậy của bạn (ví dụ chọn **My IP** trong Console) [^5]. Đây cũng là một ứng dụng trực tiếp của nguyên tắc tối thiểu quyền đã học ở phần IAM.

## Bước 7: Cấu Hình Storage

Ở phần **Configure storage**, ta có một **root volume** (ổ đĩa gốc) 8 GiB kiểu SSD đa dụng. Trong ảnh minh họa là `gp2`; tùy phiên bản giao diện, bạn có thể thấy `gp3` — cả hai đều là SSD đa dụng (General Purpose SSD). Ta giữ nguyên 8 GiB. Theo Free Tier cũ, hạn mức miễn phí là tối đa 30 GB EBS SSD đa dụng, nên 8 GiB là ổn; và ta chỉ cần một ổ đĩa.

![](https://i.ibb.co/93H7GYQ3/image.png)

Nếu mở phần **Advanced**, bạn thấy được thêm chi tiết. Điều quan trọng cần lưu ý là thiết lập **Delete on termination** (xóa khi chấm dứt instance).

> 🛠️ Với **root volume**, giá trị mặc định là **Yes** — nghĩa là khi bạn _chấm dứt (terminate)_ instance thì **ổ đĩa gốc cũng bị xóa theo** [^6]. Lưu ý thêm: với **ổ dữ liệu bổ sung** gắn thêm lúc khởi chạy bằng Console, mặc định lại là _giữ lại_ (không xóa), và ổ được giữ lại vẫn tiếp tục bị tính phí lưu trữ cho đến khi bạn tự xóa nó [^6].

![](https://i.ibb.co/mrPG0cLJ/image.png)

## Bước 8: Advanced Details Và EC2 User Data

Tiếp theo là phần **Advanced details** — nơi mọi thứ trở nên thú vị. Ta sẽ bỏ qua nhiều mục như _Placement_ và _IAM instance profile_ (sẽ quay lại khi cần, đặc biệt là IAM instance profile để gắn IAM Role cho EC2 như đã học ở bài IAM Roles).

![](https://i.ibb.co/spFhqWRb/image.png)

Hãy cuộn xuống tận cùng, ở đó có ô **User data**.

![](https://i.ibb.co/TMWC0Syw/image.png)

**User data** là nơi ta truyền vào một **script** — một loạt lệnh sẽ được thực thi ở **lần khởi chạy đầu tiên** của instance và **chỉ ở lần đầu tiên** (đây là hành vi mặc định). Ở lần khởi chạy đầu, ta muốn truyền các lệnh sau:

```shell
#!/bin/bash
# Use this for your user data (script from top to bottom)
# install httpd (Linux 2 version)
yum update -y
yum install -y httpd
systemctl start httpd
systemctl enable httpd
echo "<h1>Hello World from $(hostname -f)</h1>" > /var/www/html/index.html
```

Script này làm gì?

| Dòng lệnh                                                                    | Tác dụng                                                                                       |
| ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `yum update -y`                                                              | Cập nhật các gói phần mềm của hệ thống.                                                        |
| `yum install -y httpd`                                                       | Cài **httpd** (Apache HTTP Server) — chính là web server.                                      |
| `systemctl start httpd`                                                      | Khởi động web server ngay.                                                                     |
| `systemctl enable httpd`                                                     | Cho web server tự khởi động cùng hệ thống.                                                     |
| `echo "<h1>Hello World from $(hostname -f)</h1>" > /var/www/html/index.html` | Ghi ra file HTML trang chủ, trong đó `$(hostname -f)` được thay bằng tên máy chủ của instance. |

Cách dùng: sao chép **toàn bộ** đoạn script trên (hoặc lấy từ file tài liệu User Data của phần _EC2 Basics_ trong tài liệu khóa học) rồi **dán vào ô User data**. Bạn không cần hiểu hết từng lệnh — script này chỉ để minh họa; điều cần nhớ là nó chạy **một lần duy nhất** khi instance khởi động lần đầu. Kết quả: instance được cập nhật, cài web server httpd, và tạo một trang HTML — đó chính là website của ta.

Chọn **View all instances** và nhấn **Refresh**. Instance của bạn sẽ ở trạng thái **pending** (đang chờ xử lý) trong một thời gian ngắn — thường chỉ khoảng vài chục giây — rồi chuyển sang **running** (đang chạy).

Đây chính là sức mạnh của đám mây: bạn có thể tạo một hay thậm chí 100 instance như vậy rất nhanh mà **không cần sở hữu bất kỳ máy chủ vật lý nào**. Ta mới chỉ chạm vào bề mặt sức mạnh của đám mây.

## Kiểm Tra Instance Vừa Tạo

Khi instance đã chạy, hãy xem qua một số thông tin quan trọng:

- **Tên** instance và **Instance ID** — mã định danh duy nhất của instance.
- **Public IPv4 address** — địa chỉ ta dùng để truy cập instance từ Internet.
- **Private IPv4 address** — địa chỉ để truy cập nội bộ trong mạng AWS, không truy cập được từ Internet.

![](https://i.ibb.co/33QN0zn/image.png)

Cuộn xuống sẽ thấy thêm chi tiết như **instance type** (`t2.micro`), **AMI** đang dùng (Amazon Linux 2 trong video) và **key pair** đã chọn.

![](https://i.ibb.co/g1fs0ZN/image.png)

Ở tab **Security**, bạn xem thông tin về Security Group `launch-wizard-1` được tạo, cùng các **inbound rules** (quy tắc đi vào).

![](https://i.ibb.co/PZSZ0Yh6/image.png)

Ta thấy **cổng 22 (SSH)** và **cổng 80 (HTTP)** đều cho phép truy cập từ mọi nơi. Bạn cũng nên có kết quả tương tự; nếu không, có thể bạn đã bỏ sót một bước và nên làm lại. Ngoài ra còn có một **outbound rule** cho phép mọi lưu lượng đi ra ngoài, để instance truy cập được Internet.

![](https://i.ibb.co/6cdWmNNp/image.png)

Về lưu trữ, ta thấy đúng như đã cấu hình: một volume 8 GiB.

## Truy Cập Web Server

Để xem web server đang chạy, hãy dùng **Public IPv4 address** của instance: sao chép địa chỉ này, hoặc nhấn **Open address**.

![](https://i.ibb.co/0R7b79dP/image.png)

Có thể lúc đầu trang không hiển thị. Lý do thường gặp là **bạn cần dùng giao thức `http://`** (không phải `https://`) trong URL, ví dụ: `http://<Public-IPv4>`. Nếu dùng HTTPS, trình duyệt sẽ treo ở màn hình tải mãi — vì ta **không mở cổng 443** trong Security Group và web server cũng chưa được cấu hình HTTPS. Tùy trình duyệt, việc nhấn **Open address** có thể tự chuyển sang HTTPS; nếu vậy hãy sao chép địa chỉ, dán vào thanh địa chỉ và gõ `http://` ở đầu.

![](https://i.ibb.co/XZkwhSQw/image.png)

Hãy đảm bảo dùng `http://` cùng với địa chỉ IP, và bạn sẽ thấy trang **Hello World**.

Trong lập trình, khi làm điều gì đó lần đầu tiên, ta thường gõ "Hello World". Trang này hiển thị dòng _Hello World from ..._ kèm một chuỗi dạng `172-31-33-135`. Đây **không phải public IP** mà là địa chỉ **Private IPv4** của instance — vì tên máy chủ (hostname) mặc định của EC2 được đặt dựa trên địa chỉ IPv4 riêng. Nghĩa là: ta truy cập bằng địa chỉ public, nhưng trang do chính ta lập trình (qua User Data) đang hiển thị địa chỉ private.

> ⏳ Nếu trang chưa hiện, đừng vội: User Data cần thời gian để cập nhật hệ thống, cài httpd và tạo file. Hãy đợi khoảng vài phút rồi làm mới trang.

Vậy là bạn đã có một web server đang chạy trên EC2.

## Quản Lý Vòng Đời Instance: Stop, Start, Reboot, Terminate

Bây giờ hãy khám phá một vài thao tác quản lý. Instance đang chạy; nếu chưa cần dùng, bạn có thể vào **Instance state** rồi chọn **Stop instance** (dừng instance).

![](https://i.ibb.co/Q3GvJL3L/image.png)

![](https://i.ibb.co/svp82tLt/image.png)

![](https://i.ibb.co/5hF95mvZ/image.png)

Trên đám mây, bạn có thể bật và tắt instance tùy ý. Vì sao lại dừng? Vì instance chạy càng lâu thì bạn trả càng nhiều tiền. Khi dừng, trang web không còn truy cập được nữa vì máy chủ không chạy.

> 🛠️ . Chính xác hơn: khi instance ở trạng thái **stopped**, bạn **không bị tính phí thời gian chạy (compute)**, nhưng **vẫn bị tính phí lưu trữ cho các ổ EBS** gắn với instance [^7]. Tức là dừng instance giúp giảm chi phí, chứ chưa đưa chi phí về 0.

Bạn cần phân biệt ba thao tác thường gặp:

|Thao tác|Điều gì xảy ra|Public IPv4|
|---|---|---|
|**Reboot** (khởi động lại)|Như khởi động lại hệ điều hành; instance vẫn ở trên cùng máy chủ vật lý, giữ nguyên public DNS name, private IP và dữ liệu instance store [^7].|**Giữ nguyên**|
|**Stop → Start**|Dừng rồi bật lại; ổ EBS và private IPv4 vẫn còn, nhưng dữ liệu trên instance store và RAM mất đi [^8].|**Đổi sang địa chỉ mới** [^8]|
|**Terminate** (chấm dứt)|Xóa hẳn instance, **không thể khôi phục**; root volume bị xóa theo nếu _Delete on termination_ = Yes [^6].|Không còn|

> 🛠️Chính xác hơn: địa chỉ public IPv4 do AWS tự động gán sẽ **bị thu hồi khi bạn _stop_** và một địa chỉ **mới** được cấp khi _start_ lại; còn **reboot thì giữ nguyên** [^7][^8]. Nếu cần một địa chỉ public không đổi, bạn dùng **Elastic IP** gắn vào instance [^8].

Trên đám mây, việc tạo instance rồi bỏ đi là chuyện bình thường; ta có thể thử nghiệm rất nhanh. Để xóa hẳn instance, chọn **Instance state → Terminate instance**; Console sẽ hiện một **cảnh báo xác nhận** trước khi thực hiện.

![](https://i.ibb.co/HfvscfvW/image.png)

![](https://i.ibb.co/qMFmzmjJ/image.png)

## Mở Rộng

- **Elastic IP** — địa chỉ public IPv4 tĩnh, không đổi khi stop/start; lưu ý cũng có phí khi để không dùng.
- **Amazon Linux 2023 (AL2023) và DNF** — hệ điều hành mới thay thế Amazon Linux 2, dùng `dnf` làm trình quản lý gói.
- **Gỡ lỗi User Data** — đọc file log `/var/log/cloud-init-output.log` trên instance để xem script chạy có lỗi không.
- **Kết nối SSH vào instance** — dùng key pair vừa tạo để đăng nhập và tự kiểm tra web server.
- **EC2 Instance Connect và AWS Systems Manager Session Manager** — cách đăng nhập instance mà không cần mở cổng 22 cho toàn Internet.
- **Security Group nâng cao** — giới hạn nguồn (source) theo IP hoặc theo Security Group khác, thay vì mở cho mọi nơi.
- **Tạo AMI riêng (Custom AMI)** — đóng gói cấu hình đã cài sẵn để khởi tạo nhanh nhiều instance giống nhau.
- **Các hình thức thanh toán EC2** — On-Demand, Reserved, Savings Plans, Spot; và Free Tier so với mô hình credit mới.
