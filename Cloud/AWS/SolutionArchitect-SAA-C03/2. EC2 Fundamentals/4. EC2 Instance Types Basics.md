## EC2 Instance Types Là Gì?

AWS cung cấp nhiều **loại instance (Instance Type)** khác nhau, mỗi loại được tối ưu hóa cho một nhóm tác vụ riêng. Danh sách đầy đủ và luôn được cập nhật nằm tại: https://aws.amazon.com/ec2/instance-types/

![](https://i.ibb.co/hFTnmgLM/image.png)

Về tổng thể, các Instance Type được chia thành 6 nhóm chính [^1]:

|Nhóm|Tối ưu cho|
|---|---|
|**General Purpose**|Cân bằng giữa CPU, RAM, mạng — phù hợp đa số tác vụ|
|**Compute Optimized**|Tác vụ cần nhiều CPU|
|**Memory Optimized**|Tác vụ xử lý dữ liệu lớn ngay trong RAM|
|**Storage Optimized**|Tác vụ cần đọc/ghi tốc độ cao trên ổ đĩa cục bộ|
|**Accelerated Computing**|Tác vụ cần phần cứng tăng tốc (GPU, FPGA...)|
|**HPC Optimized**|Tính toán hiệu năng cao (High Performance Computing) quy mô lớn|

> 📌 Danh sách này thay đổi theo thời gian khi AWS ra mắt instance mới — hãy luôn kiểm tra lại trang chính thức thay vì chỉ dựa vào tài liệu này.

## Quy Tắc Đặt Tên

AWS đặt tên Instance Type theo một quy tắc chung. Ví dụ: `m5.2xlarge`

|Thành phần|Ý nghĩa|Ví dụ trong `m5.2xlarge`|
|---|---|---|
|**Instance class**|Dòng/họ instance (nhóm tối ưu hóa)|`m` (General Purpose)|
|**Generation**|Thế hệ — AWS liên tục cải tiến, ra mắt thế hệ mới theo thời gian|`5`|
|**Size**|Kích cỡ trong cùng một dòng|`2xlarge`|

Bạn không cần học thuộc từng loại instance cụ thể, nhưng hiểu được cách đọc tên là đủ để tra cứu và lựa chọn phù hợp khi cần.

## General Purpose

**Đặc điểm:**

- Phù hợp cho nhiều loại khối lượng công việc đa dạng, ví dụ: máy chủ web (web server), kho lưu trữ mã nguồn (code repository).
- Cân bằng giữa 3 yếu tố: khả năng tính toán (compute), bộ nhớ (memory), mạng (network).

Trong khóa học này, ta chủ yếu dùng `t2.micro` — một Instance Type thuộc dòng **General Purpose**.

![](https://iili.io/nYH5Yib.png)

Trang AWS liệt kê đầy đủ các Instance Type thuộc nhóm General Purpose; danh sách này thay đổi theo thời gian nên bạn nên tra cứu trực tiếp trên trang AWS thay vì chỉ dựa vào tài liệu này.

## Compute Optimized

**Đặc điểm:** phù hợp cho các tác vụ đòi hỏi CPU mạnh (compute-bound), hưởng lợi từ bộ xử lý hiệu năng cao.

**Các trường hợp sử dụng:**

- Xử lý theo lô (batch processing)
- Chuyển mã (transcoding) media
- Máy chủ web hiệu năng cao (high performance web server)
- Tính toán hiệu năng cao (HPC)
- Mô hình hóa khoa học (scientific modeling) & suy luận Machine Learning (ML inference)
- Máy chủ game chuyên dụng (dedicated gaming server)

![](https://ik.imagekit.io/giabao0510/image.png)

Các Instance Type thuộc nhóm Compute Optimized hiện đều nằm trong dòng **C** (ví dụ: C5, C6g...).

> 🛠️ **Đính chính quan trọng:** Tài liệu gốc mô tả mục này bằng nội dung thực chất thuộc về nhóm **Memory Optimized** (xử lý dữ liệu lớn trong RAM, cơ sở dữ liệu in-memory, cache phân tán, BI...) — đây là lỗi sao chép nhầm nội dung giữa hai mục trong bản gốc. Nội dung ở trên đã được thay bằng mô tả chính xác của **Compute Optimized** theo tài liệu chính thức AWS [^2].

## Memory Optimized

**Đặc điểm:** thiết kế để đạt hiệu năng cao cho các tác vụ xử lý tập dữ liệu lớn **ngay trong bộ nhớ (in-memory)**.

**Các trường hợp sử dụng:**

- Cơ sở dữ liệu quan hệ/phi quan hệ hiệu năng cao
- Hệ thống cache phân tán quy mô lớn (web-scale distributed cache)
- Cơ sở dữ liệu in-memory tối ưu cho BI (trí tuệ doanh nghiệp)
- Ứng dụng xử lý dữ liệu lớn phi cấu trúc theo thời gian thực

![](https://ik.imagekit.io/giabao0510/image2.png)

Về tên gọi: các Instance Type tối ưu bộ nhớ thuộc dòng **R** (R là viết tắt của RAM), bên cạnh đó còn có dòng **X1** (dung lượng bộ nhớ rất cao) và **Z1**.

Bạn không cần nhớ tên cụ thể từng loại, nhưng nắm được bức tranh tổng quan là rất hữu ích.

> 🛠️ **Đính chính quan trọng:** Tài liệu gốc mô tả mục này bằng nội dung thực chất thuộc về nhóm **Storage Optimized** (đọc/ghi tuần tự tốc độ cao trên ổ đĩa cục bộ) — bị trùng lặp y hệt với nội dung ở mục Storage Optimized bên dưới. Nội dung ở trên đã được thay bằng mô tả chính xác của **Memory Optimized** theo tài liệu chính thức AWS [^2].

## Storage Optimized

**Đặc điểm:** lý tưởng cho các tác vụ đòi hỏi nhiều tài nguyên lưu trữ, cần tốc độ đọc/ghi **tuần tự** cao đối với tập dữ liệu lớn trên **ổ đĩa cục bộ (local storage)**.

**Các trường hợp sử dụng:**

- Hệ thống xử lý giao dịch trực tuyến (OLTP) tần suất cao
- Cơ sở dữ liệu quan hệ và NoSQL
- Bộ nhớ đệm (cache) cho cơ sở dữ liệu in-memory (ví dụ: Redis)
- Ứng dụng kho dữ liệu (data warehousing)
- Hệ thống tệp phân tán (distributed file system)

![](https://ik.imagekit.io/giabao0510/image3.png)

Các Instance Type tối ưu lưu trữ trên AWS có tên bắt đầu bằng chữ **I**, **D** hoặc **H1**.

Bạn không cần ghi nhớ điều này — đây chỉ là ví dụ để bạn hình dung.

## Ví Dụ So Sánh Các Instance Type

![](https://iili.io/nYH1JB1.png)

Hãy so sánh một vài Instance Type cụ thể để thấy rõ sự khác biệt giữa các nhóm:

|Instance Type|vCPU|RAM|Nhận xét|
|---|---|---|---|
|`t2.micro`|1|1 GB|General Purpose — cấu hình tối thiểu, đủ dùng cho học tập, đủ điều kiện Free Tier|
|`r5.16xlarge`|16|512 GB|Memory Optimized — cùng số vCPU với `c5d.4xlarge` bên dưới nhưng RAM lớn hơn rất nhiều, thể hiện rõ đặc trưng "tối ưu bộ nhớ"|
|`c5d.4xlarge`|16|32 GB|Compute Optimized — ít RAM hơn hẳn `r5.16xlarge` nhưng cùng mức CPU, ưu tiên sức mạnh tính toán|

Ngoài vCPU và RAM, các Instance Type còn khác nhau về hiệu năng mạng (network performance) và băng thông EBS (EBS bandwidth) — càng lên các dòng cao cấp, các chỉ số này càng lớn.

**Công cụ so sánh:** để so sánh nhanh toàn bộ Instance Type của AWS (giá On-Demand, giá Reserved, RAM, vCPU...), trang được nhiều người dùng là **ec2instances.info**.

![](https://iili.io/nYHhYlI.png)

> 📌 **Cập nhật:** `ec2instances.info` đã được công ty **Vantage** mua lại từ năm 2021 và hiện hoạt động chính thức tại tên miền **https://instances.vantage.sh** — tên miền cũ vẫn dùng được nhờ redirect [^3]. Trang này cho phép sắp xếp, lọc, tìm kiếm theo tên, xem chi phí (On-Demand, Reserved...), số vCPU và dung lượng RAM của gần như mọi Instance Type hiện có trên AWS (và cả Azure, GCP).

Đây là một công cụ bạn gần như chắc chắn sẽ dùng đến nếu làm việc thường xuyên với AWS.

## Mở Rộng

- **Ý nghĩa các ký tự phụ trong tên Instance** — ví dụ: `g` (chip Graviton/ARM), `a` (chip AMD), `n` (tối ưu mạng), `d` (có ổ NVMe cục bộ đi kèm) — giúp đọc hiểu nhanh một Instance Type chỉ qua tên gọi.
- **Burstable Performance Instances (dòng T)** — như `t2.micro`, `t3.micro` đang dùng trong khóa học: cơ chế "CPU Credit" cho phép tăng tốc CPU tạm thời khi cần.
- **Accelerated Computing & HPC Optimized** — hai nhóm còn lại chưa đi sâu trong bài này, dùng cho Machine Learning training, đồ họa, và các bài toán mô phỏng quy mô siêu lớn.
- **So sánh hình thức thanh toán** — On-Demand, Reserved Instances, Savings Plans, Spot Instances — ảnh hưởng trực tiếp đến chi phí thực tế của từng Instance Type.
- **AWS Compute Optimizer** — công cụ AWS tự động gợi ý Instance Type phù hợp hơn dựa trên mức sử dụng CPU/RAM thực tế của bạn.
