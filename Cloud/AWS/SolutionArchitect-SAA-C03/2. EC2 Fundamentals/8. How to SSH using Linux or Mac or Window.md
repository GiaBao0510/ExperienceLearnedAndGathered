## Mục Tiêu

Bài trước đã giới thiệu khái niệm SSH. Bài này thực hành **kết nối SSH thật** vào EC2 Instance đã tạo, bằng cả Windows (PowerShell) và Linux/macOS — bao gồm xử lý lỗi quyền truy cập file key, một lỗi mà hầu hết người mới học đều gặp ít nhất một lần.

## Sơ Đồ Kết Nối SSH

SSH cho phép bạn điều khiển một máy chủ từ xa hoàn toàn qua giao diện dòng lệnh (terminal), như thể bạn đang ngồi trước máy đó. Đây là một trong những kỹ năng quan trọng nhất khi làm việc với AWS.

Cách nó hoạt động: máy EC2 chạy Amazon Linux có một địa chỉ **Public IP**. Từ bài Security Group trước, cổng **22** (cổng chuẩn của SSH) đã được mở cho phép truy cập. Khi bạn chạy lệnh `ssh` từ máy cá nhân, kết nối sẽ đi qua cổng 22 đó đến EC2 Instance, và từ lúc này, dòng lệnh trên máy bạn thực chất đang chạy "bên trong" máy chủ đó.

![](https://i.ibb.co/s03jGM0/image.png)

## Chuẩn Bị: Tìm File Key Pair (.pem)

Trước khi kết nối, bạn cần biết **đường dẫn đầy đủ** đến file `.pem` đã tải về khi tạo Key Pair ở bài trước (ví dụ `FisrtKeyEC2.pem`). Ví dụ đường dẫn:

```

```

## Kết Nối SSH Trên Windows (PowerShell)

Trên Windows 10 (bản 1809+) hoặc Windows 11, mở **PowerShell** — không cần cài thêm phần mềm vì OpenSSH Client đã được tích hợp sẵn.

![](https://i.ibb.co/TMydnqCL/image.png)

Vào **EC2 > Instances**, chọn instance đã tạo trước đó, copy địa chỉ **Public IPv4**.

![](https://i.ibb.co/RT50KLwJ/image.png)

Trong PowerShell, di chuyển đến thư mục chứa file `.pem`:

![](https://i.ibb.co/3m859g1Z/image.png)

Sau đó chạy lệnh kết nối:

```powershell
ssh -i FisrtKeyEC2.pem ec2-user@23.23.46.242
```

Cú pháp gồm 3 phần: `ssh -i <đường-dẫn-file-key> <username>@<Public-IP>`. Ta dùng username **`ec2-user`** vì AMI Amazon Linux (cả Amazon Linux 2 và Amazon Linux 2023) đều có sẵn một user hệ thống tên `ec2-user` được tạo tự động — đây là user mặc định để đăng nhập, khác với `root`.

![](https://i.ibb.co/6RncTjHH/image.png)

## Lỗi "Unprotected Private Key File" Và Cách Khắc Phục Trên Windows

### Nguyên nhân

Lỗi này xảy ra vì file key `.pem` có **quyền truy cập quá rộng**. Trên Windows, file nằm trong một thư mục thường thừa hưởng quyền từ thư mục cha — nên nhóm **Authenticated Users** (mọi tài khoản đã đăng nhập máy) cũng có quyền đọc được file. OpenSSH yêu cầu private key chỉ được **đúng một mình bạn** truy cập; nếu phát hiện quyền quá rộng, OpenSSH sẽ **bỏ qua key đó hoàn toàn** (không dùng để xác thực), nên server trả lại lỗi `Permission denied`.

Đây là yêu cầu bắt buộc của AWS/OpenSSH đối với mọi private key, được ghi rõ trong tài liệu chính thức [^1].

### Khắc phục bằng `icacls` (PowerShell)

## Kết Nối SSH Trên Linux / macOS

Trên Linux hoặc macOS, lệnh `ssh` đã có sẵn trong Terminal — không cần cài gì thêm. Tuy nhiên, hệ thống file quyền truy cập trên Linux/macOS hoạt động khác Windows, nên khi chạy:

```shell
ssh -i FisrtKeyEC2.pem ec2-user@23.23.46.242
```

bạn có thể gặp lỗi tương tự, nhưng với thông báo khác:

```shell
~/aws-course ssh -i FisrtKeyEC2.pem ec2-user@23.23.46.242
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@         WARNING: UNPROTECTED PRIVATE KEY FILE!          @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
Permissions 0644 for 'FisrtKeyEC2.pem' are too open.
It is required that your private key files are NOT accessible by others.
This private key will be ignored.
Load key "FisrtKeyEC2.pem": bad permissions
Received disconnect from 23.23.46.242 port 22:2: Too many authentication failures
Disconnected from 23.23.46.242 port 22
```

Nguyên nhân giống hệt trên Windows: quyền file (`0644` — chủ sở hữu đọc/ghi, nhóm và người khác đều đọc được) quá rộng so với yêu cầu của OpenSSH. Cách khắc phục trên Linux/macOS đơn giản hơn, chỉ cần một lệnh `chmod` để giới hạn quyền chỉ còn "chủ sở hữu đọc" (`400`) [^1]:

```shell
chmod 400 FisrtKeyEC2.pem
```

Sau đó chạy lại lệnh kết nối:

```shell
ssh -i FisrtKeyEC2.pem ec2-user@23.23.46.242
```

là kết nối thành công.

## Thoát Phiên SSH

Có ba cách tương đương để kết thúc phiên SSH và trở về terminal của máy cá nhân:

- Gõ lệnh `logout`:

```shell
[ec2-user@ip-172-31-20-22 ~]$ logout
Connection to 23.23.46.242 closed.
```

- Gõ lệnh `exit` — tương đương `logout`.
- Nhấn **Ctrl + D** (gửi tín hiệu kết thúc nhập liệu — EOF) để đóng phiên ngay lập tức.

> **Ghi chú đính chính:** tài liệu gốc ghi là "kiểm soát G" (Ctrl+G) để đóng kết nối — đây gần như chắc chắn là lỗi phiên âm khi chuyển giọng nói thành văn bản. Tổ hợp phím chuẩn để đóng một phiên shell/SSH là **Ctrl+D**, không có tổ hợp Ctrl+G nào mang chức năng này trong terminal thông thường. Nếu không chắc, cách an toàn nhất vẫn là gõ `exit` hoặc `logout`.

Khi muốn kết nối lại, nhớ rằng nếu bạn đã **dừng (stop) rồi khởi động lại (start)** instance, địa chỉ **Public IP sẽ thay đổi** — cần cập nhật lại IP trong lệnh `ssh` (trừ khi bạn đã gắn Elastic IP cho instance).

## Mở Rộng

- **File cấu hình `~/.ssh/config`** — OpenSSH cho phép đặt "alias" cho từng server để không phải nhớ IP và đường dẫn key mỗi lần, ví dụ:
    
    ```
    Host my-ec2
        HostName 23.23.46.242
        User ec2-user
        IdentityFile ~/.ssh/FisrtKeyEC2.pem
    ```
    
    Sau khi lưu, chỉ cần gõ `ssh my-ec2` thay vì gõ đầy đủ IP và đường dẫn key [^2].
    
- **Elastic IP** — giải pháp để Public IP không đổi mỗi lần stop/start instance, tránh phải sửa lệnh SSH liên tục.
    
- **SSH Agent / `ssh-add`** — nạp key vào bộ nhớ tạm của hệ thống để không phải chỉ định `-i` mỗi lần gõ lệnh.
    
- **AWS Systems Manager Session Manager** — cách kết nối vào instance không cần mở cổng 22 hay quản lý key pair (đã nhắc ở bài trước).
