## Mục Tiêu

Hai bài trước đã thực hành SSH truyền thống (dùng key `.pem`/PuTTY) và cách xử lý các lỗi thường gặp. Bài này giới thiệu **EC2 Instance Connect** — một cách kết nối thay thế đơn giản hơn nhiều, thực hiện ngay trên trình duyệt mà không cần quản lý file key.

## EC2 Instance Connect Là Gì

EC2 Instance Connect là tính năng của AWS cho phép mở một phiên SSH **ngay trong trình duyệt**, không cần terminal hay phần mềm SSH client riêng. Khi bạn nhấn kết nối, AWS tự tạo một cặp khóa SSH **tạm thời**, đẩy public key lên instance qua API, rồi mở phiên làm việc giúp bạn — bạn không cần tự quản lý key pair nào cả.

## Bước 1: Kết Nối Lần Đầu

Vào chi tiết Instance `First_01`, nhấn nút **Connect** ở phía trên.

![](https://i.ibb.co/yn2SQ8Bp/image.png)

AWS Console sẽ tự xác minh địa chỉ **Public IP** và điền sẵn **username mặc định** — ở đây là `ec2-user`, vì AWS nhận diện instance đang chạy **Amazon Linux 2** (AMI nào dùng `ec2-user` làm user hệ thống mặc định thì Console sẽ tự điền tên đó). Bạn có thể ghi đè username này, nhưng kết nối sẽ chỉ thành công nếu bạn nhập đúng user tồn tại trên instance.

Vì cơ chế dùng key tạm thời, màn hình này **không có tùy chọn chọn key pair** như khi SSH truyền thống — hoàn toàn không cần quản lý key.

![](https://i.ibb.co/YnJfRHJ/image.png)

## Bước 2: Khắc Phục Lỗi SSM Session Manager

Khi vào phần **Connect** của instance, bạn có thể chỉ thấy 2 trong 4 phương thức kết nối (ví dụ chỉ có **SSH client** và **SSM Session Manager**, thiếu EC2 Instance Connect). Nếu tab **SSM Session Manager** báo lỗi:

```
To connect to an instance using SSM Session Manager, link an IAM role with required permissions to this instance.
```

thì cần gán một **IAM Role** có quyền phù hợp (thường là policy quản lý `AmazonSSMManagedInstanceCore`) cho instance. Vào **Modify IAM role** để cập nhật:

## EC2 Instance Connect Và EC2 Instance Connect Endpoint Khác Nhau Thế Nào

Đây là một khái niệm nền tảng quan trọng nên được làm rõ:

- **EC2 Instance Connect** (tab đang dùng trong bài) — vẫn kết nối qua **cổng 22 công khai** của instance, chỉ khác là AWS tự động xử lý việc tạo và nạp key tạm thời giúp bạn. Vì vậy, instance **vẫn cần có Public IP và mở cổng 22** trong Security Group — đây chính là lý do thí nghiệm ở Bước 4 bên dưới sẽ thất bại khi ta xóa rule SSH.
- **EC2 Instance Connect Endpoint** (tính năng mới hơn, ra mắt 2023) — cho phép kết nối đến instance **hoàn toàn không cần Public IP và không cần mở cổng 22 ra Internet**. Kết nối đi qua một "endpoint" riêng đặt trong VPC, traffic được xem là đến từ chính endpoint đó nên không phụ thuộc rule inbound mở ra `0.0.0.0/0` — an toàn hơn đáng kể cho các instance chạy trong private subnet [^1].

Nói ngắn gọn: EC2 Instance Connect (thường) = SSH qua cổng 22 nhưng không cần quản lý key; EC2 Instance Connect **Endpoint** = không cần cổng 22 mở ra Internet luôn.

## Bước 3: Kết Nối Thành Công Và Kiểm Tra

Nhấn **Connect**, một tab mới sẽ mở ra và đăng nhập thẳng vào Amazon Linux 2 — không cần qua terminal hay cài phần mềm gì. Thử chạy vài lệnh kiểm tra:

```bash
whoami
ping google.com
```

Mọi thứ hoạt động bình thường, chỉ khác là toàn bộ phiên làm việc diễn ra **ngay trong trình duyệt**.

![](https://i.ibb.co/q31nsHjv/image.png)

> Lưu ý: trong khóa học, dù bạn chọn SSH qua terminal, qua PuTTY, hay qua công cụ dòng lệnh **`mssh`** (EC2 Instance Connect CLI — một tiện ích chính thức của AWS giúp gọi `ssh`/`sftp` thông qua cơ chế EC2 Instance Connect mà không cần quản lý key thủ công [^2]), kết quả cuối cùng đều như nhau: bạn có quyền truy cập dòng lệnh vào instance.

## Bước 5: Mở Lại Rule SSH

Quay lại Security Group, **thêm lại rule SSH** cho phép từ **Anywhere-IPv4** (`0.0.0.0/0`), rồi **Save rules**:

![](https://i.ibb.co/KpRfHtsC/image.png)

> **Lưu ý về IPv6:** nếu máy bạn hoặc mạng bạn đang dùng ưu tiên kết nối qua **IPv6**, chỉ mở rule cho IPv4 có thể chưa đủ — cần thêm một rule SSH tương tự cho **Anywhere-IPv6** (`::/0`). Việc cần thêm một hay cả hai rule tùy thuộc vào cấu hình mạng của từng người.

## Mở Rộng

- **EC2 Instance Connect Endpoint chi tiết** — cách cấu hình để loại bỏ hoàn toàn nhu cầu Public IP cho các instance trong private subnet.
- **AWS Managed Prefix List cho EC2 Instance Connect** — thay vì mở SSH `0.0.0.0/0`, AWS cung cấp sẵn một prefix list chứa đúng dải IP của dịch vụ EC2 Instance Connect theo từng region, giúp thu hẹp phạm vi rule an toàn hơn.
- **EC2 Instance Connect CLI (`mssh`, `msftp`)** — cài qua `pip install ec2instanceconnectcli`, dùng được như lệnh `ssh`/`sftp` thông thường nhưng tận dụng cơ chế key tạm thời.
- **IAM permissions cho EC2 Instance Connect** — quyền `ec2-instance-connect:SendSSHPublicKey` cần có trong policy của user/role thực hiện kết nối (khác với quyền của chính instance).
