## Mục Tiêu

Sau khi đã khởi chạy một EC2 Instance (bài trước), bước tiếp theo — và cũng là bước nhiều người mới học thấy rắc rối nhất — là **kết nối vào bên trong máy chủ đó** để thực hiện các thao tác bảo trì, cài đặt phần mềm, hoặc quản trị hệ thống. Bài này giới thiệu khái niệm SSH và các cách kết nối khác nhau tùy theo hệ điều hành bạn đang dùng trên máy tính cá nhân.

## SSH Là Gì

**SSH (Secure Shell)** là một giao thức (protocol) cho phép bạn mở một **phiên làm việc dòng lệnh an toàn (secure shell)** từ máy tính của bạn đến một máy chủ ở xa — trong trường hợp này là EC2 Instance chạy Linux. Toàn bộ dữ liệu trao đổi giữa hai bên đều được **mã hóa**, nhờ đó không ai có thể nghe lén nội dung bạn gõ hoặc dữ liệu trả về.

Về mặt kỹ thuật, SSH kết hợp hai cơ chế mã hóa:

- **Mã hóa bất đối xứng (asymmetric)** — dùng cặp khóa public/private (chính là file `.pem` bạn đã tải về khi tạo Key Pair ở bài trước) để **xác thực danh tính** bạn với máy chủ, không cần gửi mật khẩu qua mạng.
- **Mã hóa đối xứng (symmetric)** — sau khi xác thực thành công, toàn bộ dữ liệu của phiên làm việc được mã hóa bằng một khóa phiên dùng chung, giúp việc truyền dữ liệu nhanh hơn.

> _Ghi chú: hình minh họa "Symmetric Encryption" trong tài liệu gốc mô tả đúng cơ chế mã hóa dữ liệu trong phiên làm việc, nhưng việc xác thực ban đầu bằng Key Pair lại là mã hóa bất đối xứng — hai khái niệm này bổ sung cho nhau trong SSH, không mâu thuẫn._

SSH mặc định hoạt động trên **cổng 22** — đây chính là lý do rule "SSH" trong Security Group ở các bài trước luôn mở cổng 22.

Ví dụ lệnh SSH cơ bản để kết nối vào một EC2 Instance chạy Amazon Linux:

```bash
ssh -i "my-key-pair.pem" ec2-user@<Public-IPv4-của-instance>
```

Trong đó:

- `-i "my-key-pair.pem"` — chỉ định file private key đã tải về lúc tạo Key Pair.
- `ec2-user` — tên user mặc định trên các AMI Amazon Linux (các distro khác có thể khác, ví dụ `ubuntu` cho Ubuntu).
- `<Public-IPv4-của-instance>` — địa chỉ IP công khai của EC2 Instance, xem trong tab **Details**.

## Kết Nối Theo Từng Hệ Điều Hành

### Mac / Linux

Mac và Linux đều có sẵn tiện ích dòng lệnh `ssh` tích hợp sẵn trong Terminal — không cần cài thêm gì, dùng ngay lệnh `ssh` như ví dụ ở trên.

### Windows

- **Windows 10 (bản 1809 trở lên) và Windows 11:** đã có sẵn OpenSSH Client tích hợp, dùng được lệnh `ssh` trực tiếp trong Command Prompt hoặc PowerShell, giống hệt Mac/Linux.
- **Windows cũ hơn (dưới bản 1809):** cần dùng một phần mềm riêng tên **PuTTY** — PuTTY thực hiện đúng chức năng tương tự lệnh `ssh`, chỉ khác giao diện là một ứng dụng đồ họa thay vì dòng lệnh thuần túy. PuTTY hoạt động trên mọi phiên bản Windows, kể cả các bản mới.

![](https://st.quantrimang.com/photos/image/2018/07/12/cach-cai-dat-putty-tren-windows-4.jpg)

> Lưu ý: PuTTY yêu cầu định dạng key riêng là `.ppk`, trong khi AWS cung cấp Key Pair ở định dạng `.pem` — cần dùng công cụ đi kèm (PuTTYgen) để chuyển đổi `.pem` sang `.ppk` trước khi dùng.

### EC2 Instance Connect

Một cách kết nối khác không cần cài đặt phần mềm gì cả: **EC2 Instance Connect**. Đây là tính năng của AWS cho phép bạn mở một shell kết nối đến EC2 Instance **ngay trong trình duyệt web**, AWS Console sẽ tự tạo một cặp khóa tạm thời, gửi public key lên instance qua API, rồi mở phiên SSH giùm bạn — bạn không cần quản lý file key nào cả.

![](https://encrypted-tbn0.gstatic.com/images?q=tbn:ANd9GcRBcdzSejng7lYwXxLESPY-Hx6WNsXUzFrvaxYYHlhDq0Qy2s7wKkMfyrI&s=10)

Ưu điểm lớn nhất là nó hoạt động như nhau trên Mac, Linux, hay Windows — vì mọi thứ chạy qua trình duyệt, không phụ thuộc hệ điều hành máy cá nhân.

> **Đính chính:** tài liệu gốc nói EC2 Instance Connect "hiện tại chỉ hoạt động với Amazon Linux 2" — điều này **từng đúng** nhưng đã **lỗi thời**. Theo tài liệu chính thức của AWS, EC2 Instance Connect hiện được **cài đặt sẵn** trên: Amazon Linux 2 (bản 2.0.20190618 trở lên), Amazon Linux 2023, Ubuntu 20.04 trở lên, và macOS (Monterey/Ventura/Sonoma bản mới). Trên các hệ điều hành khác như RHEL, CentOS Stream, hoặc các bản Ubuntu cũ hơn, bạn vẫn dùng được EC2 Instance Connect nhưng cần **cài đặt thủ công** gói `ec2-instance-connect` trước [^1]. Vì khóa học này dùng Amazon Linux 2 cho các bài Hands-On, EC2 Instance Connect sẽ hoạt động ngay mà không cần cài thêm gì.

## Khắc Phục Sự Cố SSH

Theo kinh nghiệm giảng dạy hàng trăm nghìn học viên, **SSH là phần gây khó khăn nhiều nhất** trong khóa học này đối với người mới — thường không phải vì khái niệm khó, mà vì chỉ cần sai một chi tiết nhỏ (sai quyền file key, sai Security Group, gõ nhầm lệnh) là kết nối sẽ thất bại.

Nếu gặp sự cố khi SSH, hãy thử theo thứ tự sau:

1. **Xem lại bài giảng tương ứng với hệ điều hành của bạn** — rất có thể bạn đã bỏ sót một chi tiết nhỏ: thiếu rule trong Security Group, gõ sai lệnh, hoặc nhầm đường dẫn file key.
2. **Đọc hướng dẫn khắc phục sự cố** đi kèm khóa học — đây là tài liệu tổng hợp các lỗi SSH phổ biến nhất mà học viên từng gặp.
3. **Thử dùng EC2 Instance Connect** thay thế — vì không phụ thuộc vào cấu hình SSH client trên máy cá nhân, cách này thường khắc phục được phần lớn các lỗi liên quan đến key hoặc phần mềm.

Nếu **một trong ba cách trên** hoạt động (SSH, PuTTY, hoặc EC2 Instance Connect), bạn đã có thể tiếp tục học bình thường. Nếu **không cách nào hoạt động**, cũng không cần quá lo lắng — các bài Hands-On tiếp theo trong khóa học sẽ không phụ thuộc nhiều vào SSH.

## Mở Rộng

- **AWS Systems Manager Session Manager** — cách kết nối vào EC2 Instance mà **không cần mở cổng 22** hay quản lý key pair nào cả, bảo mật hơn SSH truyền thống trong môi trường production.
- **EC2 Serial Console** — hữu ích khi instance bị lỗi mạng và không thể SSH/Instance Connect được, cho phép truy cập trực tiếp như cắm màn hình vào máy vật lý.
- **Bastion Host (Jump Box)** — mô hình dùng một EC2 Instance trung gian làm cổng vào duy nhất, hạn chế các instance khác lộ cổng SSH ra Internet.
- **Quản lý và xoay vòng (rotate) SSH Key Pair** — thực hành bảo mật nên tìm hiểu khi vận hành hệ thống thật.
