## Kiểm Tra Phiên Bản AWS CLI

Sau khi cài đặt AWS CLI, bạn có thể kiểm tra phiên bản hiện tại bằng lệnh:

```
PS C:\Windows\system32> aws --version
aws-cli/2.0.30 Python/3.7.7 Windows/10 botocore/2.0.0dev34
```

_(Số phiên bản trong ví dụ trên chỉ mang tính minh họa — AWS CLI liên tục phát hành bản cập nhật mới, nên khi bạn tự chạy lệnh này, phiên bản hiển thị chắc chắn sẽ khác.)_

## Cấu Hình AWS CLI Với Access Key

Để AWS CLI có thể thay mặt bạn gọi API AWS, bạn cần cấu hình nó với **Access Key** của một IAM User (xem lại bài trước về Access Keys). Giả sử bạn đã có sẵn một cặp key mẫu như sau:

```
Access key ID:     AKxxxxxxxxxxxxxxxxx
Secret access key: SAKxxxxxxxxxxxxxxx
```

Mở PowerShell (hoặc Terminal trên macOS/Linux) và chạy lệnh `aws configure`, sau đó lần lượt nhập các thông tin được hỏi:

```powershell
PS C:\Windows\system32> aws configure
AWS Access Key ID [None]: AKxxxxxxxxxxxxxxxxx
AWS Secret Access Key [None]: SAKxxxxxxxxxxxxxxx
Default region name [None]: ap-southeast-1
Default output format [None]:
```

- **Default region name**: region mặc định mà CLI sẽ gửi request đến nếu bạn không chỉ định rõ (ví dụ `ap-southeast-1` là khu vực Singapore).
- **Default output format**: định dạng kết quả trả về, để trống sẽ mặc định là `json`.

## Thử Gọi API: Liệt Kê Danh Sách IAM User

Sau khi cấu hình xong, hãy thử gọi một lệnh đơn giản để kiểm tra: liệt kê tất cả IAM User trong tài khoản.

```powershell
PS C:\Windows\system32> aws iam list-users
{
    "Users": [
        {
            "Path": "/",
            "UserName": "admin_01",
            "UserId": "AIDAZMHDW3X2MRRXA3BIW",
            "Arn": "arn:aws:iam::644722646516:user/admin_01",
            "CreateDate": "2026-01-20T06:48:25+00:00"
        },
        {
            "Path": "/",
            "UserName": "NguyenvanA",
            "UserId": "AIDAZMHDW3X2CBS3XV7NC",
            "Arn": "arn:aws:iam::644722646516:user/NguyenvanA",
            "CreateDate": "2026-09-16T08:17:08+00:00",
            "PasswordLastUsed": "2026-09-17T06:47:22+00:00"
        },
        {
            "Path": "/",
            "UserName": "NguyenVanB",
            "UserId": "AIDAZMHDW3X2HSEJDFOQG",
            "Arn": "arn:aws:iam::644722646516:user/NguyenVanB",
            "CreateDate": "2026-09-16T08:55:27+00:00",
            "PasswordLastUsed": "2026-09-16T08:57:03+00:00"
        }
    ]
}
```

Lệnh này gọi API `iam:ListUsers`, trả về danh sách IAM User cùng thông tin cơ bản: `Arn` (định danh duy nhất của user), `CreateDate` (ngày tạo), `PasswordLastUsed` (lần cuối đăng nhập bằng mật khẩu — user nào chưa có trường này nghĩa là chưa từng đăng nhập Console bằng mật khẩu).

> ⚠️ **Đính chính:** Nếu IAM User đang dùng **không có quyền** (permission) để thực hiện một hành động nào đó, AWS **không** trả về kết quả rỗng — mà trả về một **lỗi rõ ràng**, thường có dạng: `An error occurred (AccessDenied) when calling the <Action> operation`. Kết quả rỗng (`"Users": []`) chỉ xảy ra khi bạn **có quyền** thực hiện lệnh nhưng tài nguyên được truy vấn không có gì để trả về (ví dụ: chưa tạo user nào). Phân biệt rõ hai trường hợp này rất quan trọng khi debug lỗi quyền hạn trên AWS.

## AWS CloudShell

**AWS CloudShell** là một terminal chạy ngay trên trình duyệt, không cần cài đặt AWS CLI hay cấu hình access key trên máy — là giải pháp thay thế cho việc dùng terminal cài trên máy tính cá nhân. Biểu tượng CloudShell nằm ở góc trên bên phải (hoặc chân trang) của AWS Management Console.

**Đặc điểm chính:**

- **Miễn phí sử dụng** — bạn chỉ trả phí cho các tài nguyên AWS khác mà mình thao tác thông qua CloudShell.
- **Không có sẵn ở mọi region.** Hiện tại CloudShell được hỗ trợ ở phần lớn (nhưng chưa phải toàn bộ) các region thương mại của AWS — nếu Console của bạn đang ở một region chưa hỗ trợ, hãy đổi sang region khác để dùng thử [^1].
- **Đã pre-authenticated** — CloudShell tự động dùng credentials của phiên đăng nhập Console hiện tại, không cần chạy `aws configure` như CLI cài trên máy.
- **1 GB dung lượng lưu trữ cố định (persistent storage) cho mỗi region**, nằm tại thư mục home (`$HOME`, ví dụ `/home/cloudshell-user`). Dữ liệu trong thư mục home sẽ được giữ lại giữa các phiên làm việc; nếu bạn không dùng CloudShell trong một region suốt 120 ngày, dữ liệu ở region đó sẽ tự động bị xóa [^2].
- Có thể mở **nhiều tab terminal cùng lúc** trong cùng một phiên CloudShell.

### Kiểm tra phiên bản CLI có sẵn trong CloudShell

```cloudshell

```

**Về region:** khi gọi CLI thông thường, bạn có thể chỉ định region bằng tham số `--region`. Trong CloudShell, nếu không chỉ định, region mặc định sẽ là **region hiện tại của phiên Console** mà bạn đang mở CloudShell.

### Thao tác với file trong CloudShell

Mỗi phiên CloudShell mới sẽ trống, nhưng các file bạn lưu trong thư mục home sẽ tồn tại lâu dài (persistent storage). Ví dụ:

```cloudshell
~ $ ls
~ $ echo "Hello world" > demo.txt
~ $ cat demo.txt
Hello world
~ $ ls
demo.txt
~ $
```

Kiểm tra đường dẫn đầy đủ của thư mục hiện tại bằng lệnh `pwd`:

```cloudshell
~ $ pwd
/home/cloudshell-user
```

Bạn cũng có thể chia màn hình để mở **nhiều tab terminal CloudShell cùng lúc** (ví dụ để vừa chạy lệnh, vừa theo dõi log ở tab khác):

![](https://i.ibb.co/6cxz8KC6/image.png)

### Tóm lại

- CloudShell hiện **chưa có ở tất cả region** — hãy chọn một region đã hỗ trợ nếu muốn dùng thử.
- Nếu region bạn cần làm việc chưa hỗ trợ CloudShell, hoặc bạn không muốn dùng CloudShell, dùng AWS CLI cài trên máy (như phần đầu bài học) vẫn hoàn toàn ổn — cả hai đều gọi cùng một bộ API AWS, chỉ khác nơi chạy lệnh.

## Mở Rộng

- **AWS CLI Named Profiles** — quản lý nhiều bộ access keys (nhiều tài khoản/region) trên cùng một máy bằng `aws configure --profile <tên>`.
- **CloudShell VPC environment** — chạy CloudShell bên trong VPC riêng của bạn để truy cập tài nguyên private (lưu ý: cấu hình này _không_ có persistent storage).
- **AWS CloudShell vs AWS Cloud9** — Cloud9 là một IDE đầy đủ chạy trên một EC2 instance (có tính phí), còn CloudShell là công cụ terminal thuần, không cần EC2, miễn phí.
- **IAM Policy Simulator** — công cụ giúp kiểm tra trước một IAM Policy có cho phép một API action cụ thể hay không, tránh phải "thử và sai" bằng CLI như ở trên.
- **AWS SSO / IAM Identity Center** — cách quản lý truy cập tập trung, hạn chế việc phải tạo và phân phát Access Key dài hạn cho từng người dùng.
