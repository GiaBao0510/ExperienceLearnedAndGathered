## 4. Lợi ích của API Gateway

### 4.1. Ẩn kiến trúc nội bộ khỏi bên ngoài

Client chỉ biết và làm việc với các public endpoint do API Gateway cung cấp. Toàn bộ cấu trúc phân chia service bên trong hoàn toàn được che giấu. Khi cần refactor hay tái cơ cấu hệ thống, phía client không bị ảnh hưởng.

### 4.2. Đơn giản hoá code phía client (frontend)

Thay vì phải tracking hàng chục endpoint của nhiều service khác nhau, client chỉ cần biết một địa chỉ duy nhất là API Gateway. Điều này đặc biệt có giá trị khi hệ thống ngày càng mở rộng.

### 4.3. Dễ dàng theo dõi và quản lý lưu lượng

Vì toàn bộ traffic đều đi qua một điểm duy nhất, việc giám sát, phân tích và quản lý lưu lượng trở nên tập trung và dễ dàng hơn nhiều so với việc theo dõi từng service riêng lẻ.

### 4.4. Caching và cân bằng tải tập trung

API Gateway kiêm luôn vai trò load balancer và cache layer. Request không đến thẳng backend, giúp giảm thiểu rủi ro quá tải và cải thiện tốc độ phản hồi tổng thể.

### 4.5. Bổ sung một lớp bảo mật

API Gateway hoạt động như một "lá chắn" đầu tiên trước hệ thống, giúp phát hiện và ngăn chặn các loại tấn công phổ biến như DDoS, SQL Injection, và các request độc hại khác trước khi chúng chạm đến service backend.

### 4.6. Tập trung logic xác thực

Thay vì mỗi service phải tự xử lý xác thực người dùng, API Gateway có thể đảm nhận toàn bộ việc này (JWT, OAuth2, API Key...), giúp giảm trùng lặp code và đơn giản hoá từng service.

## 5. Nhược điểm của API Gateway

### 5.1. Tăng độ trễ (latency)

Mọi request đều phải đi qua một lớp trung gian bổ sung, điều này làm tăng nhẹ thời gian phản hồi so với việc gọi trực tiếp đến service. Trong các hệ thống yêu cầu độ trễ cực thấp, đây là điểm cần cân nhắc.

### 5.2. Thêm điểm có thể xảy ra lỗi (Single Point of Failure)

Nếu API Gateway gặp sự cố, toàn bộ hệ thống có thể ngừng hoạt động vì không có đường nào khác để request đến được backend. Vì vậy, API Gateway cần được triển khai với **high availability** (chạy nhiều instance, có cơ chế failover).

### 5.3. Nguy cơ nghẽn cổ chai (Bottleneck)

Nếu không được cấu hình và scale đúng cách, API Gateway có thể trở thành điểm thắt cổ chai làm chậm toàn bộ hệ thống, đặc biệt khi lưu lượng tăng đột biến.

### 5.4. Chi phí vận hành tăng thêm

Triển khai và duy trì API Gateway phát sinh thêm chi phí: server, giám sát, cấu hình và nhân lực quản trị. Với hệ thống lớn cần các tính năng nâng cao (analytics chuyên sâu, developer portal...), chi phí bản Enterprise của các sản phẩm thương mại như Kong, AWS API Gateway có thể khá đáng kể.

## 6. Khi nào nên và không nên dùng API Gateway?

| Nên dùng                                               | Không nhất thiết phải dùng                    |
| ------------------------------------------------------ | --------------------------------------------- |
| Hệ thống có nhiều microservices (từ 5 service trở lên) | Ứng dụng monolith đơn giản                    |
| Cần tập trung xác thực và phân quyền                   | Hệ thống nội bộ với ít client                 |
| Cần giám sát và logging tập trung                      | Prototype hoặc dự án nhỏ giai đoạn đầu        |
| Client đa dạng (web, mobile, bên thứ ba)               | Khi độ trễ cực thấp là yêu cầu tối quan trọng |

## 7. Các API Gateway phổ biến

| Sản phẩm                 | Loại                     | Đặc điểm nổi bật                               |
| ------------------------ | ------------------------ | ---------------------------------------------- |
| **Kong**                 | Open-source / Enterprise | Plugin-based, hiệu năng cao, hỗ trợ Kubernetes |
| **AWS API Gateway**      | Cloud (AWS)              | Tích hợp sâu với hệ sinh thái AWS              |
| **Azure API Management** | Cloud (Azure)            | Phù hợp hệ sinh thái Microsoft                 |
| **NGINX**                | Open-source              | Nhẹ, hiệu năng cao, cấu hình linh hoạt         |
| **Traefik**              | Open-source              | Tự động tích hợp với Docker/Kubernetes         |
| **Apigee**               | Enterprise (Google)      | Mạnh về analytics và quản lý vòng đời API      |
